AWS WAF / Shield / Network Firewall
应用层与网络层防护

先按保护对象分流：WAF 过滤 HTTP(S) 请求；Shield 缓解 DDoS；Network Firewall 对 VPC 网络流量做状态化/无状态检查。它们可组合，不能彼此替代。

一、AWS WAF：HTTP(S) 请求过滤

Web ACL 关联到受支持的资源，通过规则组/规则按优先级检查请求并执行 Allow、Block、Count、CAPTCHA 或 Challenge 等动作。可检查 IP、地理位置、URI、Header、查询参数、请求体及速率等特征。

构件用途设计注意
Web ACL规则集合及默认动作，关联保护资源规则按优先级求值；首个终止动作决定结果
Managed rule groupsAWS 托管或 Marketplace 规则组可先 Count 观察误报，再切换 Block；容量/费用受规则组影响
Rate-based rule按聚合键统计请求速率并限流适合应用层滥用/暴力请求缓解，不等同于网络带宽 DDoS 防护
Logging / metrics查看匹配、误报与请求趋势日志可能包含敏感请求字段，配置脱敏和访问控制

常见关联对象包括 CloudFront、ALB、API Gateway REST API、AppSync、Cognito 用户池、App Runner 等（以当前支持资源为准）。CloudFront scope 的 WAF 资源通过 us-east-1 区域配置；Regional scope 资源在对应区域。

二、AWS Shield：DDoS 防护

能力适用范围考点
Shield Standard自动提供常见基础设施层 DDoS 防护默认保护常见 AWS 边缘/网络服务，无额外 Shield Standard 订阅费用
Shield Advanced关键互联网暴露应用与资源增强检测/缓解、DDoS Response Team（按资格/流程）、成本保护与高级可见性；需订阅与配置
WAF 联动HTTP(S) 洪泛和应用层请求Shield Advanced 可与 WAF 规则/自动应用层缓解协同，具体支持需核对

Shield 解决可用性和 DDoS 威胁，不负责通用 Web 漏洞规则管理，也不能替代多 AZ、缓存、弹性扩展、容量规划和应用层速率控制。

三、AWS Network Firewall：VPC 网络流量检查

托管网络防火墙部署在 VPC 子网中的 firewall endpoint，使用 stateless rule group 与 stateful rule group（包括域名/协议等规则）控制流量。常见方案是通过路由表把进出或 VPC 间流量导向检查端点。

  • 每个 AZ 部署 endpoint 并规划对应路由，避免跨 AZ 绕行、单点与非对称路由。
  • Stateless 规则先匹配，可转发至 stateful 引擎或直接放行/丢弃；Stateful 规则跟踪连接上下文。
  • 集中出口可使用 inspection VPC + Transit Gateway，但需为双向路径、故障切换和路由传播设计。
  • Network Firewall 是 VPC 数据平面防护；安全组/NACL 是不同层级的控制，仍需组合。

四、服务选型与部署边界

需求优先服务典型组合/限制
阻止 SQL 注入、恶意 HTTP 请求、机器人滥用WAFCloudFront/ALB/API Gateway 等前置资源关联 Web ACL
抵御 DDoS，关键应用增强响应Shield Advanced配合架构弹性、CloudFront/Route 53/ALB 与 WAF
限制 VPC 出站域名或检查网络协议Network Firewall路由必须确保目标流量实际经过 endpoint
应用服务本身隔离端口Security Group / NACL状态与规则语义不同；不是 Web ACL 的替代品
先找流量层次与资源挂载点。WAF 不是任意 VPC 流量防火墙；Network Firewall 不解析并替代所有应用层规则；Shield 不会自动修复脆弱应用代码。

五、场景题解析（6 题）

1. 公开网站遭 SQL 注入与恶意 HTTP 请求。
方向：在 CloudFront 或 ALB 等受支持前端关联 WAF Web ACL，启用托管规则并先观察误报。
排除：Network Firewall 的 VPC 流量策略不是针对 HTTP 请求字段的首选。
2. 关键服务遭大规模 DDoS，要求增强支持和成本保护。
方向：评估 Shield Advanced，并按其要求保护资源、准备响应流程；同时强化弹性和缓存。
排除：仅配置 WAF 不能替代基础设施层 DDoS 服务。
3. 私有子网工作负载禁止访问恶意域名。
方向：使用 Network Firewall stateful/domain 规则并通过路由表把出站流量导向各 AZ firewall endpoint。
关键验证：DNS、路由对称性、endpoint 可用区和故障路径。
4. 新的 WAF 托管规则误拦业务请求。
方向：将规则设置为 Count 进行日志/指标观察，处理例外后再启用阻断。
排除：不要在未观察情况下直接全面 Block。
5. 只需阻止某 API 被单 IP 高频调用。
方向：评估 WAF rate-based rule，选择合适聚合键并配置阈值与动作。
易错点：阈值限流不能替代应用身份验证或 DDoS 防护。
6. TGW 汇聚多个 VPC 的互联网出口检查。
方向：可建立集中 inspection VPC，通过 TGW 和路由把流量导入 Network Firewall；为每 AZ 及回程设计对称路径和故障切换。

八、快速自测

1. 防止公开 API 的 HTTP 请求遭 SQL 注入，首选？
正确答案：A。WAF 按 Web 请求特征过滤。
2. 私有子网出站流量需按域名检查，关键配置是什么？
正确答案：B。没有路由导流，流量不会经过防火墙。
3. CloudFront 前的 WAF ACL 应按哪个 scope/区域创建？
正确答案：A。CloudFront 全局分发使用 CloudFront scope 并在 us-east-1 管理。
