Amazon GuardDuty / Detective
持续检测与安全调查

GuardDuty 持续分析威胁信号并生成 findings；Detective 利用安全相关数据建立行为图，帮助调查 finding 的上下文、关系和时间线。检测、调查、响应是不同步骤。

一、GuardDuty：托管威胁检测

GuardDuty 以区域为界启用检测器，分析 AWS 环境中的遥测与威胁情报，持续生成带有严重性、资源、类型和证据的 finding。它是检测服务，不是阻断流量/自动修复的防火墙。

能力作用设计点
基础检测识别异常 API 活动、可疑网络/DNS 行为、已知恶意来源等检查每个所需 Region 的 detector 状态
Finding描述可疑活动、受影响资源和严重性finding 是检测结果；后续需调查与响应
Organization 管理管理账号或委派管理员集中启用/配置成员检测覆盖新账号与多 Region，避免成员账号遗漏
EventBridge将 finding 事件路由给 Lambda、SNS、自动化工作流等按严重性/类型过滤并为自动化设计幂等与人工审批

二、数据源与保护计划

基础分析会使用服务整合的数据源，通常不要求用户自己建立每个日志管道。可选保护计划扩展特定资源类型检测能力；开启前核对覆盖、费用和 Region 支持。

检测面覆盖示例考点
账户与网络活动CloudTrail 管理事件、VPC Flow Logs、DNS logs 等信号GuardDuty 与用户自建日志存储/留存用途不同
S3 ProtectionS3 数据访问/管理相关威胁信号识别异常访问，不是对象权限或敏感数据分类工具
EKS ProtectionEKS 控制平面审计事件及可选运行时威胁检测检查集群类型、Agent/运行时组件与配置要求
RDS Protection受支持数据库的可疑登录活动不是数据库漏洞评估或合规配置扫描
Lambda / Malware Protection受支持的 Lambda 网络活动或 EBS 恶意软件扫描保护计划范围与收费需按当前服务文档核验
检测服务不等于全面日志归档。若题目需要长期原始审计记录/取证，仍需 CloudTrail、日志存储和相应保留策略。

三、Detective：关联证据与调查

Detective 汇集并分析安全相关数据，构建行为图以便探索实体、资源、活动及其时间关联。它帮助回答“finding 周围发生了什么、哪些实体相关”，不是 SIEM 替代品，也不自动隔离资源。

  • 启用 Detective graph，并将适当的 GuardDuty 管理账号/委派管理员设置为组织成员管理者。
  • 调查从 GuardDuty finding 或实体进入，查看活动摘要、时间线、关联 IP/角色/实例等。
  • 启用后存在数据保留/用量与服务费用；纳入组织级成本和区域规划。
  • 响应操作通过 EventBridge + Lambda、Systems Manager、工单/SOAR 等另行构建并设置审批边界。

四、多账号治理与响应链路

阶段组件动作
检测GuardDuty跨账户/Region 启用并持续生成 findings
汇总委派管理员 / Security Hub（如采用）集中查看安全发现；Security Hub 与 GuardDuty 职责不同
调查Detective沿实体关系和时间上下文追查
响应EventBridge + 自动化/人工流程隔离、撤销、禁用密钥等变更须有验证、最小权限和审计

规划时确保组织中新账号自动纳管、所有目标 Region 开启、管理账号和委派管理员清晰、finding 转发不丢失，以及自动响应不会误伤生产。

五、场景题解析（6 题）

1. 组织需集中检测所有成员账号的可疑活动。
方向：使用 Organizations 管理集成/委派管理员，统一启用 GuardDuty 并覆盖各账户、所需 Region 及新账号。
2. GuardDuty 报告可疑 EC2 外联，团队要追查此前活动和相关身份。
方向：在 Detective 中从 finding 调查关联实体与时间线；必要时结合 CloudTrail/网络日志进行取证。
3. 发现高严重性 finding 后希望自动通知值班团队。
方向：用 EventBridge 规则匹配 GuardDuty finding，并投递 SNS、工单或响应函数；过滤条件和重复事件处理需设计。
4. 需求是长期保存所有 API 调用用于审计。
方向：配置组织级多区域 CloudTrail 与受控日志归档；GuardDuty 是威胁检测器，不替代原始审计日志。
5. 需要对 S3 中个人信息做发现和分类。
方向：使用 Macie；GuardDuty S3 Protection 关注威胁活动，不是敏感数据分类。
6. 想自动隔离可疑实例。
方向：GuardDuty 负责发现；用 EventBridge 启动经审批/约束的自动化响应（例如调整安全组或隔离流程），并保留回滚与审计。

八、快速自测

1. 要识别可疑 API/网络活动并产生安全发现，使用？
正确答案：A。GuardDuty 持续分析信号并生成 finding。
2. 想基于 finding 自动通知或触发响应工作流，首选事件入口？
正确答案：B。EventBridge 可匹配 finding 事件并路由目标。
3. 团队需要追查 finding 涉及实体的上下文和时间关联，使用？
正确答案：A。Detective 提供图关系和调查上下文。
