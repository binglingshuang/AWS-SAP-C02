AWS Firewall Manager
跨账户安全策略集中管理

先判断题目是否在问“跨账户、统一、新账户也要自动生效”。Firewall Manager 是安全策略的管理面：把 WAF、Shield Advanced、安全组、Network Firewall、DNS Firewall 策略统一下发到 Organizations 作用域，并按需自动修复；它本身不解析业务流量。

一、定位与核心能力

Firewall Manager 用于在 AWS Organizations 中集中定义和管理安全策略：在一个管理员账户中创建策略，指定 OU/账户与资源类型，策略会自动应用到作用域内的现有资源和之后新建的资源。它是控制面服务，不是流量检查点。

能力说明考试含义
集中策略下发一次定义，跨账户/OU 统一应用防火墙与安全组规则替代逐账户创建 WAF Web ACL、逐账户修安全组
自动覆盖新账户/新资源进入作用域的新账户、新建的资源自动纳入策略“所有现有和未来资源都要保护”是强信号
审计与自动修复发现不合规资源；部分策略类型支持自动修复安全组策略可自动纠正被改动的规则
多策略类型WAF、Shield Advanced、安全组、Network Firewall、DNS Firewall 等按“管什么”选择策略类型，不要跨层错配
委托管理可添加其他 Firewall Manager 管理员，并按策略类型限制权限只有管理员账户能创建/修改策略
高频边界：Firewall Manager 不会自己清洗 DDoS、不会解析 HTTP 请求、不会转发 VPC 流量。真正执行防护的是 WAF、Shield、安全组、Network Firewall、DNS Firewall。

二、前提条件与管理账户

  • AWS Organizations 必须启用全部功能（all features）；仅启用合并账单（consolidated billing）不足以使用 Firewall Manager。
  • 在哪个账户启用 Firewall Manager，该账户就成为默认管理员账户（default administrator）；管理员账户负责创建、修改、删除策略。
  • Firewall Manager 使用服务关联角色 AWSServiceRoleForFirewallManager 在成员账户中执行操作；不要删除或修改该角色，否则策略无法下发。
  • 可添加其他 Firewall Manager 管理员，并通过 IAM 权限限定其只能管理某一类策略（例如仅 WAF 策略）。
  • Shield Advanced 策略要求作用域内账户本身已订阅 Shield Advanced；Firewall Manager 不会替账户购买订阅。
  • WAF 策略要求目标资源类型受 WAF 支持（CloudFront、ALB、API Gateway 等）；CloudFront 属于全局 scope，其 WAF 资源在 us-east-1 管理。
  • 计费：Firewall Manager 本身不额外收费，但底层资源照常计费（WAF 请求/规则、Shield Advanced 订阅、Network Firewall endpoint 等）。

三、策略类型对比

策略类型集中管理对象典型场景易错点
WAF policy跨账户创建 Web ACL，下发托管规则组、自定义规则与速率规则，并关联作用域内资源组织级 OWASP Top 10 基线；所有 CloudFront/ALB 统一防护受支持资源类型有限；全局 scope 与区域 scope 不能混用
WAF Classic policy旧版 WAF Classic 资源与规则历史遗留环境过渡新项目应使用 WAF，而不是 WAF Classic
Shield Advanced policy为作用域内资源应用 Shield Advanced 保护关键公网应用统一 DDoS 增强防护账户需已有订阅；不能替代弹性架构与缓存
Security group policy检查安全组规则是否符合基线，可自动修复禁止 0.0.0.0/0 开放 22/3389；纠正被手工改动的规则只控制安全组层，不是 WAF/IDS；规则表达能力有限
Security group usage audit policy发现未使用或仅被单个资源使用的安全组清理僵尸安全组、收敛攻击面偏“使用情况审计”，不等于规则合规修复
Network Firewall policy集中下发 Network Firewall 防火墙策略与规则组到作用域 VPC统一 VPC 出站/域间流量检查基线策略下发≠流量被检查，仍需 firewall endpoint 与路由导流
DNS Firewall policy集中管理 Route 53 Resolver DNS Firewall 规则组并关联作用域 VPC组织级恶意域名解析阻断只作用于使用 Resolver DNS Firewall 的 VPC 解析路径

四、作用域、下发与修复

  • 定义作用域：按 OU/账户选择范围，指定资源类型，并配置需要排除的账户或资源；部分策略支持用资源标签进一步限定，具体以当前控制台/文档为准。
  • 选择行为：安全组等策略可选择“仅审计”或“自动修复”；自动修复会覆盖人工改动，建议先在审计模式观察误报与例外。
  • 自动覆盖：新账户加入目标 OU、或新建资源进入作用域后，策略自动生效，不需要逐账户重复配置——这是与 CloudFormation StackSets 自建方案的效率差异。
  • 变更影响面：一次策略变更会影响作用域内全部账户，先小范围验证，再扩大 OU；保留例外清单与变更记录。
  • 可观测性：在 Firewall Manager 控制台查看策略与合规状态，并结合 Security Hub 汇总发现、EventBridge 触发告警或工单。
  • 数据面配套：WAF 策略只负责创建/关联 Web ACL；Network Firewall 策略仍需 endpoint、子网与路由；DNS Firewall 策略仍需 Resolver 关联。

六、场景题解析（6 题）

1. 组织内数百账户，所有现有和新建 CloudFront 分发都要 OWASP Top 10 基线防护。
方向：启用 Organizations 全部功能，使用 Firewall Manager 的 WAF 策略统一下发规则集到全部分发；Config 可用于记录与合规评估，但不是规则下发主体。
排除：Shield Advanced、Security Hub 不能替代 WAF 规则部署；逐账户手工创建不可持续。
2. 成员账户的安全组被改为对 0.0.0.0/0 开放 22 端口，需要持续纠正。
方向：使用 Firewall Manager 安全组策略（审计 + 自动修复）建立组织级护栏。
辨析：若题干还要求工程师保留排障能力，更优方案是移除 SSH 暴露并改用 Systems Manager Session Manager；Firewall Manager 解决“规则被改动”，不解决“如何安全排障”。
3. 需要集中管理 WAF 规则，账户/OU 名单会动态变化。
方向：Firewall Manager 策略按 OU 生效，新账户自动纳入；若必须按显式名单调整，可用 Parameter Store + EventBridge + Lambda 自动更新策略作用域。
排除：在管理账户逐账户 AssumeRole 自建下发、或用 Control Tower/KMS 存名单，运维复杂度更高且不是规则管理服务。
4. 约 500 个每周变化的 IP 对登录接口发起暴力尝试，打爆认证服务。
方向：在 ALB 前使用 WAF rate-based rule 按请求速率阻断；这是应用层限流，不是安全组规则能表达的动态速率限制。
排除：Firewall Manager 安全组策略擅长规则合规/修复，不适合按速率动态封锁。
5. WorkSpaces 只允许公司分支办公室公网 IP 登录，且未来会新增分支。
方向：在 WorkSpaces 目录使用 IP 访问控制组（IPACG），新增分支时把 IP 加入同一组。
排除：Firewall Manager 的 WAF 策略/IPSET 不保护 WorkSpaces 登录入口；自定义镜像防火墙与证书方案运维成本更高。
6. 组织要求所有 VPC 统一做出站域名过滤与网络层检查。
方向：用 Firewall Manager 的 Network Firewall 策略集中下发规则组，配合 inspection VPC/Transit Gateway；恶意域名解析可用 DNS Firewall 策略统一管理。
关键验证：firewall endpoint 覆盖每个 AZ、路由对称、故障切换，以及 Resolver 关联是否生效。

九、快速自测

1. 组织要求所有现有和新建 CloudFront 分发统一应用 WAF 基线，最合适的服务？
正确答案：A。Firewall Manager 集中下发 WAF 策略并自动覆盖新资源。
2. 使用 Firewall Manager 的必要前提是什么？
正确答案：B。仅合并账单不满足前提，且策略由管理员账户统一下发。
3. 成员账户安全组被违规改动，需要持续自动纠正，应使用？
正确答案：A。安全组策略可跨账户审计并自动修复；B 用于应用层限速，C 用于 DDoS 增强防护。
