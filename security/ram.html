AWS Resource Access Manager
跨账号与组织资源共享

AWS RAM 让资源所有者将受支持资源共享给账号、OU 或整个组织，而不必为每个消费者重复创建资源。消费者通过自己的账号使用共享资源；资源所有权与底层服务的授权边界仍然存在。

一、共享模型

资源拥有者创建 RAM resource share，选择一个或多个受支持资源、principal（账号/OU/组织）及可选的托管权限。若接收方不是同一组织成员，通常需要通过邀请接受共享；组织内共享可在启用 Organizations 集成后免逐项接受。

角色职责权限边界
资源拥有者创建资源共享、指定 principal 和 permission保留资源所有权与通常的生命周期/配置控制
消费者账号发现共享资源并在支持的服务中引用需要本账号身份策略授权相应服务 API
Organizations启用组织范围共享，按 OU/账号集中授权组织成员关系不自动授予资源 API 权限
RAM permission定义共享后消费者可执行的资源操作以服务支持的 RAM 权限为准，不等于资源所有者交出完全控制权
共享资源不等于复制资源：资源通常仍位于拥有者账号及 Region 中；消费者的实际操作仍需考虑 RAM permission、IAM policy、服务级权限及网络配置。

二、Organizations 集成与外部共享

  1. 在 Organizations 管理账号启用可信访问/组织集成（按服务控制台提示）。
  2. 拥有者创建 resource share，选择组织或 OU/账号 principal。
  3. 组织内账号按共享权限使用资源，不需要逐一发送邀请。
  4. 组织外账号通常接收邀请并接受后才能使用；检查邀请状态和共享区域。
  • 可用委派管理员管理 RAM 相关组织工作（适用能力依当前服务支持）。
  • 资源共享有区域性：资源和 share 的区域、消费者访问区域与服务限制必须一致；部分全局资源有特殊规则。
  • 组织成员离开组织后，其可用共享关系会按 RAM/服务行为变化；需安排退出清理和访问验证。

VPC 子网共享边界

  • 共享的是子网使用权，不是把 VPC 复制给成员账号。
  • 参与者可以在共享子网部署允许的资源，但 VPC owner 管理 VPC、子网、路由表、安全组及网络 ACL 等网络基础设施。
  • 参与者通常不能管理其他参与者的资源；需通过资源 ARN/账号边界与服务权限隔离。
  • 资源部署受可用区映射、子网容量、IP 地址、路由和服务配额影响；使用 AZ ID 处理跨账号可用区映射差异。

四、权限与治理边界

  • RAM share 不是 IAM 授权替代品：消费者 principal 需要服务 API 的身份权限，资源本身也必须支持共享访问。
  • RAM 不支持任意资源类型；遇到共享要求先查该资源的官方支持列表、可共享权限及限制。
  • 组织策略 SCP 可以阻止消费者或 owner 执行相应 API；SCP 不会因建立 share 而自动放宽。
  • 对敏感资源按账号/OU 最小化共享，定期审查 resource share、外部 principal 与邀请。
  • 共享不会自动创建跨 VPC 路由、DNS、TGW route 或安全组规则；网络连接另行设计。

五、场景题解析（6 题）

1. 多个账号需要在同一私有网络部署工作负载，网络团队统一管理 VPC。
方向：由网络账号通过 RAM 共享 VPC 子网；各应用账号在共享子网部署各自资源。
注意：明确 owner 与参与者的管理边界、IP 配额及 AZ ID。
2. 多账号需要接入中心 Transit Gateway。
方向：RAM 分享 TGW 给组织/账号；消费者创建 attachment，owner 接受并配置 TGW route table/关联传播。
3. 外部供应商账号未看到共享的资源。
方向：检查 RAM invitation 是否待接受、principal ARN 是否正确、资源是否支持跨账号共享、区域是否一致。
4. 同组织账号仍无法调用共享服务资源。
方向：检查 Organizations 集成是否启用、resource share principal 和 RAM permission、消费者 IAM policy、SCP 与服务自身访问控制。
5. 共享子网后，参与账号想修改路由表。
方向：路由表属于 VPC 网络基础设施，由 VPC owner 管理；参与者负责其账号拥有的工作负载资源。
6. 资源共享成功，但应用仍无法连接。
方向：RAM 只建立资源可见/可用关系；继续检查路由、DNS、SG/NACL、TGW attachment、目标服务授权与端口。

八、快速自测

1. 中央网络账号让多个成员账号部署在同一 VPC 子网，首选？
正确答案：A。RAM 支持跨账号共享 VPC 子网，owner 管理网络。
2. RAM 分享 TGW 后，流量仍不通，下一步重点检查？
正确答案：B。共享不代替消费者 attachment 和网络路由配置。
3. 组织内 RAM share 存在，但消费者 API 调用被拒绝，应否仅扩大 RAM permission？
正确答案：B。共享关系和调用权限是不同层次。
