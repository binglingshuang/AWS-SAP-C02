一、API Gateway 定位

API Gateway 是托管的 API 前门，可发布 REST、HTTP 与 WebSocket API，处理路由、身份验证、配额与流量治理，并集成 Lambda、HTTP 服务或 AWS 服务。API 通常部署到 Stage，客户端调用阶段 URL。

客户端
Web / 移动 / 服务
→
API Gateway
认证 / 路由 / 限流
→
集成后端
Lambda / HTTP / 私有服务

API Gateway 与 ALB 的定位不同：API Gateway 提供 API 管理与授权、Stage、使用计划等能力；ALB 是应用层负载均衡器，可将 HTTP 流量分配给目标组。可按 API 功能、网络拓扑、成本与目标架构组合使用。

二、REST / HTTP / WebSocket

类型能力与特点优先使用线索
REST API功能最完整，支持 API Key/Usage Plan、请求校验、缓存、资源策略、私有 API 等特性。需要细粒度 API 管理、私有 API、缓存或使用计划。
HTTP API轻量、低延迟/成本的 HTTP API；支持 JWT/Lambda Authorizer、CORS 和 VPC Link 等常用能力。面向现代 Web/API 的简单代理，使用场景不需要 REST 专属高级功能。
WebSocket API双向持久连接；通过 route selection expression 选择 $connect、$disconnect 和自定义路由。聊天、实时仪表板、游戏或需要服务端主动推送的连接。

REST 与 HTTP API 能承载常见请求-响应，但只有 WebSocket API 为持久双向通信提供连接管理。评估差异时核对当前功能矩阵，而不是认为 HTTP API 是 REST API 的逐项等价替代。

三、集成与 VPC Link

集成类型后端注意事项
Lambda proxyAPI Gateway 调用 Lambda 并将请求事件传给函数。函数资源策略允许 API 调用；函数需按代理集成响应格式返回。
HTTP proxy / HTTP backend把请求代理到公网 HTTP 服务或后端。配置路由、TLS、请求/响应转换和后端超时。
AWS service integrationAPI Gateway 直接调用受支持的 AWS 服务 API。执行角色需授予对应服务操作权限。
VPC Link通过受管私有网络连接访问 VPC 内部集成。REST API 与 HTTP API 可用的 VPC Link 目标类型/配置方式不同；按 API 类型和当前支持的负载均衡器或 Cloud Map 目标选择。

VPC Link 是 API Gateway 到私有后端的连接能力，不等同于“创建私有 API”。私有集成解决后端网络可达性；API Endpoint Type 与资源策略决定 API 调用入口是否私有。

拓扑核对：客户端需访问私有 API 时评估 Interface VPC Endpoint、Private DNS 和 API 资源策略；API Gateway 需访问私有服务时评估 VPC Link。两端方向不同。

四、身份验证与授权

机制认证对象 / 授权用途常见场景
IAM Authorization使用 SigV4 身份签名；由 IAM 策略授权。AWS 服务、受管理工作负载或可信 AWS 身份调用 API。
Cognito User Pool / JWT Authorizer验证用户令牌与 claims；HTTP API 常见 JWT Authorizer。用户登录后的 Bearer Token API 访问。
Lambda Authorizer调用自定义授权函数评估令牌/请求，可返回策略或授权上下文。自定义身份系统、复杂授权逻辑。
Resource Policy限制哪些账户、VPC Endpoint、IP 或主体可调用 API（依 API 类型支持情况而定）。限制私有 API 或跨账户 API 访问边界。
API Key / Usage Plan标识 API 使用者并提供使用计划与节流/配额管理。统计和限制合作方用量，不是用户认证机制。

认证确定调用者身份；授权决定该身份是否能调用资源。API Key 不应作为唯一身份验证或机密凭据。Cognito/JWT 用于用户令牌；IAM 适合 AWS 身份；Lambda Authorizer 用于自定义逻辑。

五、部署、节流与缓存

  • Stage：将 API 配置部署成环境阶段，可配置阶段变量、日志与流量设置；变更通常需重新部署才能对阶段生效。
  • Throttling：使用账户、阶段、方法或使用计划等适用层级的速率/突发限制保护后端；超限请求被节流，客户端应实现退避。
  • Usage Plan：REST API 场景可通过 API Key 关联计划，设置配额和节流；它适用于用量管理，不是严格身份或安全边界。
  • 缓存：REST API 可配置阶段缓存与 TTL，降低重复读取后端负载；需确认缓存键包含所有影响响应的参数，防止跨用户返回错误数据。
  • 请求校验与映射：可在 API 层验证参数、转换负载；仍需后端做业务规则和数据完整性验证。
  • 自定义域名：使用域名映射到 API Stage；关注证书、DNS、Base Path/映射和部署生命周期。
容量保护：API Gateway 节流是入口治理，不取代后端限流、队列缓冲或数据库连接控制。对突发异步任务可在 API 接受请求后写入 SQS，再由消费者按能力处理。

六、私有 API 与网络

REST API 可配置 Private Endpoint，通过 VPC Interface Endpoint 从 VPC 私有访问；资源策略可限制允许的 VPC Endpoint、VPC 或主体。Private API 的调用者仍需满足身份授权和网络连通性。

  • Private API 主要控制客户端到 API Gateway 的入口路径；VPC Link 主要控制 API Gateway 到私有后端的集成路径。
  • 私有访问需检查 Interface Endpoint、DNS、Endpoint Policy（适用时）、API Resource Policy、路由与安全组。
  • Regional Endpoint 面向特定区域客户端；Edge-optimized Endpoint 通过 CloudFront 边缘网络改善全球客户端访问（按 API 类型支持情况选择）。
  • API Gateway 本身不自动赋予 VPC 内后端公网访问，也不替代应用层身份授权。

七、安全与可观测性

  • 最小权限配置 API 调用者、Lambda 资源策略与集成执行角色，分别审查谁能调用 API、API 能调用谁。
  • 使用 TLS、自定义域名证书、WAF（适用 API 类型）和请求校验降低常见攻击面；不要把 API Key 当作用户认证。
  • 访问日志、执行日志和追踪需显式配置适用的 CloudWatch/IAM 权限；日志中避免记录明文敏感信息。
  • 监控请求数、延迟、5xx/4xx、节流与缓存命中，并关联后端 Lambda/ALB/服务指标。
  • 跨账户调用检查 API Resource Policy、调用者 IAM 策略、域名与区域配置。
响应排错：4xx 常见于客户端认证、授权、路由或校验；5xx 常见于集成/后端错误，但需结合 Gateway 和后端日志确认，不能仅凭状态码断定根因。

八、选型与常见陷阱

需求优先选择关键区别
HTTP JSON API，需低开销基本功能HTTP API核对 REST 专属功能是否必需。
私有 API、使用计划或阶段缓存REST API确认 API 类型支持的功能与 endpoint 配置。
服务端主动推送和持续双向连接WebSocket API连接生命周期和路由与请求-响应 API 不同。
调用方是 AWS 工作负载IAM Auth + SigV4按调用者角色授予最小权限。
后端位于 VPC 私网VPC Link 私有集成不要与 Private API 混为一谈。
合作方用量限制API Key + Usage Plan（REST）不是认证/授权边界。
  • Stage 部署后需确认调用的确是新部署版本。
  • 缓存响应必须正确区分用户、租户和查询参数，防止数据串读。
  • API Gateway→Lambda 调用权限与客户端→API 权限是两段不同授权。
  • VPC Link 并不把 API 入口变成私有；Private API 也不会自动连接私有后端。
  • 节流返回后客户端应退避，不能无间隔重试形成放大流量。

九、场景题解析

场景一：AWS 内部服务安全调用 API

多个受管理 AWS 工作负载调用内部 API，要求使用 AWS 身份进行强认证和最小权限授权。

正确方向：使用 IAM Authorization 与 SigV4，为调用角色授予限定 API ARN/方法/阶段的 execute-api 权限。
分析思路：IAM 身份适合 AWS 工作负载，调用者身份与授权策略可审计。
排除：API Key 适于用量区分，不是可靠的身份认证；允许匿名再在应用内判断会扩大风险。

场景二：HTTP API 需访问 VPC 内的服务

API 面向公网客户端，但后端只能在私有子网访问，不希望后端直接暴露公网。

正确方向：按 API 类型支持情况配置 VPC Link 私有集成至内部负载均衡器/服务，并保留合适的客户端授权。
分析思路：VPC Link 建立 API Gateway 到 VPC 后端的连接；公网 API 入口与私有后端可以并存。
排除：把 API 设为 Private Endpoint 会限制客户端入口，并非将后端设为私有；给后端分配公网 IP 不是必要方案。

场景三：API 仅允许企业 VPC 内调用

内部 REST API 不应从公网访问；客户端工作负载都在指定 VPC。

正确方向：使用 REST Private API，通过 Interface VPC Endpoint 访问，并以 API Resource Policy 限制允许的 VPC Endpoint/主体。
分析思路：私有入口、网络端点、资源策略和调用者身份授权共同构成边界。
排除：仅使用 VPC Link 只解决私有后端集成，不会使 API 入口私有；仅配置 IAM 不能阻止网络层公网可达。

场景四：合作伙伴 API 用量需要配额

多个合作伙伴共用 REST API，需区分使用者并提供每个合作方的请求配额。

正确方向：为 REST API 配置 API Key 和 Usage Plan，并将 Key 发给合作方；同时使用实际授权机制保护 API。
分析思路：Usage Plan 提供用量管理与节流，不承担用户认证或授权。
排除：只靠 API Key 保护敏感 API 不足；为每个合作方复制一套完整 API 也不是必要条件。

场景五：聊天应用需要双向实时通信

客户端建立连接后，服务端需在任意时刻向客户端推送更新。

正确方向：使用 API Gateway WebSocket API，设计连接/断开路由与业务路由，并保存连接 ID 供后端回推。
分析思路：持久双向连接适用于 WebSocket，而不是不断轮询 REST/HTTP API。
排除：HTTP API 请求-响应不提供相同的持续双向通道；SNS 邮件/HTTP 通知不是客户端会话 API。

场景六：重复 GET 请求造成后端读取负载过高

只读 REST API 响应可短暂复用，但不同客户数据必须严格隔离。

正确方向：评估 REST API 阶段缓存，设置短 TTL，并将影响响应的身份/查询参数纳入缓存键或禁用不安全缓存。
分析思路：缓存可减少后端调用，但缓存键不完整会把一个用户的响应返回给另一个用户。
排除：无差别启用缓存或只靠较短 TTL 仍可能造成敏感数据串读；提高后端超时不减少请求负载。

十二、快速自测

先独立选择，再点击“查看解析”。

1. API 面向用户登录后的 JWT 客户端，推荐什么授权方式？
正确答案：B。JWT Authorizer 验证令牌；API Key 用于用量计划而非认证。
2. API Gateway 要访问私有 VPC 后端，应优先配置什么？
正确答案：B。VPC Link 解决到 VPC 后端的私有连接。
3. 需要限制 API 只能从指定 VPC Endpoint 访问，重点配置什么？
正确答案：A。私有入口需要 VPC Endpoint 网络路径和策略边界；VPC Link 是 API 到后端方向。
