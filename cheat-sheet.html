使用说明

用法只有一个：读题时抓橙色限定词，答案就是绿色那一格。不要展开分析，先形成反射，再回头验证。

格式示例
题干限定词 / 场景关键词 → 直接选它

灰色一行：一句话记忆钩子 + 最容易混淆的排除项。

注意：速记只管"第一反应"。如果题干出现多条冲突限定词（如同时出现 Overlapping CIDR 和 Hub-and-Spoke），以更特殊的那个为准（Overlapping CIDR → PrivateLink）。

一、应用集成

SNS + SQS + Lambda
"Serverless First" / 事件接收处理架构 → SNS + SQS + Lambda 组合

SNS 接事件 → SQS 缓冲解耦 → Lambda 消费，无服务器三件套。

二、存储

EFS
"多 Pod 共享" + "跨可用区 Multi-AZ" + "NFS / 文件级共享" → EFS

抓限定词：multiple pods + multiple AZs + accessible across all instances = EFS。单实例块存储才是 EBS，Windows 共享才是 FSx。

S3 → EventBridge → SNS
"S3 对象被删除时发通知"（Object Deleted → 邮件/告警） → S3 → EventBridge → SNS（SNS 发邮件）

S3 无法原生直接向 SES 发事件通知，标准链路是 EventBridge 捕获 Object Deleted 事件 → 路由到 SNS → SNS 触发邮件。选项里出现 S3 直连 SES 的直接排除。

三、安全与合规

这三个服务是经典易混三兄弟：对外暴露 → Access Analyzer；合规规则 → Config；威胁行为 → GuardDuty。

IAM Access Analyzer
"外部访问 / 公有暴露"（Public Exposure / External Access） → IAM Access Analyzer

只要题目是检查 S3、KMS、IAM 角色等资源是否被外部或公众访问，首选 Access Analyzer。

AWS Config
"合规性评估"（Compliance / Configuration Rules） → AWS Config

用于周期性或配置变更时的合规检查，不是实时"状态突变事件"的精准流转（那是 EventBridge）。

Amazon GuardDuty
"威胁检测"（Threat Detection / Malicious Activity） → Amazon GuardDuty

检测异常行为、恶意 IP、凭证泄露等动态威胁，不是静态的权限配置分析（那是 Access Analyzer）。

CloudFront + WAF + 源站保护
"保护 Web 应用" + "防 DDoS / Web 攻击" + "隐藏源站" → CloudFront + WAF + ALB 仅放行 CloudFront

Edge Security Pattern 黄金三件套：CloudFront 挡在前（隐藏源站），WAF 过滤攻击，ALB 安全组 / Header 校验只放行来自 CloudFront 的流量。

AWS Firewall Manager
"hundreds of AWS accounts" + "centrally manage" + "automatically protect new resources" → AWS Firewall Manager（跨账户集中部署防火墙 / WAF 规则）

黄金搭档前置条件必背：AWS Organizations（All Features）+ 所有受管账户启用 AWS Config（用于发现资源）。题干出现 Firewall Manager，正确选项或依赖里一定带上这两个。

Database Activity Streams
Aurora / RDS + "监控所有数据库活动 / 审计"（monitor all data activity / audit） → Database Activity Streams（数据库活动流）
Database Activity Streams（紧跟其后的下游服务） → Amazon Kinesis Data Streams

Kinesis Data Streams 底层由 AWS 自动创建和管理，数据使用 KMS 加密；下游可再接 Firehose / 第三方审计与 SIEM 工具。

四、备份与恢复

AWS Backup
"集中管理备份" + "长期保留（1 年 / 数年）" + "合规审计" → AWS Backup

跨服务统一备份策略 + 保留周期 + 合规报告，三个词凑齐就是它；单个服务的快照生命周期不算。

五、网络

AWS PrivateLink
"Overlapping CIDR 重叠网段" + 跨 VPC / 跨账号通信 → AWS PrivateLink

网段重叠时 Peering 和 TGW 路由都走不通，用 PrivateLink 把服务暴露成接口端点，天然免疫 CIDR 冲突。

AWS Transit Gateway
"集中式 Hub-and-Spoke" + 多 VPC + 本地连接 → AWS Transit Gateway

星型拓扑简化多 VPC 与本地互联；但遇 Overlapping CIDR，TGW 要叠加 NAT / 防火墙做地址转换，开销大 → 改选 PrivateLink。

Security Group vs NACL
Security Group + "Deny 拒绝规则" → 必错（SG 只有 Allow）

安全组只支持 Allow 规则，无法写 Deny；需要显式拒绝（如封禁某 IP）要用 NACL（支持 Allow / Deny，无状态）。

六、边缘与迁移

AWS Snowball Edge Compute Optimized
"工厂 Factory" + "网络受限 Limited network" + "边缘计算 / AI 处理" → Snowball Edge Compute Optimized

在边缘做本地计算/AI，并兼顾本地轻量存储时的标准答案（可跑 EC2 / Lambda 函数）。只搬数据不算力选 Storage Optimized；需强算力且机房可用选 Outposts。
