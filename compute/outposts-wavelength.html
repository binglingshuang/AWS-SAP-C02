AWS Outposts / Local Zones / Wavelength
云的延伸与边缘部署选型

三种方案都把 AWS 能力延伸到更靠近用户或数据的位置，但部署地点、网络路径和主要目标不同。先识别约束是本地驻留、城市级低延迟，还是移动运营商 5G 边缘。

二、AWS Outposts

Outposts 将一组 AWS 设计并管理的基础设施部署到客户场所，在本地运行所支持的 AWS 服务，并与父 AWS Region 保持连接，形成一致的操作体验。

  • Outposts rack：面向较大规模部署的机架式基础设施；需评估机房、电力、空间、网络和交付规划。
  • Outposts servers：在有限场所/空间内提供 Outposts 能力；可用服务和容量不同，需对照产品规格。
  • 本地低延迟：应用可在场所内处理本地数据或访问低延迟本地系统；适合制造、金融或数据驻留类需求。
  • 服务链路：Outposts 需连接到父 Region 以进行服务管理和控制面通信；客户本地网关（LGW）可用于本地网络连接路径。
  • 离线限制：不能把 Outposts 当成与 Region 完全独立、任意长时间断网仍具完整控制面的云。需评估断连期间各服务的数据面行为、管理操作和恢复流程。
  • 容量与维护：提前规划订单容量、支持服务、可用区/子网、路由和本地运维责任；硬件由 AWS 管理不代表机房连接和应用运维由 AWS 承担。
考试辨析：本地部署同时需要 AWS 服务 API、一致控制体验、数据留在场所且本地延迟敏感，Outposts 往往比单纯选择 Region 更匹配；若只是靠近某个城市用户，评估 Local Zones。

三、AWS Local Zones

  • Local Zones 是父 Region 的扩展，位于特定都会区附近，为对时延敏感的应用提供更靠近终端用户的计算、存储等服务。
  • Local Zone 子网属于该 Local Zone；创建资源时必须选择该 Zone 可用的服务与实例类型。
  • 与父 Region 及其他 AWS 服务互通仍依赖 AWS 网络和相应路由设计；不是在客户机房中的 Outposts。
  • 适用于媒体渲染、游戏、实时交互、VFX 等需要靠近城市用户、但不要求运营商 5G 核心网络内部署的工作负载。
  • 部署前核对目标 Local Zone 的服务可用性、实例规格、容量、成本和数据路径；不能假定 Region 中所有服务在 Local Zone 都可用。

四、AWS Wavelength

  • Wavelength Zone 将 AWS 计算与存储能力嵌入 5G 运营商网络边缘，减少移动设备到应用的网络往返距离。
  • 适合 5G 设备、移动边缘计算、实时视频分析、交互式体验和需要靠近蜂窝网络用户的应用。
  • 与运营商网络、Wavelength Zone、父 Region 的连接共同构成端到端路径；评估流量出口、地址、路由、部署位置与服务支持。
  • 它不是“所有边缘用户的通用 CDN”：需要动态边缘计算时评估 Wavelength；静态内容全球分发和缓存通常评估 CloudFront。
  • 服务范围、可用运营商和区域依部署地点而异，需核对最新覆盖与能力。

关注点设计问题处理方向

数据驻留哪些数据必须本地存储，哪些遥测/管理数据会离开场所？定义数据分类、复制策略、加密、日志保留和合规证据。
区域能力目标位置是否支持所需实例、存储和服务？部署前查服务清单、容量、配额与网络依赖。

边缘部署仍需端到端冗余：应用在单个本地位置运行并不能自动获得跨位置灾备。明确 Region 失联、本地站点故障、运营商故障与依赖 AWS API 的行为。

七、场景题解析

场景一：工厂数据必须留在厂区

制造系统需要低延迟处理本地设备数据，并要求 AWS 服务在厂区运行。

方向：评估 Outposts，确认所需服务、本地容量、LGW/路由、父 Region 连接与断连运行边界。

排除：Local Zones 位于 AWS 托管的城市位置，不是客户工厂机房。

场景二：大型城市用户的交互应用

应用用户集中于某个都会区，需要比远端 Region 更低延迟，无客户机房部署要求。

方向：评估覆盖该区域的 Local Zone，并确认服务与实例规格可用。

排除：Outposts 会带来客户场所硬件部署和运营要求；不是题干必要条件。

场景三：5G 设备的实时视频分析

移动端经指定运营商 5G 网络传输视频，需要在网络边缘低延迟处理。

方向：评估可用的 Wavelength Zone，验证运营商覆盖、流量路由与服务支持。

排除：CloudFront 是内容分发/缓存网络，不能替代边缘应用计算。

场景四：Outposts 父 Region 链路中断

业务假定 Region 断连后所有 AWS 控制操作仍可无限期正常。

方向：按具体服务确认断连行为，设计冗余链路、监控和恢复流程，避免未经验证的离线假设。

排除：Outposts 不是与 Region 完全无关的独立 AWS 云。

场景五：全球用户下载静态图片慢

主要问题是跨区域静态内容分发，而非动态计算位置。

方向：优先评估 CloudFront 缓存和源站优化。

排除：为了静态内容缓存直接部署 Wavelength 或 Outposts 增加复杂度。

场景六：法规要求明确数据边界

业务必须证明哪些数据保留在本地、哪些控制面和日志会传送到 Region。

方向：逐项核对服务数据路径、加密、日志与管理元数据，并由合规设计和部署验证支撑；Outposts 仅是候选架构的一部分。

排除：“本地部署”并不自动等于所有数据、遥测和控制流量都留在现场。

十、快速自测

先独立选择，再点击“查看解析”。

1. 数据须留在客户机房，同时希望本地运行 AWS 服务，优先评估什么？
正确答案：A。Outposts 将 AWS 管理基础设施部署在客户场所；仍要规划父 Region 连接和服务可用性。
2. 5G 移动设备需要在运营商网络边缘进行低延迟计算，优先考虑什么？
正确答案：C。Wavelength 位于 5G 运营商网络边缘，适用于移动边缘低延迟用例。
3. 静态内容面向全球用户下载慢，题干没有边缘计算需求，优先评估什么？
正确答案：A。CloudFront 面向内容分发与缓存；只有需靠近用户执行计算时才进一步评估边缘计算方案。
