二、同步、异步与轮询

调用模式决定响应路径、谁负责重试，以及失败是否可以进入 Lambda 的异步目的地。

调用模式典型来源响应与重试责任常见用途
同步（RequestResponse）API Gateway、ALB、直接 SDK 调用调用方等待函数响应；函数错误返回给调用方，重试策略通常由调用方决定HTTP API、交互式查询
异步（Event）S3 通知、SNS、EventBridge、直接异步调用Lambda 接收事件后立即确认；服务管理重试，可配置最大重试次数、事件最大存留时间、DLQ 或目的地后台任务、事件处理
事件源映射（轮询）SQS、Kinesis、DynamoDB Streams、KafkaLambda 轮询来源并批量调用；处理成功后才推进/删除对应记录，失败处置取决于来源与映射配置消费队列与流
快速判断：看到“Lambda 从 SQS/Kinesis 拉取”，想到 Event Source Mapping；看到“API 立即返回结果”，想到同步；看到“S3 上传后后台处理”，通常是异步调用。异步调用的 DLQ/目的地不能直接套用到同步请求。

执行环境复用

  • 初始化代码可在执行环境创建时运行，之后的调用可能复用该环境；把 SDK 客户端等可复用对象放在 handler 外部有助于复用连接。
  • 执行环境可能被回收，后续调用也可能在另一个环境中运行；状态应放在 DynamoDB、S3、缓存或数据库等外部持久层。
  • 函数应能安全处理重复事件；不要把“恰好执行一次”作为默认前提。

三、触发器与事件源映射

核心差异是推送触发还是 Lambda 主动轮询，以及批次失败时记录如何推进。

来源接入方式需要特别配置 / 关注

S3 / SNS / EventBridge服务事件触发（通常异步）事件通知目标权限；异步重试、事件保留和失败目的地

Kinesis / DynamoDB StreamsLambda 轮询分片并批量处理分片并发、记录顺序、迭代器年龄、重试与跳过策略；有序流中的失败记录会影响后续处理进度
MSK / 自托管 KafkaLambda 事件源映射消费网络连通、认证、批次处理和消费滞后；Kafka 来源与 SQS 的确认语义不同

SQS 批处理与部分失败

默认批次中任一条消息导致函数报错时，批次会重试；已成功处理的记录也可能再次出现。启用 ReportBatchItemFailures 后，函数可返回失败消息标识，让事件源映射只重试失败记录，减少重复工作。

可见性超时陷阱：SQS 消息在可见性超时到期前未成功处理会重新可见，可能造成并发重复消费。将可见性超时设置得足以覆盖函数超时和重试过程，并让处理逻辑具备幂等性；不要只靠延长超时解决毒消息。

流处理控制

  • 事件源映射可设置批次大小、批次窗口（适用来源）、并行度等；权衡吞吐、延迟和单次失败影响范围。
  • 部分批次失败、拆分失败批次、最大记录年龄和重试次数等能力需结合事件源及配置确认。
  • 若允许丢弃超龄或持续失败记录，配置失败目标/目的地并监控相关指标，避免静默丢数。

四、并发与扩展

并发表示同一时刻处理的请求数。容量规划既要看 Lambda 并发，也要看下游数据库、API 或分区的承载能力。

机制作用适合场景 / 陷阱
Account concurrency账户与区域级并发额度，由账户中的函数共同使用突增调用可能被节流；规划预留容量并申请配额调整（如需要）
Reserved concurrency为某函数保留并限制最大并发，额度从账户池划出保护关键函数或限制对下游的压力；设为 0 可停止该函数处理
Provisioned concurrency预先初始化指定版本/别名的执行环境降低冷启动并稳定延迟；持续产生费用，配置对象不是未发布的 $LATEST
事件源映射并行度控制轮询来源的消费速度，例如 SQS 并发扩展配置、流分片并发限制消费速率以保护下游；并发上限也受函数并发和来源分区限制

估算与容量保护

粗略估算：所需并发 ≈ 每秒请求数 × 平均执行秒数。例如平均每秒 120 次调用、每次运行 0.5 秒，约需 60 个并发执行环境；实际还要考虑突发、尾延迟、重试和批次。

保护数据库对函数设置 Reserved Concurrency 上限，并用连接池/RDS Proxy 等控制数据库连接数。
降低启动延迟对有明确延迟目标的版本或别名配置 Provisioned Concurrency，并按流量做预置/自动扩缩。
快速吸收流量异步队列可缓冲突发；按消费者吞吐与积压调整消费能力，避免把尖峰直接压向下游。
区分节流原因检查账户配额、函数 Reserved Concurrency、Provisioned Concurrency 状态及事件源并发，而非只盲目增大超时。
考试陷阱：Reserved Concurrency 是“保留 + 上限”，不是预热实例；Provisioned Concurrency 是“预初始化环境”，不是函数可用的最大并发额度本身。两者可组合，但预置容量受到并发配置约束，超出预置容量的请求是否可用还取决于剩余并发空间。

五、重试、失败与幂等

调用类型失败处理重点推荐设计
同步调用方收到错误/超时；Lambda 不替同步调用方无限重试由调用方做有界重试与退避；非幂等操作用幂等键
异步Lambda 异步调用队列会重试函数错误，可配置重试次数及事件最大年龄；持续失败事件可能过期配置 On-failure Destination 或 DLQ、告警与重放流程；按业务需要设置重试与保留期
队列/流映射事件源映射重试记录/批次；来源类型决定检查点、删除或偏移提交行为配置最大重试、记录最大年龄、部分批次失败及失败目标；处理毒消息，监控积压/迭代器年龄

DLQ 与异步目的地

  • DLQ通常保存未成功处理的原始事件，便于排查或重放；Lambda 异步调用可使用 SQS 或 SNS 作为失败队列。
  • 异步调用目的地可按成功或失败发送调用记录，记录包含请求/响应等调用信息；支持将事件路由到多种目标。
  • SQS 事件源映射的失败消息通常由队列自身的 Redrive Policy 与 DLQ 处理，不要误认为 Lambda 的异步调用 DLQ 自动接管。

幂等处理要点

  1. 为业务操作生成稳定的幂等键（例如业务订单 ID 或来源事件 ID）。
  2. 用 DynamoDB 条件写入或其他原子机制记录“已处理”，避免并发重复执行造成重复扣款/创建。
  3. 把业务变更与幂等状态尽可能放在同一事务边界；对外部副作用使用可重试的状态机或补偿流程。
  4. 考虑重复事件、乱序、超时后调用方重试，以及函数已成功但确认丢失等情况。
设计原则：至少一次投递意味着消费者必须能够安全处理重复消息。对副作用操作，“重试”与“幂等”应一起设计。

六、冷启动与性能

冷启动发生在需要建立新的执行环境时，常见耗时来自运行时初始化、依赖加载、初始化代码和网络配置。

手段收益成本 / 限制
减小部署包、精简依赖、延迟加载非必需模块缩短初始化时间需要持续优化和测量；不要为微小体积牺牲必要功能
提高内存配置同时获得更多 CPU 资源，可能缩短执行时间成本随配置和执行时长变化；用压测找到成本/延迟平衡点
Provisioned Concurrency为指定版本/别名预初始化环境，适合可预测的低延迟流量即使空闲也会产生费用；需规划容量与自动扩缩
SnapStart（支持的运行时）发布版本时对初始化环境快照，调用时恢复以降低启动延迟需确认运行时及功能兼容；快照恢复后重建不应跨环境共享的唯一标识/连接
减少 VPC 初始化负担使用当前 Lambda VPC 网络架构并保持子网/安全组合理VPC 连接仍需正确的路由、DNS 与安全组，不等于自动拥有公网访问

执行时间与成本

  • 按真实请求测量 p50/p95/p99 延迟、错误率与并发；初始化耗时可通过日志中的初始化阶段数据观察。
  • Lambda 费用与请求数、执行时长、内存配置等相关；Provisioned Concurrency 和附加服务有独立计费项。
  • CPU 密集型任务可尝试提高内存以增加 CPU 配额；若任务持续时间或资源需求不适合函数模型，比较容器/实例方案。
冷启动答题顺序：先明确是否有严格首包延迟目标；可预测的生产流量优先评估 Provisioned Concurrency，兼容运行时可评估 SnapStart；同时优化包体与初始化。不要把加大超时当作冷启动优化。

七、VPC 网络与数据库连接

函数连接 VPC 资源时，Lambda 会为执行环境配置网络访问；网络能否到达目标，仍由子网路由、网络 ACL、安全组、DNS 和目标策略共同决定。

目标推荐网络路径常见错误
私有子网中的 RDS / ElastiCache函数关联可达目标的 VPC 子网与安全组；目标安全组允许来自函数安全组的流量只勾选 VPC 而未放行目标端口/来源安全组
从私有函数访问公网 API私有子网默认路由到 NAT Gateway，再出 Internet Gateway把函数放进 public subnet 就以为它会获得公网 IP
访问 AWS 服务 API使用适当的 VPC Endpoint（Gateway 或 Interface），或经 NAT 出网没有 NAT/Endpoint 时访问 S3、Secrets Manager 等服务超时
降低数据库连接压力复用连接，并评估 RDS Proxy、并发限制与连接池突发扩容导致每个执行环境新建连接，耗尽数据库连接数
典型陷阱：Lambda 连接 VPC 后，需要额外设计外网出口。Public subnet 本身不会给 Lambda 执行环境分配可直接上网的公有 IP。访问 S3 等服务可用 VPC Endpoint，或者经 NAT；按最小权限和成本选型。

网络诊断时按路径逐跳检查：函数子网路由 → NAT/Endpoint → 安全组与网络 ACL → DNS 解析 → 目标服务策略。对于跨 VPC/跨账号目标，再验证路由传播、对等连接/Transit Gateway 与资源授权。

需求主要控制核对点
函数访问 S3 / DynamoDB / Secrets ManagerExecution role IAM policy最小权限、资源 ARN、条件键；不要嵌入静态访问密钥

九、部署、版本与发布

能力用途重点
ZIP 部署包运行时代码及依赖打包上传依赖可直接打入包或作为 Layer；大小有配额
Container image需要自定义镜像或复杂依赖时部署镜像存放于 ECR，并遵守 Lambda 镜像格式及大小限制
Layer在多个函数间共享依赖或运行时扩展版本化但不等同于业务服务；避免层级和依赖冲突
Published version不可变的函数代码与配置快照生产发布使用版本可回滚；修改 $LATEST 不会改写已发布版本
Alias指向一个或多个版本的稳定入口可用于流量切换/加权部署；Provisioned Concurrency 可绑定版本或别名

灰度与回滚

  1. 部署新代码后发布新版本，保留已验证的旧版本。
  2. 将生产调用指向 Alias，并配置部署工具/流量权重逐步切换。
  3. 观察错误率、延迟、节流和业务指标；异常时将 Alias 回切到稳定版本。

可通过 CodeDeploy 与 Lambda Alias 实施 Canary / Linear 部署，并配置 CloudWatch Alarm 触发自动回滚。直接让调用方固定调用 $LATEST 会削弱版本化发布与回滚能力。

十、Lambda@Edge 与 CloudFront Functions

两者都在 CloudFront 边缘处理请求，但运行时、事件阶段、网络能力和执行耗时差异明显。

维度CloudFront FunctionsLambda@Edge
典型用途轻量、高吞吐的 viewer 请求/响应处理更复杂的边缘逻辑，例如访问源站前后处理
事件阶段Viewer request、Viewer responseViewer request/response、Origin request/response
运行能力轻量 JavaScript 执行环境，启动快；不访问网络或文件系统Lambda 运行时及更丰富的执行能力；不支持任意 VPC 资源访问
部署范围与 CloudFront Function 关联并在边缘执行函数需发布版本，并部署到 CloudFront 所要求的区域/分发配置
选型线索URL 重写/规范化、请求头处理、简单 token 检查复杂认证/授权、动态源站选择、基于请求生成响应等
服务边界：若逻辑很轻、只需查看者请求/响应阶段的快速转换，优先评估 CloudFront Functions；若需要更复杂的运行时能力或 Origin 阶段事件，评估 Lambda@Edge。需要访问 VPC 内数据库/私有 API 时，不应把 Lambda@Edge 当作普通 VPC Lambda。

Lambda@Edge 通常要求在 us-east-1 创建并发布函数版本，再关联到 CloudFront 分发；部署与配置传播需要时间。边缘函数也需考虑复制、日志位置、权限和配额。

十一、场景题解析

场景一：API 延迟偶尔出现初始化尖峰

电商 API 由 API Gateway 同步调用 Lambda，少数冷启动超过延迟目标。流量每天有规律的高峰，预算允许为高峰预留容量。应优先采用什么设计？

正确方向：为生产别名配置 Provisioned Concurrency，并按可预测流量预置/自动扩缩。

分析思路：问题是新环境初始化延迟，且高峰可预测；预置并发在请求到达前初始化执行环境。与此同时测量并精简初始化代码。

排除：只提高超时不会减少延迟；Reserved Concurrency 只保留并限制容量，并不预热；把函数改成异步会改变 API 响应语义。

场景二：Lambda 处理 SQS 消息时数据库连接耗尽

队列积压后事件源映射快速扩展，多个函数执行环境同时连接同一 RDS。如何在不丢失消息的前提下保护数据库？

正确方向：限制消费者并发（函数 Reserved Concurrency / 事件源映射并发配置），评估 RDS Proxy，并保持队列可见性与 DLQ 策略合理。

分析思路：队列能缓冲积压，重点是控制消费速率及连接复用，而不是允许无限并发直冲数据库。持续监控 ApproximateAgeOfOldestMessage。

排除：将消息可见性超时无限增大不会减少连接数；增加批次大小可能提升而非降低单次连接压力；关闭 DLQ 会让毒消息反复阻塞。

场景三：S3 文件上传触发后，失败事件需要可重放

上传事件由 S3 异步触发 Lambda。短暂错误应自动重试；超过重试后要留存事件供运营排查和重放。如何配置？

正确方向：使用异步调用配置重试/事件最大年龄，并设置失败目的地或 DLQ；为处理逻辑加入幂等键。

分析思路：S3 通知对 Lambda 属于异步调用，失败重试由 Lambda 异步调用机制管理。失败目标保留终态失败事件，重放前应处理重复副作用风险。

排除：只配置函数返回错误不会永久保存事件；API 调用方重试策略不适用于无人等待响应的异步通知；SQS Event Source Mapping 的队列 DLQ 与此场景并非同一配置层。

场景四：SQS 批次只有一条消息格式错误

函数收到 10 条消息，9 条已处理成功，1 条持续失败。希望成功消息不被每次整批重做，同时避免失败消息永久阻塞队列。

正确方向：启用部分批次失败响应，仅报告失败消息 ID；为队列设置合理的接收次数与 DLQ Redrive Policy。

分析思路：事件源映射默认按批次处理，失败可能导致整批重试。部分失败响应缩小重试范围，DLQ 为毒消息提供隔离通道。

排除：仅调高函数超时不能修复坏数据；删除整批消息会丢失失败消息；把 SQS 队列配置成 Lambda 异步调用 DLQ 是混淆了失败处理层。

场景五：私有 Lambda 可以访问 RDS，但无法读取 Secrets Manager

函数位于无公网出口的私有子网，VPC 中已有数据库。函数需要从 Secrets Manager 读取凭证，当前请求超时。

正确方向：为 Secrets Manager 配置可达路径，例如 Interface VPC Endpoint（含 Endpoint Policy / 安全组 / DNS）或 NAT 出口，并核对执行角色权限。

分析思路：VPC 内可访问 RDS 不代表可以访问 AWS 公共服务端点。网络路由和 IAM 授权必须同时满足。

排除：仅把 Lambda 关联到 public subnet 不会赋予公有 IP；仅增加 IAM 权限不能解决网络超时；把秘密硬编码进代码不安全。

场景六：只需在边缘规范化 URL 并改写请求头

CloudFront 分发需要将 URL 小写化、移除跟踪参数并设置一个请求头；逻辑轻量，不访问外部网络。

正确方向：使用 CloudFront Functions 处理 Viewer Request。

分析思路：这是简单、低延迟的查看者请求转换，CloudFront Functions 的能力和事件阶段与需求匹配。

排除：Lambda@Edge 能力更丰富但在此可能过重；若需求改为 Origin Request 阶段或复杂运行时逻辑，再评估 Lambda@Edge。

已掌握 0 / 18

  • Execution role：函数访问 AWS 资源的身份凭证
  • Resource policy：授权服务/账号调用函数；调用方策略也可能需要允许
  • 同步：调用方等待结果，重试通常由调用方负责
  • 异步：Lambda 管理重试，可配置事件年龄、失败目的地或 DLQ
  • Event Source Mapping：Lambda 轮询 SQS、流或 Kafka 等来源
  • SQS：Visibility Timeout、部分批次失败、Redrive Policy / DLQ
  • 流来源：分片并发、记录顺序、检查点与迭代器年龄
  • Account concurrency：账户与区域的共享并发容量
  • Reserved Concurrency：保留并限制函数并发，不会预热
  • Provisioned Concurrency：预初始化版本/别名环境，降低冷启动并产生费用
  • 至少一次投递：允许重复，副作用操作必须幂等
  • 异步目的地：可按成功/失败投递调用记录
  • VPC 公网访问：私有子网经 NAT；访问 AWS API 可用 VPC Endpoint
  • Public subnet：不会自动为 Lambda 执行环境分配公网 IP
  • 数据库连接：限制消费者并发，评估 RDS Proxy 与连接复用
  • 发布：不可变版本配合 Alias 做渐进流量切换与回滚
  • CloudFront Functions：轻量 Viewer 请求/响应逻辑
  • Lambda@Edge：更复杂边缘逻辑及 Origin 事件阶段

十四、快速自测

先独立选择，再点击“查看解析”。

1. 一个函数需要稳定的低延迟响应，且部署使用版本别名。要减少冷启动，最直接的配置是什么？
正确答案：B。Provisioned Concurrency 预初始化执行环境。Reserved Concurrency 控制容量，不负责预热；VPC 子网和重试次数不解决冷启动。
2. 一个 Lambda 轮询 SQS 队列，数据库连接数在积压高峰时耗尽。首要的容量保护方向是什么？
正确答案：C。并发上限控制同时运行的消费者数，RDS Proxy 可帮助管理数据库连接。消息保留时间和函数超时不会直接减少数据库并发连接。
3. S3 事件异步触发函数，最终处理失败的事件要保留并供重放。应在哪个调用层配置失败处置？
正确答案：C。S3 通知到 Lambda 是异步调用，配置异步重试/最大事件年龄与失败目的地或 DLQ。SQS 事件源映射适用于 Lambda 轮询队列，不是本场景。
