AWS App Runner
快速部署与运行 Web 应用

App Runner 将源代码或容器镜像构建、部署为可扩缩的 Web 服务。重点是理解它减少了哪些平台运维，以及网络连接、权限和运行时仍由谁负责。

一、服务模型

App Runner 是用于部署和运行 Web 应用/API 的托管服务。它接收源代码仓库或容器镜像，构建/拉取镜像并维护可访问的服务端点。

对象职责考试关注

Service提供托管部署、健康检查、TLS 端点与自动扩缩。它托管应用运行，不替代业务数据存储、IAM 设计或应用层高可用。
边界：App Runner 面向 Web 服务的快速托管，不是通用容器编排器。需要精细控制网络拓扑、Daemon、任务调度或集群资源时，比较 ECS/EKS。

二、源与部署

  • 源代码仓库方式可由 App Runner 按构建配置创建运行镜像；容器镜像方式由服务拉取指定镜像。
  • 私有 ECR 镜像拉取使用 ECR Access Role；它是部署时获取镜像的权限，不是应用运行时身份。
  • 自动部署适合每次源更新后自动推进；若生产变更需审批或固定发布窗口，可采用手动部署和受控版本流程。
  • 部署前验证应用监听端口、启动命令、健康检查路径、环境变量与 secrets 引用。
  • 使用不可变镜像标签/摘要与环境隔离，保留已知良好版本以便回滚。

从源码部署提升便利性，但应用仍需正确处理 SIGTERM、并发请求、无状态扩容和外部持久化。

三、实例与自动扩缩

App Runner 的 Auto Scaling Configuration 决定服务实例数量与扩缩行为。评估并发请求、响应时间、资源用量和扩缩上限；具体参数与配额以当前服务文档为准。

设计问题建议风险
突发流量为服务设定适配的并发目标与最大实例数，压测冷启动与扩容延迟。上限过低造成排队/拒绝；上限过高可能压垮数据库或增加费用。
会话状态把会话、上传文件和任务状态存放到外部托管存储。实例可横向扩缩或替换，实例本地状态不可靠。
下游保护设置合理扩缩上限、连接池、超时与重试退避。只按入口请求扩容可能把压力传递给数据库或第三方 API。

四、入口与 VPC 网络

  • App Runner 为服务提供 HTTPS Web 端点；域名、证书与客户端入口策略按服务能力配置。
  • 默认服务入口与 VPC Connector 是不同方向：VPC Connector 主要使应用实例访问 VPC 内的资源（出站私网连接）。
  • 启用 Connector 时选择私有子网和安全组，确认路由、DNS、目标安全组入站规则与可用 IP。
  • 访问公网依赖相应出站网络路径；VPC Connector 不会自动让私有子网具备 Internet/NAT 出口。
  • 若要求限制入站访问为私有网络，需核对当前 App Runner 的 VPC ingress 能力、区域支持和端点配置；不要把“能出站访问 VPC”误认为“服务入口已私有化”。
排查方式：先分别确认入口是否可达，再验证 Connector 子网路由、SG、DNS、连接目标端口和应用监听地址；出站和入站属于不同配置面。

五、身份与密钥

角色/机制使用时机注意
Access RoleApp Runner 从私有 ECR 拉取镜像。部署/镜像访问权限；不授予应用运行时代码 AWS API 权限。
Instance Role运行中的应用调用 AWS 服务。最小权限，仅授予应用真正需要的操作与资源。
Secrets / 参数将数据库密码、API token 等注入运行配置。使用 Secrets Manager / Parameter Store 与 KMS 权限；避免明文写入仓库或镜像。
安全组与 VPC控制 Connector 到目标资源的网络路径。网络可达不代表 IAM 授权；两者都必须满足。

六、可用性、观测与限制

  • 使用多个服务实例承载生产流量，并配置合理健康检查；无状态设计便于替换和扩缩。
  • 日志发送到 CloudWatch Logs，结合应用指标和告警监控 5xx、延迟、实例扩缩及部署状态。
  • 数据库连接、队列消费和外部 API 调用要设置并发保护、超时和重试策略。
  • 按需要使用 App Runner VPC Connector 访问 RDS/Redis 等 VPC 资源；数据库安全组仅允许 Connector 所需流量。
  • 涉及特殊容器运行权限、GPU、任意调度策略或节点级运维时，转而评估 ECS/EKS/EC2。

七、与 ECS、Beanstalk、Lambda 对比

服务主要抽象优先考虑
App Runner源/镜像到托管 Web 服务希望快速发布 Web API，减少基础设施和集群配置。
ECS / FargateTask Definition、Task、Service需要更精细容器部署、网络、容量、后台任务或服务编排。
Elastic Beanstalk应用版本与环境传统应用平台化部署，需要环境类型、部署策略和平台配置。
Lambda事件触发函数短时、事件驱动工作负载，不需常驻 Web 服务进程。

八、场景题解析

场景一：快速发布容器化 REST API

团队已有 HTTP 应用容器镜像，不需要自定义集群调度，希望减少运维。

方向：评估 App Runner，以 ECR 镜像创建服务并设置端口、健康检查、自动扩缩和部署策略。

排除：若需控制任务编排、后台 Worker 组合或自定义网络拓扑，App Runner 可能过于抽象，应比较 ECS。

场景二：服务连接私有 RDS 失败

App Runner 服务有公网 HTTPS 端点，但无法连接 VPC 中的数据库。

方向：配置 VPC Connector，核对私有子网路由、Connector 安全组、数据库 SG 入站、DNS 和端口。

排除：只修改公网服务 URL 或添加 Instance Role 权限不会建立私有网络路径。

场景三：私有 ECR 镜像部署失败

镜像存在于 ECR，但新服务无法拉取。

方向：检查 ECR Access Role 与仓库授权、镜像 URI/tag、区域和部署日志。

排除：Instance Role 是应用运行时身份，通常不是镜像拉取授权的替代品。

场景四：扩容后数据库连接耗尽

HTTP 流量增加时服务正常扩实例，但 RDS 连接数超限。

方向：设置合理最大实例/并发、应用连接池、超时与限流；评估数据库代理或缓存。

排除：无限提高最大实例数会放大下游过载。

场景五：生产部署必须人工批准

开发分支可自动部署，生产版本需经过审批并固定变更窗口。

方向：对生产服务使用受控/手动部署触发，结合不可变镜像版本、审批流水线和回滚流程。

排除：无条件自动跟随所有提交不满足变更治理要求。

场景六：应用文件在扩容后丢失

用户上传内容写入实例本地目录，扩容或替换后文件不可见。

方向：将对象上传到 S3 或选用适当共享持久存储；应用实例保持无状态。

排除：增加实例数、固定实例规格或重启服务无法保证本地数据持久。

十一、快速自测

先独立选择，再点击“查看解析”。

1. App Runner 应用需要访问 VPC 内的 RDS，优先配置什么？
正确答案：B。VPC Connector 建立服务到 VPC 的出站路径，SG、路由和数据库监听仍需正确。
2. 哪个角色用于让 App Runner 从私有 ECR 获取镜像？
正确答案：A。Access Role 用于部署时拉取私有镜像；运行时代码访问 AWS 服务才使用 Instance Role。
3. 扩容导致 RDS 连接数过高，首先应采取什么？
正确答案：B。扩容必须受下游容量约束；连接池与数据库代理可协助管理连接。
