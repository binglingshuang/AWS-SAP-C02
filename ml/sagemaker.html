一、机器学习生命周期地图

典型路径：准备数据 → 标注/特征工程 → 训练和评估 → 注册/审批 → 部署推理 → 监控和再训练。SageMaker 将多个托管能力组合起来，但数据质量、业务指标、访问控制和上线审批仍由团队负责。

阶段常见组件架构问题
开发与协作SageMaker Studio / 域与用户环境身份、用户隔离、共享资源、网络及开发成本。
标注与数据Ground Truth、Processing、S3、Feature Store标签质量、数据版本、特征一致性和数据权限。
训练与评估Training jobs、内置算法/自定义容器、自动模型调优计算类型、分布式策略、训练耗时、检查点与评估标准。
部署推理实时/无服务器/异步端点、Batch Transform在线延迟、请求体大小、流量峰值、成本和模型装载时间。
运营治理Pipelines、Model Registry、Model Monitor可复现、审批、回滚、数据/模型漂移和审计。
选型优先级：先判断“离线批量还是在线调用”，再判断在线请求的延迟/流量/负载特征；训练和推理是不同作业，可分别选资源和扩缩策略。

二、Studio 与协作环境

SageMaker Studio 是面向 ML 开发工作流的 Web 环境。团队可在其中探索数据、编写代码、运行训练和查看部署资源；实际资源、身份集成和工作区模式以当前 Studio 配置为准。

  • 规划域/用户配置时，明确执行角色、身份来源、VPC 接入、加密密钥和共享存储权限。
  • 不同用户的工作区不应共享过宽权限；用 IAM 角色和资源策略限制对 S3 数据、模型工件、ECR 镜像及端点的访问。
  • 开发环境可按需启停或使用合适的计算配置；长期空闲的交互资源也会产生费用。
  • Studio 是工作环境，不等同于生产模型托管服务；生产推理仍需选择端点或批处理运行方式，并单独设计发布和监控。
陷阱：允许分析师打开 Studio 不代表自动具备读取所有训练数据、解密密钥或部署生产端点的权限。

三、数据准备与标注：Processing、Ground Truth

Processing

Processing 作业使用托管计算执行预处理、后处理、特征工程或模型评估任务，常从 S3 读取输入并将输出写回 S3。它与训练作业职责不同，适合把可重复的数据转换纳入流水线。

Ground Truth

  • Ground Truth 协助构建标注工作流，可使用人工标注和支持的自动化/预标注方式；标注配置、任务类型和工作团队影响质量与成本。
  • 对高影响预测任务抽样审查标签，建立一致性规则、难例复核和质量反馈；“标注完成”并不等于标签准确。
  • 敏感数据要控制工作团队可见范围、标注界面暴露内容、输入数据位置和标注结果保存权限。

训练/验证/测试数据需避免泄漏，时间序列和用户事件要按业务时间切分；记录数据版本和处理逻辑才能复现训练结果。

四、SageMaker Feature Store

Feature Store 用于定义、存储、发现和复用机器学习特征。在线和离线存储可支持不同访问模式；具体一致性、写入可见性和查询能力需按当前配置与服务行为验证。

访问模式适合用途注意点
Online store在线推理时低延迟读取最新特征。检查特征组键、写入路径、容量和在线读取权限。
Offline store历史特征分析、训练数据集构建与回测。数据落在 S3 相关存储路径时仍需管理 bucket、加密和查询权限。
  • 训练和在线推理复用相同的特征定义，有助于降低训练/服务偏斜（training-serving skew）。
  • 设计事件时间、记录标识、特征版本和过期策略；避免训练样本误用未来信息。
  • Feature Store 管理的是特征，不会自动保证输入标签正确、模型有效或推理端点健康。

五、训练作业与超参数调优

能力用途架构师需判断
Built-in algorithms使用托管实现快速训练常见算法。算法是否满足精度、数据格式、特征和定制需求。
自定义容器 / 框架运行自有训练代码或支持的 ML 框架。镜像维护、依赖、漏洞修补、ECR 权限和可复现性。
Training job按需启动 CPU/GPU 训练计算，运行完成后释放作业实例。资源规格、分布式训练、输入通道、输出工件和中断恢复。
Managed Spot Training利用 Spot 计算降低可中断容忍型训练成本。训练是否可中断、检查点是否频繁持久化及总耗时容忍度。
Automatic Model Tuning并行搜索超参数空间，比较训练指标。目标指标、搜索空间、并发容量与试验总成本。
  • 训练实例只在作业运行期间提供计算，但输入/输出数据、模型工件和相关存储仍需治理。
  • 通过检查点将训练状态写到持久存储，以便 Spot 中断后恢复；不支持或未配置恢复的作业可能需要重跑。
  • 训练指标需与验证集、业务效果和公平性/安全目标一起评估，不能仅以训练集损失最小作为上线条件。
  • 大规模分布式训练需评估数据读取、网络通信、并行策略和实例族兼容，不应只扩大 GPU 规模。

六、推理部署模式：在线端点还是批量处理

模式适用负载权衡与边界
Real-time endpoint低延迟、持续或可预测的在线请求。需选择实例、配置自动扩缩、健康检查和生产发布策略；常驻容量有成本。
Serverless Inference流量间歇、请求量不大且可接受冷启动/服务限制的在线推理。核对当前支持的模型/资源、并发、负载大小和启动时间要求。
Asynchronous Inference大请求、处理时间较长或可异步返回结果。调用方需接受排队/结果通知和 S3 输出工作流，配置扩缩与队列处理。
Batch Transform离线批量预测，无需常驻在线端点。适合批作业，不为实时请求服务；需规划输入分片、结果位置与作业监控。
  • 实时端点支持生产流量时，应按压测结果配置实例、并发和扩缩阈值，监控延迟、错误率和饱和度。
  • 端点可结合多模型/多容器等部署能力，但模型加载、请求路由和隔离限制要先验证。
  • 部署新模型时可用端点变体或相应的发布控制能力逐步切流；回滚前要保留可用模型版本与配置。
  • 输入/输出包含敏感数据时，保护传输、日志和结果存储；避免在应用日志中记录完整特征或预测请求。
快判：请求必须同步低延迟 → 实时端点；有突发但可接受无服务器限制 → Serverless；慢/大请求可排队 → Async；整批离线打分 → Batch Transform。

七、Pipelines、模型注册与持续交付

  • SageMaker Pipelines 将 Processing、Training、评估、条件判断和注册等步骤编排成可重复的 ML 工作流，并可参数化数据路径、实例配置和指标阈值。
  • Model Registry 管理模型版本及其元数据/审批状态；把评估门槛和人工审批接入生产发布流程，避免训练任务完成就自动上线。
  • CI/CD 可触发流水线运行、测试模型工件、部署批准版本并保留变更记录；模型代码、数据、容器镜像和参数都应版本化。
  • Model Monitor 可用于监控生产数据质量、模型质量或偏差等适用场景；需准备基线、监控计划、告警阈值和后续调查责任人。
  • 漂移告警只是信号，不会自动证明模型失效，也不会自动完成再训练；应评估业务影响、确认标签/数据质量后再运行受控训练和部署。
陷阱：Pipelines 负责可重复编排，不会替团队定义正确的业务指标；Registry 的批准状态也不代表端点上线后无需监控。

八、安全、身份与网络

  • 为 Studio、Processing、Training 和部署分别使用边界清晰的执行角色；IAM 权限按所需 S3 前缀、ECR 镜像、KMS 密钥和 SageMaker API 最小化。
  • 在受限网络中运行时，规划 VPC 子网、安全组、DNS、S3/ECR/STS 等依赖的私有连通方式，以及拉取镜像和下载数据所需的出口路径。
  • 使用 KMS 管理训练输入/输出、模型工件、存储卷和日志的加密；密钥策略需允许对应服务角色执行所需操作。
  • 私有子网并不自动等于服务可用：检查接口/网关端点、路由、NACL、安全组、服务端点策略和 DNS。
  • 模型端点应仅暴露给授权调用方；结合 VPC 配置、IAM 授权、日志审计及输入验证，避免把公网可达误当作必要条件。
  • 管理训练数据和模型工件的生命周期、跨账号共享、审计日志及敏感数据访问；Model Monitor/CloudWatch 指标也需限定读取权限。
访问链：调用身份 → SageMaker API 权限 → 执行角色 → S3/ECR/KMS/网络资源权限。先定位链路中的拒绝层，不要用管理员权限掩盖配置缺失。

九、成本、可靠性与部署决策

需求优先评估常见风险
偶发批量预测Batch Transform / 临时处理作业误开常驻端点导致空闲费用。
低频在线流量Serverless Inference（符合约束时）冷启动、并发和请求上限不满足 SLO。
稳定高吞吐在线服务常驻端点配自动扩缩和容量压测低估峰值容量或过度配置常态容量。
可中断的长时间训练Spot Training + 检查点未验证恢复，导致反复从头训练。
反复人工训练部署Pipelines + Registry + 审批只编排任务却不治理数据/模型版本。

成本评估要覆盖开发计算、训练实例时长、调优并发、在线端点空闲/峰值、存储、数据传输和监控。选择 GPU 之前先确认模型和数据确实需要；通过批处理、缩放、缓存、Spot 或合适推理模式降低成本，但不能牺牲业务延迟和恢复目标。

十、场景题解析

场景一：每天夜间对数千万条记录打分，白天不要求在线预测

应用只需要定时拿到完整结果，不要求毫秒级响应。

方向：使用 Batch Transform 或受控的批量处理工作流，而非保持实时端点全天运行。
离线批量负载无需常驻在线容量，可降低空闲推理成本。
不要因“模型推理”就默认创建长期运行的实时端点。

场景二：交易请求间歇出现，允许短暂冷启动且不需要大请求体

希望降低低流量时的常驻实例成本。

方向：在模型、请求大小、并发和延迟约束兼容时评估 Serverless Inference。
按流量模式选推理模式，并通过端到端测试确认冷启动和服务配额满足 SLO。
Serverless 不意味着没有并发、模型或请求约束。

场景三：训练可中断，团队希望利用 Spot 降低长作业成本

训练任务可以恢复，但从头重跑代价很高。

方向：使用 Managed Spot Training 并配置可验证的检查点持久化/恢复流程。
Spot 节省取决于训练是否能容忍中断；检查点让任务从已保存状态继续。
只切换 Spot 而没有检查点，可能导致反复丢失训练进度。

场景四：多个产品团队重复实现同一套用户/商品特征

离线训练和实时推理特征有不一致风险。

方向：使用 Feature Store 建立共享、可发现的特征组，并按在线/离线读取模式设计。
复用特征定义可减少训练服务偏斜；需治理特征版本、事件时间和权限。
Feature Store 不能代替数据质量、标签与访问控制治理。

场景五：模型训练后必须通过评估和审批才能发布

要求可重现构建、人工把关并追踪模型版本。

方向：用 Pipelines 编排数据处理、训练与评估，将批准版本写入 Model Registry，再部署批准的工件。
流程编排、模型版本和审批共同构成受控发布；部署还应支持回滚与监控。
不能把训练成功直接视为模型达到生产门槛。

场景六：训练作业在私有子网中无法下载 S3 数据和 ECR 镜像

安全组已限制互联网出口，作业启动失败。

方向：逐层检查执行角色的 S3/ECR 权限、VPC 路由与端点、DNS、安全组、端点策略及 KMS 授权。
私有网络限制了路径；网络可达和 IAM/KMS 授权必须同时满足。
仅扩大训练角色 IAM 权限无法修复缺失的网络连通性。

十二、考前速记卡

已掌握 0 / 18

  • Studio 是 ML 开发环境，不是生产推理模式。
  • Ground Truth 辅助创建人工/自动化标注工作流。
  • Processing 用于预处理、后处理与评估作业。
  • Feature Store 复用特征并降低训练服务偏斜。
  • 在线特征适合低延迟读取，离线特征适合历史分析。
  • 训练作业与在线推理端点是不同资源。
  • Spot Training 应与检查点和恢复流程配套。
  • 自动调优会消耗并行试验计算资源。
  • 实时端点适合需要同步低延迟响应的工作负载。
  • Serverless 要验证冷启动、请求和并发约束。
  • Async 适合可异步返回的大请求/长处理任务。
  • Batch Transform 适合离线批量预测。
  • Pipelines 编排可重复的 ML 工作流。
  • Model Registry 跟踪模型版本与审批状态。
  • 训练成功不等于达到生产评估门槛。
  • Model Monitor 的告警仍需调查和决策。
  • 私有子网需同时满足 IAM、路由、端点和 DNS。
  • 保护数据、工件、镜像、密钥和端点的访问。

十三、快速自测

1. 无需实时响应、每天要对大批数据运行预测，优先选什么？

Batch Transform 或其他批处理工作流，避免维持空闲实时端点。

2. 如何降低可中断训练的 Spot 成本风险？

配置周期性检查点并验证从持久化检查点恢复训练。

3. 训练工作流要求评估通过且审批后才部署，哪些能力组合适合？

Pipelines 编排处理、训练和评估，Model Registry 管理版本/审批，再部署批准的工件。
