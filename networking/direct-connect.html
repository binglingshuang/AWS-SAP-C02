一、Direct Connect 基础

AWS Direct Connect（DX）提供从企业数据中心或办公室到 AWS 的专用物理网络连接，绕过公共互联网，提供稳定低延迟和一致带宽。

核心记忆：Direct Connect 是专用物理连接，不走公共互联网，但默认不加密。需要加密时，必须在 DX 之上叠加 VPN（MACsec 或 IPsec）。

两种连接类型

二、虚拟接口（VIF）类型

一条物理 Direct Connect 连接上，通过 VLAN 标签可以创建多个逻辑虚拟接口（VIF），每种 VIF 类型对应不同的访问目标。

三种 VIF 详解

🔵 Private VIF

连接到 VPC 的私有资源（EC2、RDS 等），通过 Virtual Private Gateway（VGW）或 Direct Connect Gateway 接入。

使用私有 IP 地址段，不能访问公有 AWS 服务（如 S3）。

🟠 Public VIF

访问 AWS 公有服务（S3、DynamoDB、Glacier 等），使用 AWS 公有 IP 地址范围。

流量不走公共互联网，但目标是公有服务端点，不是 VPC 私有资源。

🟢 Transit VIF

连接 Transit Gateway（TGW），支持通过单条 DX 连接访问多个 VPC。

必须配合 Direct Connect Gateway 使用，是大规模混合网络的推荐方案。

📌 Hosted VIF

由 DX 合作伙伴创建并共享给客户账户，客户需要接受共享请求后才能使用。

适用于托管连接（Hosted Connection）场景。

快速记忆：Private VIF → VPC 内部资源；Public VIF → AWS 公有服务（S3/DynamoDB）；Transit VIF → 多 VPC（通过 TGW）。考试看目标类型即可判断 VIF 类型。
易错陷阱：通过 Public VIF 访问 S3 时，流量不走公共互联网，但使用的是 S3 的公有 IP 端点，而非 VPC Endpoint。如果想通过私有 IP 访问 S3，需要使用 Private VIF + VPC Gateway Endpoint for S3。

三、Direct Connect Gateway

Direct Connect Gateway 是全球级别的逻辑组件，允许一条 DX 连接关联多个 VPC（跨 Region）或多个 Transit Gateway，解决"一线通多点"的问题。

On-Premises
→
DX Connection
物理专线
→
DX Gateway
全球资源
→
VGW / TGW
（多区域）

核心功能

  • 跨 Region 连接：一个 DX Gateway 可关联多个不同 Region 的 VGW 或 TGW，实现单条 DX 线路跨区域访问
  • 跨账号连接：DX Gateway 可跨 AWS 账号关联 VGW
  • 与 TGW 配合：使用 Transit VIF + DX Gateway + TGW 是连接多 VPC 的最佳实践

DX Gateway 使用模式

模式VIF 类型接入方式适用场景
单 VPC（同区域）Private VIF直连 VGW简单场景，无需 DX Gateway
多 VPC（跨区域）Private VIFDX Gateway → 多个 VGW需要访问多区域 VPC
多 VPC（大规模）Transit VIFDX Gateway → TGW数十上百 VPC 的混合网络
重要限制：
  • 通过 DX Gateway 连接的 VPC 之间，不能相互通信（DX Gateway 只做 On-Premises ↔ VPC 的中转，不做 VPC ↔ VPC 的路由）
  • 关联的 VPC CIDR 之间不能重叠
  • 每个 DX Gateway 最多关联 10 个 VGW（可申请提额）
  • DX Gateway 是全球资源，但每个 DX Gateway 只能属于一个 AWS 账户

四、LAG（链路聚合组）

LAG（Link Aggregation Group）将多条相同速率的物理 DX 连接捆绑为一条逻辑连接，提升带宽并增加冗余。

企业路由器
→ 多条物理线路 →
LAG（逻辑聚合）
LACP 协议
→
AWS 接入
  • LACP（802.3ad）：LAG 基于 LACP 协议实现链路聚合
  • 同速率要求：所有加入 LAG 的连接必须具有相同的带宽（如都是 10G）
  • 同位置要求：所有连接必须位于同一个 DX Location
  • 最大端口数：LAG 中最多 4 条活跃连接
  • 最少活跃数：可设置 LAG 的最小活跃连接数，低于该数量时 LAG 自动关闭
LAG vs 双 DX 连接：LAG 提升带宽聚合，但所有连接在同一 Location，仍有单位置故障风险。真正高可用需要双 Location + 双 DX（参见第五节冗余设计）。

最大弹性（Maximum Resiliency）：每个 DX Location 部署 2 条连接，共 2 个 Location、4 条连接，实现任意单点故障都不影响连通性。

DX + VPN 备份路由控制

当同时存在 DX 和 Site-to-Site VPN 时，通过 BGP 控制优先使用 DX：

  • AS-PATH Prepend（VPN 侧）：在 VPN 的 BGP 路由上增加 AS-PATH 长度，使 DX 路由更优先
  • MED（Metric）：对 VPN 路由设置更高 MED 值，降低优先级
  • LOCAL_PREF（AWS 侧）：在 AWS VGW 上为 DX 路由设置更高 LOCAL_PREF
考试关键词：需要"最高可用性"→ 双 DX 双位置；需要"成本低且有备份"→ DX 主用 + VPN 备用；"快速建立连接"→ VPN（DX 建立周期长）。

六、加密方案

Direct Connect 物理链路默认不提供数据加密。若需要传输加密，必须在 DX 之上叠加加密层。

考试必记：Direct Connect 默认不加密。题目若同时要求"低延迟专线"和"数据加密"，答案通常是 VPN over Direct Connect（在 DX 之上运行 IPsec VPN）。

两种加密方案对比

方案MACsec（802.1AE）VPN over Direct Connect（IPsec）
加密层级Layer 2（链路层）Layer 3（网络层）
加密位置在 DX Location 内，逐跳加密端到端加密（客户设备 → VGW/TGW）
适用连接类型仅专用连接（Dedicated，1G/10G/100G）专用连接 + 托管连接均可
性能影响极小（硬件加速）有一定 CPU 开销，带宽上限约 1.25 Gbps/隧道
配置复杂度较高（需要支持 MACsec 的设备）相对简单（标准 IPsec 配置）
跨 Region不支持跨 Region（链路层限制）支持（IP 路由不受限制）
典型场景金融、政务等高合规要求，需要硬件级加密通用加密需求，与 DX 冗余配合

七、BGP 路由控制

Direct Connect 强制使用 BGP 协议（Border Gateway Protocol）进行路由交换，理解 BGP 属性对于控制流量优先级至关重要。

BGP 核心属性（考试相关）

BGP 属性说明控制方向值越大/越长？
AS-PATH路由经过的 AS（自治系统）路径列表影响入站路由选择（对端如何选择路径）越短越优先
AS-PATH Prepend人为增加 AS 号让路径看起来更长降低该路径优先级（用于备份路由）添加后变长，优先级降低
MED
（Multi-Exit Discriminator）		向对端 AS 建议进入本 AS 的首选入口影响对端 AS 如何选择进入路径越小越优先
LOCAL_PREFAS 内部的路由优先级影响 AS 内部路由器如何选择出口路径越大越优先
BGP Communities路由标记，用于策略控制AWS DX 支持特定 Community 值控制路由传播范围—

DX 优先于 VPN 的路由配置

  • 方法1（VPN 侧降权）：在 VPN 的 BGP 路由上使用 AS-PATH Prepend，增加跳数 → AWS 优先选择 DX 路由
  • 方法2（DX 侧提权）：配置 DX 路由的 LOCAL_PREF 值高于 VPN → AWS 内部路由器优先选 DX 出口
  • 方法3（MED）：对 VPN 路由设置较高 MED 值 → 对端 AS 优先从 DX 入口进入
ECMP（等价多路径）：Transit Gateway 支持跨多条 DX 或 VPN 连接做 ECMP，实现水平扩展带宽。VGW 不支持 ECMP（仅支持主备切换）。

八、场景题解析

先独立思考，再查看解析。

场景1：某公司需要将大型数据集从本地传输到 S3，要求低延迟、高带宽，数据不经过公共互联网，但不需要额外加密（数据本身已加密）。最合适的方案是？
正确答案：B。访问 S3 等公有 AWS 服务，需要 Public VIF（使用 AWS 公有 IP 端点）。数据已自行加密，无需叠加 VPN。Private VIF 连接的是 VPC 私有资源，不能直接访问 S3 公有端点。
场景2：某金融机构要求所有从本地到 AWS 的数据传输必须满足：低延迟、高带宽、数据传输加密（合规要求）。应该选择哪种方案？
正确答案：C。VPN over Direct Connect 结合了 DX 的低延迟专线优势和 IPsec VPN 的端到端加密。DX 单独使用不加密；仅 VPN 延迟高且带宽受限；PrivateLink 是 VPC 内服务访问方案，不适用于混合网络传输加密。
场景3：某企业目前使用单条 DX 连接到 AWS，想提升连接可用性，在 DX 完全中断时仍能访问 AWS 资源，且希望成本合理（不需要最高级别冗余）。最优方案是？
正确答案：C。DX+VPN 备份是最具成本效益的冗余方案，VPN 在 DX 中断时自动接管（通过 BGP 路由优先级控制）。同位置双 DX 无法抗 DX Location 故障；LAG 同样在同一 Location；双 DX 双 Location 成本最高，超出"成本合理"要求。
场景4：某企业在 us-east-1 和 ap-southeast-1 都有 VPC，需要通过一条本地 DX 线路同时访问两个 Region 的 VPC 资源，应该如何设计？
正确答案：C。Direct Connect Gateway 是全球级资源，可将一条 DX 连接关联到多个 Region 的 VGW，实现跨 Region 连接，无需建立多条物理 DX 线路。选项B中一条 DX 连接只能创建有限数量 VIF，而 DX Gateway 提供更简洁的管理方式。
