一、AWS VPN 总览

AWS 的 VPN 不是单一服务，而是三种形态：Site-to-Site VPN（站点到站点、IPsec）、Client VPN（终端用户远程接入、OpenVPN/TLS），以及作为加密叠加层的 VPN over Direct Connect。考试必须先判断"连接的两端是谁"，再选形态。

对比项Site-to-Site VPNClient VPN
连接对象本地数据中心 / 分支机构 ↔ VPC单个终端用户设备 ↔ VPC
协议IPsec（IKEv1 / IKEv2）OpenVPN（基于 TLS/SSL）
AWS 侧端点Virtual Private Gateway（VGW）或 Transit Gateway（TGW）Client VPN Endpoint（关联 Target Subnet）
客户侧Customer Gateway（物理或软件 VPN 设备）用户安装 AWS VPN Client 或任意 OpenVPN 客户端
认证方式预共享密钥（PSK）+ 可选证书Active Directory、SAML 联合身份、双向证书
路由方式静态路由或 BGP 动态路由按 Target Subnet 路由 + 授权规则
典型场景混合云、分支互联、DX 备份链路远程办公、运维接入、临时项目访问
一句话区分：连"站点/路由器"→ Site-to-Site VPN；连"人/笔记本"→ Client VPN。两者不能互相替代，也不存在"一个 VPN 连接同时服务站点和终端用户"的设计。

三种加密叠加/增强形态

VPN over Direct Connect

在 DX 专线上跑 IPsec，兼顾专线的稳定低延迟与端到端加密。DX 本身默认不加密。

VPN CloudHub

多个分支通过各自的 Site-to-Site VPN 连接汇聚到同一个 VGW，形成星型 hub-and-spoke 互联。

加速 Site-to-Site VPN

用 Global Accelerator 承载 VPN 流量，改善跨国长距离、公网抖动场景。仅支持 TGW，不支持 VGW。

与 DX 主备

DX 主用 + Site-to-Site VPN 备用，是成本与可用性平衡最常见的混合网络冗余答案。

速度对比：Site-to-Site VPN 可在分钟级建立（配置 + 隧道协商），Direct Connect 通常需要数周。题目只要出现"尽快/短期打通"，优先考虑 VPN。

四个核心组件

组件归属作用考试要点
Customer Gateway（CGW）客户侧逻辑资源描述本地 VPN 设备的公网 IP 与 BGP ASNCGW 本身不是设备，是 AWS 侧的一条配置记录；设备更换后需重建/更新
Virtual Private Gateway（VGW）AWS 侧附加到单个 VPC，作为 VPN 终点一个 VPC 只能附加一个 VGW；VGW 不支持 ECMP
Transit Gateway（TGW）AWS 侧作为 VPN Attachment 的终点，连接多个 VPC支持多连接 ECMP，可横向扩展 VPN 带宽
VPN ConnectionAWS 侧一条 IPsec 连接，含两条隧道只能附加到 VGW 或 TGW，二者不可同时

建立顺序

  1. 创建 Customer Gateway：填写本地设备公网 IP；若用 BGP，填写客户侧 ASN（如 65000）。
  2. 创建 VPN Connection：选择附加到 VGW 或 TGW，选择静态路由或 BGP。
  3. 下载配置模板：AWS 会输出两条隧道的端点、预共享密钥、IKE/PSK 参数。
  4. 在本地设备上配置两条隧道，并放行 UDP 500（IKE）与 UDP 4500（NAT-T）。
  5. 启用路由传播（VGW）或在 TGW 路由表中添加/传播路由，确认实例安全组与 NACL 放行。
最常见失败原因：只配置了一条隧道、PSK 或 IKE 版本不一致、本地防火墙未放行 UDP 500/4500、路由未传播到 VPC 路由表、CGW 位于 NAT 设备之后未启用 NAT-T。

隧道选项（Tunnel Options）

  • Inside IPv4 CIDR：每条隧道使用一个 /30 网段（默认由 AWS 分配，也可自定义），两端各占一个地址。
  • Pre-Shared Key：每条隧道独立 PSK，可自定义；泄漏后需重建连接。
  • IKE 版本：推荐 IKEv2；老设备可能只支持 IKEv1。两端版本必须一致。
  • DPD（Dead Peer Detection）：用于检测对端存活并触发重建，影响故障切换速度。

三、隧道、带宽与高可用设计

SAP-C02 的 VPN 题目几乎都在考两件事：带宽够不够、单点故障在哪里。记住隧道数量与上限，比记配置步骤更有用。

两条隧道是默认设计，不是冗余选项

  • 每个 VPN Connection 自带 2 条隧道，AWS 侧端点位于不同可用区，用于抵御单 AZ 故障。
  • 两条隧道可同时配置在同一个 CGW 上；更稳的做法是两个 CGW（两台设备）分别承载一条隧道，避免设备级单点。
  • 隧道状态可在 CloudWatch 查看 TunnelState，建议对两条隧道都设置告警，而不是只监控一条。
指标典型值 / 限制说明
单隧道最大吞吐约 1.25 Gbps实际值受加密算法、设备 CPU、丢包与 MTU 影响
单连接理论吞吐约 2.5 Gbps（双隧道）单条 TCP 流通常仍受单隧道限制
VGW 聚合能力不支持 ECMP多条 VPN 连接只能主备，无法叠加带宽
TGW 聚合能力支持 ECMP多条 VPN Connection 可并行分担流量并提升故障切换速度
隧道 MTU约 1400 字节IPsec 封装开销导致，需调整 MSS 或放行 ICMP 分片
支持协议IPv4 / IPv6双栈场景需确认本地设备与隧道 CIDR 配置
带宽陷阱：题目要求"通过互联网连接、需要 3 Gbps 以上、且可叠加"时，单条 VPN 连接（双隧道）达不到。正确答案通常是 TGW + 多条 Site-to-Site VPN 连接 + ECMP，或改用 Direct Connect，而不是"增加一条隧道"。

高可用方案对比

方案拓扑可抵御的故障成本
单隧道1 CGW → 1 隧道无（隧道/AZ/设备均为单点）最低
双隧道单 CGW1 CGW → 2 隧道单隧道、单 AZ 故障低
双隧道双 CGW2 CGW → 各 1 隧道隧道、AZ、单台设备故障中
多连接 + TGW ECMP多个 VPN Connection → TGW上述全部 + 带宽叠加中高
DX 主 + VPN 备DX（主）+ VPN（备）DX 线路/设备中断中
答题顺序：先问"是否要求带宽聚合"→ 是则必须 TGW + ECMP；再问"是否要求对抗站点级故障"→ 是则双 CGW；最后才考虑加速或 DX。

四、路由、BGP 与故障切换

VPN 隧道建立成功不代表业务可达。路由是否被传播、BGP 是否宣告、安全组/NACL 是否放行，是三层独立的问题。

静态路由 vs BGP 动态路由

对比项静态路由BGP 动态路由
配置方式在 VPN Connection 中手工指定本地网段由本地设备与 AWS 端点交换路由
故障切换隧道断开后依赖路由失效，切换较慢BGP 快速撤销路由，切换更快
适用场景设备不支持 BGP、网段固定且简单多分支、多网段、需要自动收敛（推荐）
考试判断"设备不支持动态路由""需要自动故障切换/多路径"

路由传播的三条链路

  • VGW 场景：VPN 路由需在 VPC 路由表中启用 Route Propagation，静态路由则需手工添加目标为 VGW 的路由。
  • TGW 场景：VPN Attachment 的路由进入 TGW 路由表，再由 TGW 关联/传播到各 VPC 的附件路由表。
  • 本地侧：本地设备必须把 AWS VPC CIDR 加入路由表/隧道感兴趣流量（Interesting Traffic），否则不会发起协商。
易错点：VGW 无法把路由"推"给本地设备，BGP 是双向的；如果本地只配了单向静态路由，常见现象是"隧道 Up 但业务不通"。

故障切换与路由优先级

  • DX 主 + VPN 备：对 VPN 路由使用 AS-PATH Prepend 或更高 MED，让流量优先走 DX；DX 中断时 VPN 自动接管。
  • 多 VPN 连接 + TGW：利用 ECMP 并行分担；BGP 撤销失效路径后自动收敛。
  • VGW：不支持 ECMP，多连接只能主备，切换依赖 BGP/路由失效检测。

DNS 解析：Route 53 Resolver

混合网络中的常见需求是"本地能解析 AWS 私有域名，AWS 也能解析本地域名"。做法是部署 Route 53 Resolver Inbound / Outbound Endpoint，并通过 VPN/DX 打通 53 端口：

  • Inbound Endpoint：本地 DNS 服务器把 aws.example.com 的查询转发到 Resolver Inbound IP（位于 VPC 子网内）。
  • Outbound Endpoint + Resolver Rule：AWS 侧把 corp.example.com 的查询转发到本地 DNS。
  • 安全组/NACL 必须允许 UDP/TCP 53；本地防火墙需允许访问 Endpoint 的私有 IP。
与 VPN 的关系：Resolver Endpoint 是 VPC 内的私有 IP，天然需要 VPN/DX 才能从本地访问；题目出现"本地服务器无法解析 AWS 私有域名"时，优先检查 Resolver Endpoint 与安全组，而不是重建 VPN。

五、AWS Client VPN

Client VPN 是按用户的托管 VPN：员工在笔记本上安装客户端，通过 TLS 接入 VPC，无需在办公室部署硬件 VPN。

核心组件

组件说明考试要点
Client VPN EndpointVPN 的逻辑入口，需绑定 ACM 服务器证书一个 Endpoint 关联一个 VPC 的多个 Target Subnet（可跨 AZ）
Target SubnetEndpoint 关联的子网，用于承载客户端流量建议每个 AZ 关联一个子网，实现高可用
Client CIDR分配给 VPN 客户端的地址池不能与 VPC CIDR 或本地网段重叠
Authorization Rules按用户组限制可访问的目标网段默认拒绝；必须显式授权，否则客户端接入也访问不到资源
Split Tunneling只让指定流量走 VPN，其余走本地公网开启后需在客户端路由/授权规则中精确配置

三种认证方式

Active Directory

对接 AWS Directory Service 或自建 AD，按用户/组授权。适合已有域环境的企业。

SAML 联合身份

对接 Okta、Azure AD 等 IdP，用户在浏览器完成 SSO 后获得 VPN 会话。适合多云/ SaaS 身份体系。

双向证书认证

客户端证书 + 服务器证书互验，适合设备级接入或自动化场景，不需要目录服务。

组合方式

可同时启用"证书 + 用户认证"，实现设备与用户双重校验（合规场景常见）。

Split Tunnel：全流量 vs 分流

模式流量走向优点缺点 / 适用
Full Tunnel（关闭 split tunnel）客户端所有流量经 VPN 到 VPC统一出口、便于审计与内容过滤占用 VPN 带宽与 AWS 出口费用；需 NAT/互联网出口
Split Tunnel（开启）只有目标网段走 VPN，其余走本地网络节省带宽、降低延迟、成本低安全策略需在终端侧配合；适合只访问内网资源
Client VPN 不是站点 VPN：它只服务终端用户，不能让两个分支机构互联，也不能替代 Site-to-Site VPN。题目要求"分支路由器互联"时，选 Site-to-Site VPN 或 DX。
授权规则顺序：Client VPN 的 Authorization Rule 默认全部拒绝。只关联 Target Subnet 而不加授权规则，是最常见的"能连上但打不开资源"原因。

六、VPN over Direct Connect

Direct Connect 提供稳定低延迟的专用链路，但默认不加密。当合规要求"传输加密"、同时又不能放弃专线质量时，在 DX 之上叠加 IPsec，即 VPN over Direct Connect。

两种接入方式

方式DX 虚拟接口AWS 侧终点说明
Public VIF + VGWPublic VIFVGW 的公网 IP最常见形态：通过 DX 到达 AWS 公网端点后建立 IPsec，不经过公共互联网
Transit VIF + TGWTransit VIFTGW 上的 VPN Attachment适合多 VPC 场景，可在专线之上叠加加密并复用 TGW 路由域
与 DX 页面的对应：DX 本身不加密，加密方案是 MACsec（L2，仅专用连接）或 VPN over DX（L3 IPsec）。题目同时要求"低延迟专线 + 端到端加密"时，答案通常是后者。

与 MACsec 的边界

对比项MACsecVPN over Direct Connect
加密层级Layer 2（逐跳）Layer 3（端到端 IPsec）
适用连接仅 Dedicated ConnectionDedicated + Hosted 均可
性能开销极小（硬件加速）有 CPU 开销，单隧道约 1.25 Gbps
跨 Region不支持（链路层限制）支持（IP 路由不受限）
典型场景金融/政务硬件级加密通用合规加密 + 专线质量
成本与设计：VPN over DX 需要同时为 DX 端口与 VPN 连接付费。若只是"加密公网流量"，普通 Site-to-Site VPN 就够了；只有题目明确"已有 DX / 要求专线低延迟"时才选叠加方案。

DX 主用 + VPN 备用

这是 SAP-C02 最经典的混合网络冗余答案：DX 承载生产流量，Site-to-Site VPN 通过公网作为备份，靠 BGP 属性控制优先级；DX 中断后 VPN 自动接管。相比双 DX 双 Location，成本显著更低，但备份链路带宽与延迟较差。

七、VPN CloudHub（星型分支互联）

当多个分支机构各自只有一条 Site-to-Site VPN、又需要"分支之间互相通信"时，不需要为每对分支建隧道，而是让所有分支连接到同一个 VGW，由 VGW 做中转。

↘
VGW
Hub
↙
分支 B
CGW-B
↔
分支 C
CGW-C

工作方式

  • 每个分支建立一条 Site-to-Site VPN 到同一个 VGW，形成 hub-and-spoke。
  • 各分支通过 BGP 向 VGW 宣告自己的私有网段；VGW 把其他分支的路由再宣告回来。
  • 分支 A → 分支 B 的流量经 VGW 中转，无需 A、B 之间直连。
  • 建议各分支使用不同 BGP ASN，避免路由环路与 ASN 冲突。
CloudHub 与 TGW 的区别：CloudHub 基于 VGW，本质是"一个 VPC 的星型 VPN 汇聚"；需要连接多个 VPC、做路由域隔离或大规模扩展时，应使用 Transit Gateway，而不是在 VGW 上堆连接。
易错点：CloudHub 中分支间流量会经过 VGW，VGW 不做安全组过滤；访问控制需依赖各分支防火墙、VPC 安全组或子网 NACL。不要把它当作"分支之间天然隔离"。

八、加速 Site-to-Site VPN

当分支与 AWS 跨越大洲、公网丢包抖动严重时，普通 VPN 的吞吐和稳定性会明显下降。加速 VPN 用 AWS Global Accelerator 把流量引入 AWS 全球骨干网，改善长距离传输。

关键约束

项目说明
AWS 侧端点必须使用 Transit Gateway；不支持 VGW
加速器创建 Global Accelerator，把 VPN 作为端点，客户端流量走 Anycast IP 进入 AWS 骨干网
对端要求本地设备仍需公网 IP，并配置两条隧道
收益降低跨国丢包与抖动、提升吞吐稳定性；不改变加密方式（仍是 IPsec）
成本VPN 费用 + Global Accelerator 费用，通常高于普通 VPN
关键词映射："跨洲/长距离" + "公网质量不稳定" + "需要稳定 VPN" → 加速 Site-to-Site VPN；如果题目还要求"多 VPC"，正好与 TGW 组合。
别混用：Global Accelerator 也可以加速 ALB/NLB/EC2/EIP，但"加速 VPN"这条特性只对 TGW 上的 Site-to-Site VPN 生效。VGW + 加速器不是合法组合。

九、常见故障与排查路径

VPN 问题分四层：隧道是否建立 → 路由是否可达 → 安全策略是否放行 → 应用/DNS 是否正确。按顺序排查，比反复重建连接有效。

现象优先检查常见原因
隧道一直 DownPSK、IKE 版本、加密算法、CGW 公网 IP两端参数不匹配；本地设备在 NAT 后未启用 NAT-T；UDP 500/4500 被封
隧道 Up 但业务不通VPC 路由表、TGW 路由表、感兴趣流量路由未传播；本地未把 VPC CIDR 加入隧道；子网路由指向错误
能 ping 通但 TCP 不通安全组、NACL、实例防火墙只放行了 ICMP；NACL 无状态导致返回流量被拒
大包失败、小包正常MTU / MSS、ICMP 分片IPsec 封装后超过 1400 字节；中间设备丢弃 ICMP
访问时通时断两条隧道状态、BGP 收敛、ECMP只监控一条隧道；BGP 计时器过长；路径不对称
本地解析不了 AWS 私有域名Route 53 Resolver Endpoint、53 端口未部署 Inbound Endpoint；安全组未放行 53；本地未配置条件转发
Client VPN 连上但打不开资源Authorization Rule、Target Subnet 路由默认拒绝且未加授权；Target Subnet 路由表没有到目标网段的路由

排错顺序建议

  1. 看隧道：CloudWatch TunnelState 是否为 Up；两条隧道是否都配置。
  2. 看路由：VPC/TGW 路由表是否有目标网段；是否为传播路由；本地是否有回程路由。
  3. 看策略：安全组入/出站、NACL 双向、实例系统防火墙。
  4. 看 MTU/DNS：大包测试、dig 指定 Resolver Inbound IP 验证解析链路。
监控建议：为两条隧道都建立 CloudWatch 告警（TunnelState、TunnelDataIn/Out），并对 VPN 连接建立/断开事件做通知；仅监控"连接存在"无法发现单隧道失效。

十、场景题解析

先独立判断，再查看解析与错误选项排除。

场景 1：一家公司需要在两周内把本地数据中心接入 AWS VPC，要求流量加密、可接受公网延迟、预算有限。最合适的方案是？
正确答案：B。两周内建立 + 加密 + 成本敏感 → Site-to-Site VPN。A 的 DX 建立通常需要数周且默认不加密；C 的 Client VPN 面向终端用户，不能连接数据中心路由器；D 的 PrivateLink 用于私有访问服务端点，不是站点互联。
场景 2：某企业通过互联网连接 5 个 VPC，要求 VPN 总吞吐可扩展到 4 Gbps，且任一隧道故障不影响业务。应如何设计？
正确答案：B。需要带宽聚合 → 必须使用支持 ECMP 的 TGW，多条 VPN 连接可并行分担并快速收敛。A 单连接上限约 2.5 Gbps 且只有两条隧道；C 的 VGW 不支持 ECMP，只能主备，无法叠加到 4 Gbps；D 面向终端用户，不适用于站点互联。
场景 3：公司已有一条 Direct Connect 专线承载生产流量，合规新规要求本地到 AWS 的传输必须加密，但不接受公网 VPN 的延迟波动。最佳方案是？
正确答案：C。VPN over Direct Connect 同时满足"专线低延迟"和"传输加密"。A 的 DX 默认不加密，不满足合规；B 放弃专线质量且带宽受限；D 是服务端点私有访问方案，与混合链路传输加密无关。
场景 4：远程员工需要访问 VPC 内的私有管理资源，要求使用公司 Active Directory 认证、按部门限制可访问网段，并且员工日常上网流量不要占用 VPN 带宽。应选择？
正确答案：B。面向员工终端 → Client VPN；目录认证 → AD；按部门限制 → 用户组授权规则；不占用 VPN 带宽 → Split Tunnel。A 面向站点；C 缺少 AD 且全流量会占用带宽；D 需要专线且不服务个人终端。
场景 5：某跨国企业在新加坡、伦敦、圣保罗各有分支，均通过公网 Site-to-Site VPN 连接 AWS，近期长距离链路丢包严重、吞吐不稳定。在不改变 IPsec 加密的前提下，最优改进是？
正确答案：B。跨洲长距离 + 公网质量差 → 加速 VPN 把流量引入 AWS 骨干网，且仍保持 IPsec 加密。加速 VPN 仅支持 TGW，所以 B 是完整组合。A 形态错误；C 的 VGW 不是越多越好且不支持 ECMP；D 的 MACsec 只适用于 Direct Connect 专用连接。
场景 6：三个分支机构各自只有一条 Site-to-Site VPN，现要求分支之间可以直接互访，且不想为每对分支单独建隧道。成本最低的做法是？
正确答案：B。VPN CloudHub 用同一个 VGW 做星型中转，分支通过 BGP 宣告各自网段即可互访，避免 N×N 条隧道。A 成本高且管理复杂；C 面向终端用户；D 不用于站点间私有网络互联。

  • 协议区别：Site-to-Site 用 IPsec（IKEv1/v2）；Client VPN 用 OpenVPN（TLS）
  • AWS 侧端点：VGW 或 TGW；一条 VPN 连接只能附加其中之一
  • 两条隧道：每个 VPN 连接默认 2 条隧道，位于不同 AZ
  • 高可用：双隧道 + 双 CGW 抵御隧道、AZ、设备故障
  • 带宽上限：单隧道约 1.25 Gbps，双隧道约 2.5 Gbps
  • VGW 限制：不支持 ECMP，多连接只能主备
  • 带宽聚合：TGW + 多条 VPN 连接 + ECMP
  • 路由方式：静态路由或 BGP；BGP 收敛更快，推荐生产使用
  • VPC 路由：VGW 场景需启用 Route Propagation 或手工添加路由
  • Client VPN 端点：需 ACM 服务器证书；关联多个 Target Subnet 实现 AZ 高可用
  • Client VPN 认证：AD、SAML 联合身份、双向证书，可组合
  • Client VPN 授权：默认拒绝，必须配置 Authorization Rule
  • Split Tunnel：只有内网流量走 VPN，节省带宽
  • DX 默认不加密：加密靠 MACsec（L2）或 VPN over DX（L3）
  • CloudHub：多个分支连同一 VGW 做星型中转，基于 BGP
  • 加速 VPN：Global Accelerator + TGW，不支持 VGW
  • MTU：IPsec 隧道约 1400 字节，大包问题查 MSS/ICMP

十三、快速自测

先独立选择，再点击"查看解析"。

1. 一个 VPC 已附加 VGW，现在需要为 VPN 增加带宽到 3 Gbps 以上。以下哪种做法可行？
正确答案：B。VGW 不支持 ECMP，多条连接只能主备；每个连接固定 2 条隧道，不能自行增加；MTU 与吞吐上限无关。带宽聚合必须使用支持 ECMP 的 TGW。
2. 使用 Client VPN 让员工接入后，员工反馈"VPN 显示已连接，但无法访问 VPC 内的 EC2"。最可能的原因是？
正确答案：C。Client VPN 的授权规则默认拒绝全部目标；同时 Target Subnet 所在 VPC 路由表必须有到目标网段的路由。Client VPN 不使用 BGP；证书过期通常会导致无法建立连接，而不是连上后无权限；MTU 不是首要原因。
3. 某公司已有 Direct Connect，但审计要求"本地与 AWS 之间的数据必须端到端加密"，同时明确不能牺牲专线延迟。以下方案最合适的是？
正确答案：C。专线保留低延迟，IPsec 提供端到端加密。Private VIF 本身不加密；VPN 替换 DX 会失去专线质量；Client VPN 面向个人终端，不能承载站点间流量。
