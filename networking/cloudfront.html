一、CloudFront 基础

CloudFront 是 AWS 的全球内容分发网络（CDN），通过遍布全球的 PoP（Point of Presence）将内容缓存到距用户更近的位置，降低延迟，减少源站负载。

核心概念

边缘站点（Edge Location）

实际缓存内容的地理节点，全球 400+ 个。用户请求会被路由到最近的 PoP。

区域边缘缓存（Regional Edge Cache）

位于边缘站点和源站之间的中间层缓存，容量更大，缓存不常访问的内容，减少对源站的穿透。

分发（Distribution）

CloudFront 的核心配置单元，定义源站、行为、TTL、访问控制等。一个分发可关联多个 Origin 和多个缓存行为。

默认行为（Default Cache Behavior）

所有未匹配路径规则的请求都会应用默认行为，必须存在且无法删除。

可以配置一个主 Origin 和一个备 Origin 组成 Origin Group。当主源返回特定 HTTP 错误码（如 500、502、503、504）时，CloudFront 自动切换到备源。

三、缓存行为

Cache Policy

Cache Policy 控制 CloudFront 如何构建缓存键（Cache Key）和转发哪些信息给源站。

配置项说明影响
TTL（Time to Live）缓存时间：最小 / 默认 / 最大 TTL控制缓存时长，源站响应头可覆盖默认 TTL
Headers指定哪些请求头纳入缓存键头部越多，缓存命中率越低
Query Strings哪些查询字符串纳入缓存键全部包含会造成缓存碎片化
Cookies哪些 Cookie 纳入缓存键建议只包含必要 Cookie

TTL 优先级规则

  • 源站响应头 Cache-Control: max-age — 在 [最小TTL, 最大TTL] 范围内生效
  • 源站响应头 Cache-Control: s-maxage — 同上，优先于 max-age
  • 源站响应头 Expires — 若 max-age 未设置时使用
  • 若源站不返回缓存头，使用 默认 TTL（Default TTL，默认 86400s = 24h）
最小/最大 TTL 作用：最小 TTL 确保内容至少缓存该时长（即使源站说 0）；最大 TTL 确保内容不超过该时长（即使源站说更长）。

Cache Key 设计原则

原则：Cache Key 越小越精确，缓存命中率越高；不相关的 Header/Cookie/QueryString 不纳入 Cache Key，避免缓存碎片。动态 API 请求通常 TTL=0，禁用缓存。

四、访问控制

签名 URL vs 签名 Cookie

特性签名 URL（Signed URL）签名 Cookie（Signed Cookie）
适用场景单个文件的时效访问多个文件 / 整个目录的授权访问
RTMP 分发✅ 支持（旧版）❌ 不支持
客户端变更 URL需重新生成Cookie 有效期内无需重新生成
典型场景单个视频文件付费下载付费会员访问整个视频目录

地理限制（Geo Restriction）

  • 白名单模式：只允许指定国家/地区访问
  • 黑名单模式：拒绝指定国家/地区访问
  • 基于 IP 的地理位置数据库，非 100% 精确
  • 返回 403 Forbidden

六、HTTPS 与证书

ACM 证书区域要求

超高频陷阱！CloudFront 使用的 ACM（AWS Certificate Manager）证书 必须在 us-east-1（美国东部 N. Virginia） 申请和验证，无论你的 Origin 在哪个区域。区域性服务（ALB、API GW）使用同区域的 ACM 证书。

Viewer Protocol Policy vs Origin Protocol Policy

策略作用常见选项
Viewer Protocol Policy控制用户与 CloudFront 之间的协议HTTP and HTTPS / Redirect HTTP to HTTPS / HTTPS Only
Origin Protocol Policy控制 CloudFront 与源站之间的协议HTTP Only / HTTPS Only / Match Viewer

SNI（Server Name Indication）

CloudFront 支持 SNI（默认免费），允许一个 IP 对应多个 SSL 证书（多域名）。如果需要为旧版客户端使用专用 IP，则需要 专用 IP SSL（额外收费）。

考试提示：SAP-C02 中若题目提到"旧版不支持 SNI 的设备"，则需要选择专用 IP SSL 方案（Dedicated IP Custom SSL）。

七、性能优化

压缩（Compression）

  • CloudFront 自动压缩支持 Gzip 和 Brotli
  • 需要在缓存行为中启用 Compress objects automatically
  • 只压缩特定 MIME 类型的内容（文本类），不压缩已压缩格式（JPEG/PNG/ZIP）

S3 Transfer Acceleration vs CloudFront 区别

特性CloudFrontS3 Transfer Acceleration
主要用途内容分发（读取/下载）加速上传到 S3
方向Origin → 用户用户 → S3
缓存✅ 在边缘节点缓存❌ 无缓存，纯加速传输
使用场景静态资源、视频、API 响应缓存大文件上传、跨洲上传到 S3

Field-Level Encryption（字段级加密）

在用户请求到达源站之前，对特定敏感字段（如信用卡号、密码）进行加密。使用非对称密钥（公钥加密），只有拥有私钥的应用程序才能解密。

考试场景：需要保护敏感 POST 数据（如信用卡），且不希望敏感数据以明文形式出现在 CloudFront 或中间层 → Field-Level Encryption。

其他优化手段

  • Cache Hit Ratio 优化：减少 Cache Key 中不必要的 Header/Cookie/QueryString
  • Origin Shield：在区域边缘缓存前再加一层集中缓存层，进一步减少源站请求（适合多区域多 CloudFront 分发共享同一 Origin）
  • 预热（Invalidation）：主动清除边缘缓存，前 1000 次路径/月免费，此后收费

八、场景题解析

场景 ①：S3 私有桶 + CloudFront 访问，不暴露桶到公网

需求：S3 桶必须设为私有，但用户通过 CloudFront 访问。要求使用最新推荐方式。

正确答案：A。OAC 是当前 AWS 推荐方式，支持 SSE-KMS 加密的 S3 桶，Bucket Policy 允许 cloudfront.amazonaws.com 服务主体访问。OAI 是旧版方式，新部署不推荐。
场景 ②：旧版设备发送不规范的 HTTP 头部，需要在边缘规范化后再缓存，要求超低延迟且不需要网络调用

需求：在 Viewer Request 阶段修改/规范化请求头，极高吞吐，成本低。

正确答案：A。CloudFront Functions 专为超轻量 Viewer 阶段操作设计，执行时间 <1ms，成本极低，适合 Header 规范化、URL 重写、缓存键处理等场景。不需要网络访问时优先选 CF Functions。
场景 ③：动态内容需要在边缘进行 JWT 认证，认证失败则重定向，且可能需要调用外部认证 API

需求：用户认证、外部 API 调用，可能需要几百毫秒执行时间。

正确答案：B。Lambda@Edge Viewer Request 触发器支持网络调用（外部 API）、执行时间最长 5s，适合用户认证/授权场景。CF Functions 不支持网络调用。
场景 ④：架构为 CloudFront → WAF → ALB → EC2，如何确保 EC2 只接受来自 ALB 的流量，而 ALB 只接受来自 CloudFront 的流量？

需求：多层安全防护，防止绕过 CloudFront 直接访问 ALB。

正确答案：B。ALB 安全组配置为只允许 CloudFront 托管前缀列表（com.amazonaws.global.cloudfront.origin-facing）中的 IP，或使用 CloudFront 自定义 Header + ALB Listener Rule 验证。EC2 安全组只允许来自 ALB 安全组的流量，形成完整防护链。

已掌握 0 / 12

  • OAC 是当前推荐方式：替代旧版 OAI，支持 SSE-KMS，所有 S3 区域均支持
  • ACM 证书必须在 us-east-1：CloudFront 为全球服务，证书只认 N.Virginia 区域
  • WAF Web ACL 也必须在 us-east-1：关联 CloudFront 时与 ACM 证书同区域
  • CF Functions <1ms：只支持 Viewer 阶段，无网络访问，极低成本
  • Lambda@Edge 最多 30s：支持 Origin 阶段，可网络调用，适合认证/动态内容
  • Origin Group = Active-Passive：主源失败时切换备源，不是负载均衡
  • CloudFront ≠ Transfer Acceleration：CF 是内容分发（下载），TA 是加速上传到 S3
  • Signed URL = 单文件；Signed Cookie = 多文件：付费内容访问控制
  • Geo Restriction 返回 403：基于 IP 地理位置，非 100% 精确
  • Field-Level Encryption：敏感 POST 字段在边缘用公钥加密，只有拥有私钥的应用解密
  • SNI 默认免费，专用 IP 额外收费：旧版客户端不支持 SNI 时需专用 IP SSL
  • Origin Shield：集中缓存层，减少多分发共享同一 Origin 时的穿透请求
