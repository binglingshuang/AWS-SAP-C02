私有服务连接与端点服务 — SAP-C02 核心考点

一、架构与角色

PrivateLink 是一组通过 AWS 网络私下访问服务的能力。消费者在自己的 VPC 建立端点，服务提供方把服务放在负载均衡器后并发布为 Endpoint Service；两端不需要互相宣布 VPC CIDR，也不因此获得对方 VPC 的通用路由。

Interface Endpoint消费者在所选子网创建 endpoint network interface（ENI）；应用通过私有 DNS 名称或端点 DNS 名称连接。

一眼识别：题目强调“只向合作伙伴开放某个服务，不暴露整个 VPC”“CIDR 重叠”“无需公网”，优先考虑 PrivateLink；如果需要跨 VPC 的广泛 IP 互通，再考虑 Peering 或 Transit Gateway。

二、消费者端点：Interface Endpoint

Interface Endpoint 让消费者在 VPC 子网中获得服务入口 ENI。可按需要在一个或多个可用区创建端点网络接口；客户端访问服务时，流量经 AWS 网络抵达服务提供方，不要求为消费者 VPC 配置指向提供方 CIDR 的路由。

创建与连接流程

  1. 确认目标服务、区域和可用区支持；选择 AWS 服务或服务提供方发布的 Endpoint Service。
  2. 选择消费者 VPC、一个或多个子网，并配置端点 ENI 的安全组。
  3. 若为第三方端点服务，确认允许的主体；如果服务要求接受连接，等待提供方批准连接。
  4. 应用使用 Private DNS 名称，或端点提供的区域 / 可用区 DNS 名称访问服务。
  5. 验证 DNS、端点安全组、提供方目标健康状态和服务自身的认证授权。

与其他 VPC Endpoint 的区别

类型主要用途网络实现考试注意
Interface Endpoint大多数 AWS 服务、合作伙伴或自建 Endpoint Service子网中的 ENI；PrivateLink按端点 / 可用区及数据处理等计费，具体以服务和区域价格为准。
Gateway EndpointAmazon S3、DynamoDB将前缀列表路由加入所选路由表不创建 ENI；不使用 PrivateLink；不按小时收取端点费用。
Gateway Load Balancer Endpoint将流量送入 GWLB 后方的网络虚拟设备集群消费者子网中的 GWLBe，通过路由表透明转发不是普通应用调用服务的 Interface Endpoint；常用于防火墙 / 检测设备插入。
别把“VPC Endpoint”当成同一种实现：S3 / DynamoDB 的 Gateway Endpoint 通常是简洁且无端点小时费的选择；若需要经本地网络访问、使用 PrivateLink 私有 IP 或连接第三方 Endpoint Service，则评估 Interface Endpoint。具体服务支持方式需查官方列表。

三、服务提供方：Endpoint Service

提供方通过 Endpoint Service 将私有服务暴露给消费者。传统服务入口使用 Network Load Balancer；面向 GWLB appliance 流量的服务则使用 Gateway Load Balancer。消费者只访问被发布的服务入口，不会因此获得提供方 VPC 的全网路由。

发布服务的关键步骤

  1. 在提供方 VPC 部署服务目标，并创建跨所需可用区的负载均衡器与健康检查。
  2. 基于负载均衡器创建 Endpoint Service，检查可用区覆盖及服务名称。
  3. 按最小权限配置允许的 AWS 主体；如适用，开启连接请求接受流程。
  4. 如使用自定义 Private DNS 名称，按 AWS 流程证明对该域名的所有权，并在验证完成后供消费者启用。
  5. 消费者请求连接后，提供方按接受策略批准或拒绝；连接建立后仍由应用认证和授权具体用户 / 请求。
控制点作用不能替代什么
Allowed principals限制哪些 AWS 主体可请求连接该服务。不等于业务用户认证，也不代表连接请求已被接受。
Acceptance required要求提供方审查并接受新的端点连接。不自动撤销业务层权限；已建立连接也仍需应用控制。
负载均衡器健康检查筛除异常目标，控制新流量的目标选择。不检查消费者是否有权调用应用中的特定操作。
Private DNS 验证证明服务提供方控制自定义私有 DNS 域名。不等于消费者已启用端点 Private DNS 或应用 DNS 已正确解析。
SaaS 多租户常见模式：每个客户在自己的 VPC 建立端点，服务商控制服务入口与后端；客户可独立撤销自己的端点连接，服务商不必把整段 VPC 网络开放给客户。

四、DNS、可用区与连接可用性

DNS 选项

  • 端点 DNS 名称：创建 Interface Endpoint 后提供区域级及可用区级 DNS 名称，可用于验证或显式定位端点。
  • Private DNS：对支持的 AWS 服务，消费者可启用 Private DNS，让服务的标准 DNS 名称在 VPC 内解析到端点 ENI。
  • 自定义私有域名：Endpoint Service 可关联已验证的私有 DNS 名称；消费者启用前仍要满足服务状态和 VPC DNS 配置要求。
  • 混合 DNS：本地客户端通过 DX / VPN 到达 VPC 时，需规划 Route 53 Resolver、条件转发和名称解析路径；端点存在并不自动替本地环境配置 DNS。
常见排查顺序：DNS 是否解析至端点私有地址 → 客户端到端点 ENI 的路由与安全组 / NACL → endpoint connection 状态 → 提供方负载均衡器与目标健康 → 服务认证、授权和应用响应。

可用区设计

  • 消费者在需承载流量的可用区创建端点网络接口，以减少单 AZ 依赖；实际可用区名称映射应以双方可用的 AZ ID / 服务列表为准。
  • 提供方需在 Endpoint Service 中启用相应可用区，并确保负载均衡器及后端容量覆盖预期故障域。
  • 跨可用区能力和费用取决于端点、负载均衡器和区域配置；不要仅凭“服务是多 AZ”推断每条路径都没有跨 AZ 流量。
  • 为故障切换保留健康的端点与目标容量，并通过应用重试、超时和幂等设计处理连接中断。
考点：端点 DNS 正常不代表后端服务健康；单 AZ Endpoint 也不会因 PrivateLink 自动变成多 AZ 高可用架构。

五、安全、策略与可观测性

层次应检查的控制职责边界
消费者网络入口Interface Endpoint ENI 上的安全组入站规则、子网 NACL 与客户端路由。安全组允许客户端到端点的目标端口；它不授予 AWS API 权限。
端点连接允许的主体、服务策略、连接接受状态。控制哪些账号 / 主体可以建立连接；不负责业务请求级鉴权。
AWS 服务调用IAM 身份策略、服务资源策略、端点策略（仅限支持的服务和端点）。端点策略是附加边界，不替代 IAM / 资源策略；不是所有 Endpoint Service 都有通用端点策略。
提供方网络与应用NLB / GWLB、目标安全组、应用认证与授权、速率限制和审计。仅仅“私有连接”不代表请求可信，也不自动加密或鉴别应用层身份。
审计与故障定位CloudTrail（适用的 API 管理事件）、VPC Flow Logs、负载均衡器 / 应用日志与指标。根据服务类型及日志能力组合使用；先定位是控制面、网络面还是应用面。
安全原则：PrivateLink 降低暴露面，不是零信任的替代品。仍需最小权限、TLS / 应用认证、端点连接生命周期管理，以及提供方对租户数据的隔离。

六、PrivateLink vs VPC Peering

两者解决的问题不同：Peering 让两个 VPC 通过私有 IP 路由互通；PrivateLink 把一个服务作为消费者可连接的私有入口。题干要求“连接一个服务”时不必为整个网段建立连接。

维度PrivateLinkVPC Peering
暴露范围面向指定服务 / 端点，服务提供方控制发布面。提供双方 VPC CIDR 间的 IP 路由；由路由和安全组细化允许流量。
CIDR 重叠通常适合重叠网段的服务级连接场景。对等 VPC 的 IPv4 CIDR 不可重叠。
路由可传递性不是通用 VPC 路由，也不提供对端 VPC 的传递路由。非传递：不能经一个 Peering 连接访问另一个 Peering 后的网络。
消费者发起消费者为服务创建端点连接；不获得提供方任意地址的路由。双方按路由表和安全策略配置可达地址。
典型用途共享 API、第三方 SaaS、集中服务端点、AWS 服务私有访问。少量 VPC 之间需要广泛私有 IP 通信。
扩展与治理适合将服务逐个发布给许多消费者，需管理每个服务及端点连接。大量全互联时连接与路由管理复杂；可评估 Transit Gateway。
选型口诀：“只给我用这个服务”→ PrivateLink；“两个网段需要互相访问多种资源”→ Peering；“许多 VPC 需要中心化路由与分段”→ Transit Gateway。题目中的规模、CIDR、传递性和管理要求优先于口诀。

七、常见架构与易混边界

高频组合

  • 消费者私有子网访问 AWS API：按服务支持情况选 Interface Endpoint；S3 / DynamoDB 可比较 Gateway Endpoint 的能力与费用。
  • 合作伙伴提供 SaaS：服务商发布 Endpoint Service，客户创建 Interface Endpoint；按需启用私有 DNS 与连接接受。
  • 多账号共享内部 API：提供方发布服务并限制允许主体，消费者逐个创建端点；结合 Organizations / IAM 与应用层身份验证。
  • 本地网络私有访问：本地经 DX / VPN 到达消费者 VPC 的 Interface Endpoint 私有 IP；另行配置 DNS Resolver、路由、端口和策略。
  • 集中式网络检查：若目标是插入透明防火墙而非调用应用 API，评估 GWLB / GWLBe；使用 PrivateLink 端点服务并不能自动改写现有 VPC 的所有路由。

不要混淆的能力

误区正确判断
PrivateLink 会创建到对端 VPC 的 Peering。不会。端点连接是服务级私有访问，不是两端 VPC CIDR 全互通。
只要创建端点，本地 DNS 就会自动解析。不会。混合 DNS 仍需 Route 53 Resolver / 条件转发等配置。
端点连接成功就可调用服务中的所有 API。不一定。IAM、资源策略、应用认证与授权仍生效。
Gateway Endpoint 也是 PrivateLink 的 Interface Endpoint。不是。Gateway Endpoint 用路由表；Interface Endpoint 才创建 ENI 并使用 PrivateLink。
PrivateLink 一定比 Peering 更便宜。不能一概而论。比较端点小时数、数据处理、跨 AZ 流量、数据传输及运维成本。
服务提供方必须手动接受每个连接。只有在启用 acceptance required 时需要；根据信任边界与运营流程决定。

八、场景题解析

场景 1：多租户 API，租户 VPC CIDR 可能重叠

一家 SaaS 厂商要让数百个客户从私有网络调用其 API。客户只应访问该 API，不能访问厂商其他子网；客户 CIDR 由各自管理，可能互相重叠。

正确方向：厂商创建 NLB 并发布 Endpoint Service；客户在各自 VPC 创建 Interface Endpoint。
分析：PrivateLink 暴露具体服务，不要求客户与服务商交换 VPC 路由，适合大量消费者、CIDR 重叠和服务级隔离。配置允许主体与连接接受策略，并在应用层认证租户。
排除：Peering 要求 CIDR 不重叠且暴露面更宽；Transit Gateway 用于网络路由中枢，不是发布单个 SaaS API 的最小方案。
场景 2：两个 VPC 要双向访问多种私有资源

两个 VPC 的 CIDR 不重叠，应用需访问对方多个子网中的数据库、文件服务和内部管理接口，团队希望保持简单的点对点网络连接。

正确方向：评估 VPC Peering，并配置双方路由表与安全组。
分析：需求是多种资源间的私有 IP 路由，而不是仅调用一个被发布的服务。Peering 可满足点对点互通，但不是传递路由。
排除：PrivateLink 需要把所需服务逐个发布，不能提供通用 CIDR 路由；如果连接规模持续增长或需要中心化检查，再评估 Transit Gateway。
场景 3：消费者和提供方 CIDR 重叠

收购后的两个业务 VPC 地址段重复，但消费者只需要调用提供方的订单查询 API，不能重新编号网络。

正确方向：将订单 API 作为 Endpoint Service 发布，消费者通过 Interface Endpoint 访问。
分析：服务级连接避免建立重叠 CIDR 间的路由互通。验证服务支持的区域和 AZ，并在应用侧限制可访问的租户与 API。
排除：Peering 不能用于 CIDR 重叠的 VPC；PrivateLink 并不解决双方所有网段的地址冲突，只隔离并暴露服务入口。
场景 4：私有子网访问 S3，要求控制端点成本

EC2 仅需访问同区域 S3，网络与 DNS 要求采用标准服务名，且没有通过本地网络访问该端点的需求。

正确方向：优先评估 S3 Gateway Endpoint，并将其关联到所需路由表。
分析：Gateway Endpoint 不创建 ENI，且没有端点小时费用；其策略可作为额外控制（具体能力以服务支持为准）。
排除：不要因为题干出现“私有子网”就默认选择 Interface Endpoint。若必须让本地经 DX / VPN 访问 S3 私有端点，或需要 Interface Endpoint 能力，再选择并核算 Interface Endpoint。
场景 5：开发者通过 DX 从本地访问私有服务

本地构建系统通过 Direct Connect 连接到 VPC，需要调用一个合作伙伴发布的私有 API，不能经公网；API 服务本身已通过 PrivateLink 提供。

正确方向：在连接到本地网络的消费者 VPC 创建 Interface Endpoint；配置本地到端点 ENI 的私有路由与 DNS 解析。
分析：端点 ENI 提供 VPC 内私有地址，可经 DX / VPN 到达；Route 53 Resolver 与本地条件转发负责名称解析，安全组和策略负责放行所需端口与请求。
排除：Gateway Endpoint 的路由表机制不等同于可从本地直接访问的 ENI；单有 DX 连接也不会自动配置私有 DNS。
场景 6：限制未知消费者接入，并保留提供方审批

服务只允许指定企业账号连接。每个新端点还需服务团队核准，但已连接的客户仍须按业务角色授权。

正确方向：限制 Endpoint Service 的 allowed principals，并启用连接接受要求；保留应用层认证授权。
分析：允许主体控制谁可以请求连接；人工接受用于审批连接本身。应用层鉴权决定已连接客户可执行哪些操作，应单独实施与审计。
排除：不要把连接批准等同于授予业务权限；也不要用宽泛的主体列表代替最小权限。

十一、快速自测

先独立作答，再点击选项查看解析。

1. 客户与服务商 VPC CIDR 重叠，客户只需调用服务商的一个 API，优先使用什么？
正确答案：B。PrivateLink 暴露服务级入口，不需要重叠 VPC 之间建立 CIDR 路由。Peering 不支持 CIDR 重叠，S3 Gateway Endpoint 仅针对 S3。
2. EC2 在私有子网中仅需访问同区域 S3，题目强调低成本且不需要本地接入。优先选择什么？
正确答案：A。Gateway Endpoint 不创建 ENI，并且没有端点小时费用；它通过路由表提供到 S3 的私有访问。若题目增加从本地访问或 Interface Endpoint 特定要求，再比较其他方案。
3. Endpoint Service 只允许指定账号，并要求每个端点连接先经团队审批，应配置什么？
正确答案：B。Allowed principals 限制可请求连接的主体，acceptance required 让提供方审查连接请求。服务调用权限仍需单独管理。
