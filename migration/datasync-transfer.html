AWS DataSync 与 Transfer Family
在线数据集迁移与托管文件传输 — SAP-C02

DataSync 用于在支持的文件/对象存储之间自动化、高速传输数据；Transfer Family 为合作伙伴和应用提供托管文件传输协议端点。二者处理的数据交付模式不同，不能与长期混合云文件访问或离线设备迁移混为一谈。

一、先识别数据传输模式

题目若要求把已存在的大量文件/对象复制到 AWS，评估 DataSync；若外部用户或合作伙伴需要用标准协议上传/下载到 S3 或 EFS，评估 Transfer Family。

需求首选方向关键区别
一次性/定期迁移 NFS、SMB 或对象数据到 AWSAWS DataSync由任务计划和端点定义数据复制与验证。
合作伙伴以 SFTP、FTPS、FTP 或 AS2 交换文件AWS Transfer Family托管协议端点、用户身份与 S3/EFS 后端。
本地应用持续以文件系统语义访问云端数据评估 Storage Gateway 或其他混合存储架构长期在线访问模式，不等同于批量搬迁。
网络带宽受限且需离线转移超大数据集评估 Snow Family 当前可用产品与区域物理设备运送；不是在线同步方案。

二、AWS DataSync：任务驱动的数据传输

  • Endpoint / Location：描述源和目标存储位置；根据数据源选择网络可达的 DataSync Agent 或服务端点。支持位置类型、功能和区域以当前服务文档为准。
  • Task：定义从源到目标的传输、筛选、验证和覆盖行为；可按需启动或配置计划，适合重复同步。
  • Agent：访问本地存储或特定网络中的数据源并安全连接 AWS 服务；部署前核实网络、资源规格、激活和端点连通要求。
  • 可观测性：使用任务执行状态、CloudWatch 指标/日志和任务报告检查失败文件、吞吐和完成情况；按需要选择数据验证级别。
  • 带宽与规模：可通过带宽限制、任务计划和并行任务治理共享链路；基于实际变更率、文件数、对象大小和网络窗口测试吞吐。
传输完成不等于应用切换完成：仍要验证数据完整性、权限/所有权、元数据、目标路径、增量同步策略和最终冻结/切换窗口。

三、AWS Transfer Family：托管协议端点

协议典型场景设计要点
SFTP安全文件交换，合作伙伴常用 SSH 文件传输。用户/身份提供方、SSH 公钥、逻辑目录、角色权限、端点网络和主机密钥管理。
FTPS需使用 TLS 保护的 FTP 工作流。证书、协议兼容、客户端配置及端口/防火墙要求。
FTP仅在对端协议要求且风险被接受时使用。FTP 本身不加密传输；通过网络隔离、受控访问等措施评估风险，优先考虑加密协议。
AS2B2B EDI 文档交换与消息回执。合作伙伴配置、证书、消息签名/加密、MDN 和审计要求。
  • 可将文件工作流与 Amazon S3 或 Amazon EFS 集成；根据应用选后端，不代表后端对象/文件自动具有业务一致性。
  • 身份可采用服务管理或集成的自定义身份提供方等方式；授权角色应限制到用户所属目录和所需操作。
  • 端点可采用支持的公开或 VPC 网络选项；检查互联网暴露要求、来源 IP 限制、DNS、弹性 IP、负载均衡及客户端可达性。
  • CloudWatch、CloudTrail、结构化日志和事件通知可用于审计与故障定位；自动化上传后处理应做好幂等与失败重试。

四、带宽、验证与运行治理

  1. 测量基线：盘点数据量、文件数量/尺寸分布、变更率、链路利用率、可用传输窗口和对生产业务的影响。
  2. 分批执行：按数据集、应用依赖和业务窗口规划任务；先小批试传并测量端到端吞吐。
  3. 限制与调度：用带宽限制和任务计划避免挤占生产网络；多任务并发前确认共享链路和目标端承载。
  4. 监控失败：查看任务执行、日志、报告和网络错误；区分权限、路径、吞吐、文件锁定和目标限制。
  5. 最终切换：按需执行增量同步，冻结源端写入或采用一致性策略，验证目标后更新应用路径。

选择 DataSync 的验证模式时权衡传输耗时与检查覆盖；对关键迁移保留可审计的执行结果和业务核验。Transfer Family 重点验证认证、授权、目录映射、客户端兼容和对象/文件落点。

五、与其他迁移方式的边界

服务解决的问题容易混淆之处
DataSync自动化在线复制/同步文件和对象数据。不是持续挂载访问的文件系统网关；也不是文件传输协议服务端。
Transfer Family为客户端托管 SFTP/FTPS/FTP/AS2 协议入口。面向协议客户端交付，不是替代 DataSync 的大规模存储同步任务。
Storage Gateway本地应用与 AWS 存储之间的混合访问/缓存模式。长期混合访问与一次/周期性数据迁移目标不同。
Snow Family在网络传输不现实或需边缘计算时评估离线/物理数据处理路径。根据数据规模、可用产品、运送周期、区域与安全要求评估；不能只按“TB 级”设固定阈值。
MGN / DMSMGN 迁移服务器；DMS 迁移/复制数据库数据。文件复制不等于服务器或数据库迁移；参见 MGN 和 DMS/SCT。

六、场景题解析

场景一：本地 NFS 文件需要按计划同步到 Amazon EFS

团队要迁移大量共享文件，并能安排周期性增量复制。

方向：配置 DataSync 源/目标位置和任务，部署满足网络要求的 Agent，按窗口计划运行并验证目标数据。
这是存储数据集传输，而不是为客户端开放 SFTP 服务。
不要用 Transfer Family 代替存储到存储的批量同步任务。

场景二：供应商每天通过 SFTP 上传交易文件到 S3

公司不希望管理 FTP 服务器，并要求按供应商隔离访问目录。

方向：使用 Transfer Family SFTP endpoint，配置身份验证、用户角色、逻辑目录映射及最小权限 S3 访问。
托管协议入口和用户授权是核心；存储后端为 S3。
只创建端点不代表用户权限自动隔离。

场景三：外部合作方只能使用 AS2 交换 EDI

需要消息签名/加密、伙伴配置和交付回执。

方向：评估 Transfer Family AS2 支持，配置交易伙伴、证书、消息处理与 MDN/审计流程。
AS2 是 B2B 消息交换协议，不能简单当作 SFTP 用户登录。
不要只配置 S3 bucket 而遗漏协议和伙伴级信任配置。

场景四：数据迁移会占满生产链路

业务要求在夜间窗口同步，白天限制传输速率。

方向：为 DataSync 任务设置带宽治理和计划，先测吞吐并监控任务与生产网络影响。
带宽上限和排程可将传输融入现有网络运营。
不要无依据地并发启动大量任务，导致链路拥塞。

场景五：本地应用需要长期以 NFS 方式读写 AWS 文件

不是一次迁移，应用仍需持续使用混合云文件访问。

方向：评估 Storage Gateway 等混合存储架构；DataSync 可承担数据搬迁/同步，但不提供同类持续文件网关语义。
区分一次性/周期复制和应用在线访问模式。
不要将 DataSync task 当成永久挂载点。

场景六：数 PB 数据但出口带宽有限、线上迁移赶不上窗口

可接受设备运送周期，需要尽快完成初始种子数据复制。

方向：评估 Snow Family 离线传输路径及当前可用设备/区域，再设计后续增量同步与切换。
选择基于可用带宽、数据量、时限、运送周期和成本的比较，而不是死记容量阈值。
物理传输后仍需处理后续变化、数据验证和应用切换。

九、快速自测

1. 供应商通过 SFTP 上传文件到 S3，优先选什么？

Transfer Family；同时配置身份、S3 权限、目录映射和端点网络。

2. 需要限制大规模在线传输对生产链路的影响，怎么办？

使用 DataSync 的带宽治理/计划能力，并先测试吞吐、监控网络与任务结果。

3. DataSync 能否取代长期挂载访问的混合文件网关？

不能简单等同。DataSync 是任务式数据传输；长期混合访问应评估 Storage Gateway 等架构。
