AWS Elastic Disaster Recovery (DRS)
持续服务器复制与灾难恢复 · SAP-C02

AWS DRS 将兼容的本地或云端源服务器持续复制到 AWS 的暂存区域，在灾难或恢复演练时启动恢复实例。它解决的是服务器级灾难恢复，不是 AWS Backup 的策略性备份，也不是 MGN 的一次性 Rehost 迁移流程。

一、服务模型

DRS 在源服务器安装 AWS Replication Agent，将磁盘块级变更持续、异步复制到目标 AWS 区域的暂存资源；发生故障或执行演练时，可按恢复设置启动目标 EC2 实例。

环节作用设计关注点
源服务器与 Replication Agent读取源服务器磁盘变化并发送复制数据。核对 OS、磁盘、代理要求、网络连通性与变更率。
暂存区域（Staging Area）承载复制数据和复制基础设施。规划子网、路由、存储、加密、带宽、配额与成本。
恢复设置定义恢复实例的计算、存储和网络参数。预先配置目标 VPC、子网、安全组、实例规格和启动顺序。
恢复实例在演练或故障时启动到恢复环境。验证应用依赖、DNS/流量切换、数据状态、监控和回退计划。
性能指标：DRS 采用持续异步复制，常用于实现较低的数据丢失窗口和较快恢复，但实际 RPO / RTO 并非固定保证值；它们取决于源端变更率、网络、启动时间、应用依赖和恢复演练结果。

二、支持范围与 SAP 场景

  • 应用无关：DRS 在操作系统与磁盘层复制服务器，不理解或转换应用协议、数据库 schema 或业务事务。
  • 源环境：可用于符合当前支持要求的本地物理服务器、VMware 等虚拟环境及其他云环境服务器，恢复目标为 AWS。
  • 操作系统：常见 Linux 发行版和 Windows Server；部署前须核对 DRS 当前支持的操作系统、内核、磁盘和区域清单。
  • 工作负载：可保护运行于受支持服务器上的企业应用与数据库，包括 SAP 应用服务器、Oracle、SQL Server、MySQL、PostgreSQL 等。
  • SAP 架构：可将 SAP 应用服务器作为服务器级恢复对象；对 SAP HANA 等数据库层，应结合数据库原生复制与一致性设计（例如评估 HANA System Replication），不能把块级复制当作数据库原生复制的替代品。
设计边界：请依据 AWS DRS 当前支持矩阵验证源系统及工作负载。对于高事务率或大型数据库，需额外评估应用一致性、数据库恢复流程、复制吞吐及目标容量。

三、复制、演练与故障恢复流程

  1. 准备：定义恢复区域、目标网络、安全、IAM、密钥、配额、恢复优先级和业务 RTO/RPO。
  2. 启用复制：在源服务器安装代理并完成初始同步，随后持续复制块级变化；监控复制状态、延迟、吞吐和错误。
  3. 执行恢复演练：在隔离或预定的恢复环境启动测试实例，验证系统启动、应用依赖、数据、性能和流量切换流程；妥善隔离测试网络和流量，可在不切断主生产环境的情况下验证恢复步骤。
  4. 灾难切换：根据事件流程启动恢复实例、验证业务并切换客户端流量；避免未经协调的源端/恢复端双写。
  5. 回切与复原：灾难结束后按计划重新同步并恢复到目标环境，明确数据权威端、切换窗口和回退条件。

关键考点：DRS 支持恢复演练，演练用于验证真实启动与恢复步骤；持续复制状态正常并不代表应用恢复、网络切换和业务验收已经通过。

四、DRS、MGN 与 AWS Backup 的边界

维度AWS DRSApplication Migration Service (MGN)AWS Backup
主要目标持续灾难恢复与恢复演练。将服务器 Rehost 到 AWS 并完成切割。策略化备份、保留、归档及恢复。
主要机制源服务器代理进行块级持续异步复制。服务器复制后按 Test / Cutover 流程迁移。按计划创建恢复点，可配置生命周期和副本。
RPO / RTO可设计较低的数据丢失窗口和恢复时间；实际结果取决于复制健康、恢复资源、应用流程与演练。针对迁移测试和切割流程设计，不是长期 DR 指标。受备份频率、恢复点和恢复步骤影响，通常不能等同于持续复制。
典型题目线索源机房故障、持续保护、恢复演练、failover / failback。大批服务器迁移、尽量少改造、迁移测试与正式切换。合规保留、定期备份、Vault Lock、跨账号/跨区域备份。
不是不能替代数据库原生复制或备份留存治理。不是长期灾难恢复运营服务。不是持续服务器块级复制或快速启动整机的通用替代品。

更多迁移流程见 AWS Application Migration Service (MGN)；备份策略见 AWS Backup。

五、场景判断

场景一：本地机房发生灾难，需启动服务器恢复环境

需要在 AWS 持续维护服务器复制，并提前验证恢复流程。

方向：评估 AWS DRS，规划暂存和恢复网络，定期执行恢复演练。

场景二：迁移团队需把服务器搬迁到 AWS

目标是一次性 Rehost，要求测试目标实例后再正式切换。

方向：评估 MGN。若切换后仍需长期灾备，再单独设计 DRS 等持续恢复能力。

场景三：法规要求长期保留、避免备份被删除

要求按保留期归档、集中管理备份并强化不可删除控制。

方向：评估 AWS Backup 的备份计划、生命周期、跨区域复制和 Vault Lock，而不是只依赖 DRS。

场景四：SAP HANA 与应用服务器需要跨站点保护

既要恢复 SAP 应用层，也有数据库一致性和事务恢复要求。

方向：可评估 DRS 保护应用服务器，并为 HANA 设计原生复制/恢复方案；整体 RPO/RTO 要通过端到端演练验证。

六、考前速记

  • DRS = 服务器级持续块复制与灾难恢复。
  • MGN = 服务器迁移（Rehost），测试后切割。
  • AWS Backup = 策略性备份、保留、归档与合规治理。
  • RPO / RTO 取决于完整架构和演练，不是服务名称自动保证的固定数值。
  • 数据库一致性与 SAP HANA 灾备要结合原生机制和应用级流程设计。
