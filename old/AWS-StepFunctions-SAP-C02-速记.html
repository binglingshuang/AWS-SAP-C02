01 Standard vs Express（最高频）

工作流类型一旦创建不可修改。考试看到关键词先在心里分类。

STANDARD

标准工作流

  • 最长运行：最多 1 年
  • 执行语义：Exactly-once，适合非幂等操作
  • 计费：按状态转换次数（state transition）
  • 执行历史：控制台可见，支持 GetExecutionHistory
  • 支持：Distributed Map、Redrive
  • 典型：人工审批、支付、长作业、ETL 跑数小时、需审计
EXPRESS

快速工作流

  • 最长运行：最多 5 分钟
  • 执行语义：Async = At-least-once；Sync = At-most-once，必须幂等
  • 计费：按执行次数 + 时长 + 内存（GB·秒）
  • 执行历史：控制台无完整历史，必须开 CloudWatch Logs
  • 支持：高并发吞吐；不支持 Distributed Map / Redrive
  • 典型：IoT ingestion、每秒上万事件、短数据转换、成本敏感
口诀：流程 >5 分钟 / 人工审批 / 不能重复执行 → Standard；高吞吐、短流程、可接受至少一次、成本优先 → Express。

02 三种服务集成模式（Task 调用 AWS 服务）

Resource ARN 的后缀直接决定模式。这是 SAP-C02 最爱挖的点。

arn:aws:states:::<service>

① Request Response（默认）

调用服务拿到 HTTP 返回立刻走下一状态，不等后台任务完成。适合 SNS 发消息、DynamoDB PutItem、同步 API。

arn:aws:states:::<service>.sync

② Run a Job（同步等待）

Step Functions 内部轮询，等后台 Job 跑完才往下走。适合 Batch、Glue、EMR 这类异步 Job。注意：仅优化集成服务支持 .sync，不是所有 API 都行。

arn:aws:states:::<service>.waitForTaskToken

③ Wait for Callback（Task Token）

把 Task Token 传给下游，工作流暂停卡住；外部系统（人工审批、第三方服务）拿到 Token 后调用 SendTaskSuccess / SendTaskFailure 才继续。

考题陷阱：不要自己写 Lambda 循环轮询。等 Job 完成优先用 .sync；外部系统没法被轮询 → 用 Task Token Callback。

03 状态类型速查（只考功能区分，不默写 ASL）

不用背语法，看到关键词能对应到状态名即可。

状态类型作用考试关键词
Task调用 AWS 服务、Lambda、API；支持 Retry / Catch执行某一步操作
Choice分支判断（if / else）根据字段走不同分支
Wait休眠固定时长，或等到某个时间戳等待 N 秒 / 等到某时刻
Parallel并行多分支，全部完成才继续；任一分支失败整体失败同时跑 N 件事
Map（Inline）遍历数组并行执行子项，并发有限少量数组遍历
Map（Distributed）超大批量，S3 作为数据源，独立子执行；仅 Standard 支持遍历 S3 几十万对象
Pass不调任何服务，做输入输出投影 / 数据转换裁剪、重命名字段
Fail / Succeed显式终止流程，标记失败 / 成功提前结束

04 错误处理：Retry + Catch

执行顺序：出错 → 先 Retry（重试）→ 重试耗尽 → 再 Catch（跳转）。

Retry（指数退避重试）

匹配瞬时错误：网络抖动、限流、5xx。参数：

  • ErrorEquals 错误码，内置 States.Timeout、States.ALL
  • IntervalSeconds 首次间隔
  • MaxAttempts 最大次数（默认 3）
  • BackoffRate 退避倍率（默认 2.0）
  • TimeoutSeconds Task 整体超时 → 触发 States.Timeout

Catch（捕获后跳转）

匹配业务不可恢复错误，跳到补偿 / 回滚 / 告警状态。

  • 只有 Task / Parallel / Map 支持 Retry 和 Catch
  • Wait / Choice 不支持
  • 非幂等操作（如支付）慎用 Retry

05 输入输出处理（ASL 路径字段）

常作为干扰项出现，记住每个字段的作用即可。

字段作用
InputPath截取输入中哪一部分进入状态
Parameters构造传给服务的参数
ResultPath把服务返回结果塞回输入 JSON；ResultPath: null 表示丢弃本次返回，只传原始输入
OutputPath本状态最终输出给下一状态的内容
ResultSelector对返回结果做字段重命名、裁剪（最常用）

06 IAM 权限（高频挖坑点）

状态机有一个 执行角色（Execution Role），是 状态机自己 去调用 Lambda、Batch、S3、DynamoDB 等服务时用的角色。

它和"发起 StartExecution 的用户角色"是两回事。策略里要显式允许对应服务 API：lambda:InvokeFunction、batch:SubmitJob 等。
回调模式下，下游服务（人工审批系统）需要 states:SendTaskSuccess / states:SendTaskFailure 权限。

典型错项："给调用 Step Functions 的用户加 Lambda 权限" —— 错。是状态机执行角色有权限，不是调用者。

07 触发方式与编排选型

触发源适用场景
EventBridge定时触发、事件触发（S3 上传、自定义事件）。SAP-C02 最爱考的编排入口
API Gateway同步对外 API；搭配 Express 工作流
Lambda调 StartExecution API 启动工作流
SQS → EventBridge Pipes消息解耦、削峰后进入编排
选型：简单消息触发、不需要分支编排 → SQS + Lambda；多步骤、分支、重试、人工审批、长流程 → Step Functions。Step Functions 本身不是队列，不负责削峰。

08 Redrive（失败重驱，新版考点）

支持 Redrive

Standard 工作流。失败的执行可重新启动，重试计数器重置，上游临时故障修复后批量重跑。

不支持 Redrive

Express 工作流。失败执行只能重新发起新执行。

09 高频场景答题模板（直接套）

看到下面这类题干，按"正确答案 / 常见错项"直接对号入座。

Q1需要人工审批环节，审批时长不固定。
Standard + .waitForTaskToken；人工系统拿 Task Token，审批后 SendTaskSuccess。
Express；Lambda 循环轮询；SQS 轮询。
Q2提交 Batch / Glue Job，要等 Job 完成再走下一步。
Standard + .sync 集成模式。
Request Response + Lambda 自己写轮询循环。
Q3每秒上万条 IoT 事件，每条做简单转换，5 分钟内跑完，成本优先。
Express Workflow。
Standard；按 state transition 计费成本高。
Q4遍历 S3 里几十万个对象，并行处理。
Standard + Distributed Map（S3 清单作为数据源）。
Inline Map（并发有限）；Express（不支持 Distributed Map）。
Q5支付流程，不允许重复扣款。
Standard Exactly-once；Retry 慎用，业务必须幂等。
Express（At-least-once，可能重复扣款）。
Q6某一步经常超时，希望重试 3 次，仍失败就进告警补偿分支。
Task 配 Retry 匹配 States.Timeout + Catch 跳到告警状态。
Wait 状态里做重试；Choice 里判断错误。

10 避坑清单（最容易选错的干扰项）

  1. Express 不能跑超过 5 分钟，不能做 Distributed Map，控制台无标准执行历史。
  2. .sync 不是所有服务都支持，仅限优化集成的服务。
  3. Task Token 不是轮询，是暂停等待外部回调。
  4. Step Functions 本身不是队列，是编排器；削峰靠 SQS，不是 Step Functions。
  5. Distributed Map 只有 Standard；Inline Map 并发有限。
  6. 计费：Standard 按状态转换，不是按时长；Express 按执行 + 时长 + 内存。
  7. 状态机类型一旦创建不能切换，只能重建。

11 考场决策树口诀

题目读完后，按这 7 步依次自问，答案基本自动浮现。

  1. 流程 >5 分钟 / 人工审批 / 非幂等需要 Exactly-once → Standard
  2. 高吞吐、短流程、允许至少一次、成本优先 → Express
  3. 调用异步 Job，需要等 Job 结束 → .sync
  4. 外部系统 / 人工审批，不知道多久返回 → .waitForTaskToken
  5. 只发请求，不等后台任务完成 → Request Response
  6. 大批量遍历 S3 对象 → Distributed Map（Standard）
  7. 瞬时失败 → Retry；业务失败 → Catch 补偿
