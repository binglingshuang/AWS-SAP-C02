一、S3 存储类别（Storage Classes）

One Zone-IA 的风险

数据仅存储在单个可用区。如果该 AZ 发生灾难性故障，数据将永久丢失。因此只适合可重新生成的数据（如缩略图、中间处理结果），不适合唯一的业务数据。

二、生命周期策略（Lifecycle Policies）

自动化对象的存储类别转换和过期删除，降低成本，无需手动管理。

转换操作（Transition Actions）

将对象从一种存储类别转换到另一种。例如：对象创建 30 天后从 Standard 转换到 Standard-IA，90 天后转换到 Glacier Flexible Retrieval。

过期操作（Expiration Actions）

在指定时间后永久删除对象或删除标记（Delete Marker）。例如：日志文件保留 365 天后自动删除；或清理版本控制中过时的旧版本。

存储类别转换限制（单向，不可逆）

S3 生命周期转换是单向的，只能从更"热"的层向更"冷"的层转换，不能反向操作。

与版本控制结合

启用版本控制后，可以对当前版本和非当前版本（Noncurrent versions）分别设置策略：

  • 当前版本（Current）：正常的转换和过期规则
  • 非当前版本（Noncurrent）：可设置保留 N 天后转换或删除旧版本
  • 删除标记（Delete Markers）：配置何时清理孤立的删除标记

Multipart Upload 未完成的清理

分段上传（Multipart Upload）中途中断后，已上传的分段会在存储桶中占用空间并持续计费。可以通过生命周期策略设置规则，自动中止超过指定天数（如 7 天）仍未完成的分段上传，释放存储空间。

典型场景：设置"中止未完成的 Multipart Upload（7 天）"是 S3 成本优化的常见做法，在 SAP-C02 中经常出现在成本优化题型中。

三、版本控制（Versioning）与 MFA Delete

版本控制的三种状态

状态描述效果
未启用（Unversioned）默认状态，从未启用过版本控制上传同名对象会覆盖，无法恢复旧版本
已启用（Enabled）版本控制处于激活状态每次上传创建新版本 ID，可恢复任意历史版本
已暂停（Suspended）曾启用过，现已暂停不再为新上传创建版本，历史版本保留。新上传的对象版本 ID 为 null
重要：一旦启用版本控制，无法回到"未启用"状态，只能"暂停"。这是高频陷阱题考点。

删除操作的行为

不指定版本 ID 的删除

S3 不会真正删除对象，而是在最新位置放置一个删除标记（Delete Marker）。对象看起来消失了，但历史版本都在，可以通过删除"删除标记"来恢复。

指定版本 ID 的删除

S3 会永久删除该特定版本，无法通过 S3 本身恢复。需要指定版本 ID 才能彻底清除某个版本。

MFA Delete

MFA Delete 为 S3 版本控制增加了额外的安全层，防止误删或恶意删除：

  • 只有桶拥有者（root 账户）可以启用或禁用 MFA Delete
  • 启用后，永久删除某个版本或更改版本控制状态，都需要在请求中包含 MFA 验证码
  • 必须通过 AWS CLI 配置（控制台不支持直接启用）
  • 适用场景：保护关键业务数据，防止勒索软件删除版本历史
记忆：MFA Delete ≠ MFA 登录控制台。它是 S3 API 层面的额外验证，要删除版本必须带 MFA Token。

版本控制与复制的关系

S3 跨区域复制（CRR）和同区域复制（SRR）都必须启用版本控制才能工作。源桶和目标桶都需要启用版本控制。

四、跨区域复制（CRR / SRR）

S3 复制允许将对象异步地自动复制到另一个桶，分为跨区域复制（CRR）和同区域复制（SRR）。

CRR vs SRR 对比

对比维度CRR（Cross-Region Replication）SRR（Same-Region Replication）
目标桶位置不同 AWS 区域同一 AWS 区域
典型场景灾难恢复、降低读取延迟、合规数据主权日志聚合、生产与测试账号之间的同步
数据传输费用有（跨区域传输）无（同区域传输免费）
合规用途在特定地理区域保存数据副本在同一区域内多账号之间同步

复制的前提条件

  • 源桶和目标桶都必须启用版本控制
  • 源桶需要有 IAM 角色授权 S3 访问目标桶
  • 可以跨账号复制，但需要在目标桶的 Bucket Policy 中授予源账号权限

复制范围与限制

重要陷阱：启用复制规则之前已存在的对象不会被自动复制。如果需要复制现有对象，必须使用 S3 Batch Operations 配合 CopyObject 操作来补全。
  • 删除标记的复制：默认不复制删除标记，可选择启用"Replicate delete markers"
  • 指定版本 ID 的删除：永远不会被复制（防止恶意删除传播）
  • 加密对象的复制：需要配置 KMS Key 权限（目标区域的 KMS CMK），并在 IAM 角色中添加 KMS 相关权限
  • 不支持链式复制：A 桶复制到 B 桶，B 桶不会自动将内容复制到 C 桶

S3 Replication Time Control（S3 RTC）

标准复制是尽力而为的异步复制。S3 RTC 提供 99.99% 的对象在 15 分钟内完成复制的 SLA，并附带监控指标，适用于对复制时效有严格要求的场景。

场景判断：题目提到"灾难恢复、多区域可用性" → CRR；题目提到"日志聚合、多账户数据同步、同一区域" → SRR；题目提到"确保 15 分钟内复制" → S3 RTC。

五、访问控制

S3 访问控制是 SAP-C02 的核心考点，需要理解不同访问控制机制的优先级和适用场景。

访问控制机制对比

机制类型适用场景跨账号支持
Bucket Policy资源基础策略（Resource-based）为整个桶或特定前缀设置访问规则；强制加密；跨账号访问✅ 支持
IAM Policy身份基础策略（Identity-based）控制 IAM 用户/角色/服务对 S3 的访问权限需结合 Bucket Policy
ACL（访问控制列表）遗留机制AWS 已逐渐弃用，建议使用 Bucket Policy 替代有限支持
S3 Access Points访问点策略为不同应用/团队创建独立命名空间和访问策略✅ 支持

Block Public Access（阻止公共访问）

Block Public Access 是 S3 的账号级和桶级安全控制，包含四个独立设置：

  • BlockPublicAcls：阻止通过 ACL 授予的公共访问
  • IgnorePublicAcls：忽略所有公共 ACL 设置
  • BlockPublicPolicy：阻止新的公共 Bucket Policy
  • RestrictPublicBuckets：限制现有公共 Bucket Policy 的访问
最佳实践：默认情况下，新桶的四个 Block Public Access 选项全部开启。除非明确需要公开访问（如静态网站或公开文件分发），否则保持全部开启。

S3 Access Points（访问点）

当多个应用程序、用户或团队需要访问同一个 S3 桶，并且每组有不同的访问权限时，直接在单个 Bucket Policy 中管理会变得复杂。Access Points 为每个应用提供独立的访问端点和独立的权限策略，大幅简化管理。

  • 每个 Access Point 有独立的 hostname 和 ARN
  • 可以限制 Access Point 只能从特定 VPC 访问（VPC Origin）
  • Access Point Policy + Bucket Policy 共同决定最终权限

预签名 URL（Presigned URL）

允许无 AWS 账号的用户临时访问指定对象：

  • 由拥有该对象访问权限的 IAM 身份生成
  • 预签名 URL 中包含签名信息，服务端验证
  • 有效期可配置，过期后自动失效
  • 典型场景：为用户提供私有对象的临时下载链接；用户直接上传文件到 S3 而无需暴露 AWS 凭证

跨账号访问

六、加密

S3 加密分为服务端加密（SSE）和客户端加密（CSE），SAP-C02 重点考察不同 SSE 模式的区别和使用场景。

服务端加密（Server-Side Encryption，SSE）

加密类型密钥管理特点适用场景
SSE-S3 S3 自动管理（AES-256） 默认加密方式，无额外成本，无需配置。请求 Header：x-amz-server-side-encryption: AES256 通用场景，不需要自定义密钥管理
SSE-KMS AWS KMS 管理 CMK 有审计日志（CloudTrail），可控制密钥访问权限；KMS API 有调用速率限制（5500-30000 QPS）。Header：x-amz-server-side-encryption: aws:kms 合规要求，需要密钥审计，需要跨账号密钥控制
SSE-C 客户自提供密钥 AWS 不存储密钥；客户在每次请求时提供密钥；只支持 HTTPS。AWS 加密后立即丢弃密钥。 客户需要完全控制密钥，不希望密钥存入 AWS
CSE
（客户端加密）		 客户端完全自主管理 对象在离开客户端前已加密；S3 只存储密文；AWS 不参与加密过程 极高安全要求，AWS 完全无法访问数据内容

传输加密（Encryption in Transit）

S3 支持 HTTPS，可通过 Bucket Policy 强制要求所有请求使用 HTTPS：

{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::my-bucket/*"],
  "Condition": {
    "Bool": {
      "aws:SecureTransport": "false"
    }
  }
}
考试陷阱：SSE-KMS 存在 KMS API 的调用速率限制（Throttling）。如果应用有极高的 S3 读写 QPS，SSE-KMS 可能导致 KMS 限速，影响性能。解决方案：使用 S3 Bucket Keys（减少 KMS 调用次数）或申请提高 KMS 配额。

S3 Bucket Keys

启用 S3 Bucket Keys 后，S3 在桶级别生成一个短期数据密钥，用于加密对象，减少直接调用 KMS 的次数，降低成本，同时缓解 KMS 限速问题。

记忆：SSE-S3 = AWS 全管，最简单；SSE-KMS = 有审计有控制，稍贵；SSE-C = 客户管密钥，AWS 只加密不存钥；CSE = 客户全权，AWS 只存密文。

七、性能优化

多部分上传（Multipart Upload）

  • >100MB：官方建议使用
  • >5GB：必须使用多部分上传（单次 PUT 最大 5GB）
  • 单个对象最大 5TB
  • 每个分段大小：5MB 到 5GB（最后一个分段可以更小）
  • 优势：并行上传加速、断点续传、大对象上传失败只需重传失败的分段

字节范围获取（Byte-Range Fetches）

通过在 GET 请求中指定字节范围，并行下载对象的不同部分，显著提升大对象下载速度。也可以用于只下载对象的特定部分（如文件头部元数据）。

S3 Transfer Acceleration

利用 AWS CloudFront 全球边缘节点网络（Edge Locations）加速对 S3 的上传和下载：

  • 用户上传到最近的 CloudFront Edge 节点，内部走 AWS 骨干网到目标桶
  • 适合地理位置分散的用户上传数据到特定区域的桶
  • 启用后桶会获得独立的 Transfer Acceleration Endpoint：bucketname.s3-accelerate.amazonaws.com
  • 有额外费用，仅在比直连 S3 更快时才收费

请求率与前缀性能

操作类型每个前缀每秒请求上限
PUT / COPY / POST / DELETE3,500 QPS
GET / HEAD5,500 QPS

前缀分散：S3 性能限制是每个前缀的限制。通过将对象分散到不同的前缀，可以成倍提升总吞吐量。例如使用随机哈希前缀（a3b2/image.jpg）而非顺序日期前缀（2024/01/01/image.jpg），避免热点前缀成为瓶颈。

过去的经验：早期 S3 建议在键名中加入随机哈希前缀来分散请求。自 2018 年后，S3 分区算法已优化，支持任意键名达到高吞吐，但了解前缀性能限制仍是 SAP-C02 考点。

八、事件通知（Event Notifications）

S3 事件通知允许在特定对象操作发生时自动触发下游处理，是构建数据处理流水线的常见模式。

支持的目标服务

Amazon SNS

发布到 SNS Topic，可通过订阅将消息扇出到多个 SQS 队列、Lambda 或 HTTP Endpoint。

Amazon SQS

将事件消息放入队列，下游消费者按需处理，适合削峰填谷。

AWS Lambda

直接触发 Lambda 函数，无服务器处理，适合图像处理、数据转换等场景。

Amazon EventBridge

将所有 S3 事件路由到 EventBridge，支持更丰富的过滤规则和多目标路由。

支持的事件类型

  • 对象创建：PUT、POST、COPY、CompleteMultipartUpload
  • 对象删除：DELETE、DeleteMarkerCreated
  • 对象还原：从 Glacier 恢复的完成通知
  • 对象复制：复制操作状态
  • 生命周期转换：对象转换到不同存储类别

直接通知 vs EventBridge 的对比

维度S3 直接通知（SNS/SQS/Lambda）EventBridge
过滤能力只能按前缀/后缀过滤支持丰富的事件内容过滤规则
多目标路由需要借助 SNS 扇出原生支持多个目标
跨账号路由有限支持发送到其他账号的事件总线
事件归档/重放不支持支持事件归档和重放
配置复杂度简单略复杂，但功能更强
场景选择：简单触发一个 Lambda → S3 直接通知；需要多个目标、复杂过滤、事件重放 → EventBridge；需要解耦并缓冲 → S3 → SQS → Lambda。

九、静态网站托管

S3 可以作为静态网站的托管平台，提供高可用、低成本的 HTML/CSS/JS 文件服务。

基本配置

  • 在桶属性中启用"Static website hosting"
  • 指定索引文档（Index document）：如 index.html
  • 指定错误文档（Error document）：如 error.html
  • 启用后获得 Endpoint URL：bucketname.s3-website-region.amazonaws.com
  • 注意：网站端点（s3-website）和 REST API 端点（s3.amazonaws.com）是不同的 URL

OAC（Origin Access Control）是 OAI 的后继方案，用于确保 S3 桶内容只能通过 CloudFront 访问，不能直接通过 S3 URL 访问：

  • S3 桶设为私有（Block Public Access 全开）
  • Bucket Policy 只允许 CloudFront 的服务主体（service-principal: cloudfront.amazonaws.com）访问
  • OAC 比 OAI 支持更多 AWS 区域，支持 SSE-KMS 加密桶，是推荐方案

与 Route 53 结合

  • 使用 Route 53 别名记录（Alias Record）将自定义域名指向 CloudFront 分发或 S3 网站端点
  • S3 桶名必须与域名完全一致（如域名是 example.com，桶名必须是 example.com）
  • HTTPS 需要 CloudFront + ACM 证书，S3 网站端点本身只支持 HTTP
注意：S3 静态网站不支持 HTTPS。要实现 HTTPS，必须在前面加 CloudFront 并配置 ACM 证书。

十、其他重要特性

Object Lock（对象锁定，WORM）

Object Lock 实现 Write Once Read Many（WORM）合规存储，防止对象在指定时期内被删除或覆盖。必须在创建桶时启用，之后无法关闭。

Compliance Mode（合规模式）

锁定期间内，任何人（包括 root 账户）都无法删除或修改对象；也无法缩短保留期或更改为其他模式。适合强合规要求，如金融、医疗行业监管。

Governance Mode（治理模式）

普通用户无法删除或修改；但具有特殊权限（s3:BypassGovernanceRetention）的管理员可以覆盖或删除。适合内部管控，比 Compliance Mode 灵活。

Legal Hold（合法保留）：不设定到期时间，只要 Legal Hold 处于激活状态，对象就不能被删除。独立于保留期，可随时由有权限的用户开启或关闭。

Requester Pays（请求方付费）

默认情况下，桶拥有者支付所有数据下载费用。启用 Requester Pays 后，请求方（下载者）需要承担数据传输费用，桶拥有者只付存储费。典型场景：共享大规模公开数据集。

注意：匿名访问者不能访问启用了 Requester Pays 的桶，因为无法追踪费用归属。

S3 Select

在 S3 服务端对 CSV、JSON 或 Parquet 格式的对象执行 SQL 查询，只返回过滤后的数据，而不是整个对象。显著减少网络传输量和客户端处理量，降低成本并提升速度。

Intelligent-Tiering 自动分层

S3 Intelligent-Tiering 会监控访问模式，自动将对象在以下层级间移动：

  • Frequent Access（频繁访问层）：默认层，成本同 Standard
  • Infrequent Access（不频繁访问层）：30 天未访问自动移入，成本同 Standard-IA
  • Archive Instant Access（即时归档层）：90 天未访问自动移入
  • Archive Access（归档层，可选）：90-730 天未访问，需手动配置，检索需数小时
  • Deep Archive Access（深度归档层，可选）：180-730 天未访问，成本最低
场景：题目出现"访问模式不可预测"、"不确定访问频率"、"自动优化存储成本"等关键词 → Intelligent-Tiering。

S3 Inventory

定期生成桶内对象的清单报告（CSV / ORC / Parquet 格式），包含加密状态、复制状态、存储类别等元数据，支持配合 S3 Select 或 Athena 进行分析。

十一、场景题解析

以下为典型 SAP-C02 场景题，先思考再展开分析。

场景 1：金融公司要求所有交易记录上传到 S3 后，7 年内任何人（包括管理员）都不能删除或修改。如何满足这一合规要求？
答案：S3 Object Lock — Compliance Mode（合规模式）

分析："任何人包括管理员都不能删除"是 Compliance Mode 的核心特征。Governance Mode 允许有特殊权限的管理员绕过锁定，不满足"任何人都不能"的要求。配置方式：创建桶时启用 Object Lock，在上传对象时设置 Compliance Mode 保留期为 7 年。

关键词映射：合规要求 + 任何人不可删 + 固定保留期 → Object Lock Compliance Mode
场景 2：公司有 PB 级历史数据存在 S3，部分数据被频繁访问，部分很少被访问，但访问模式会随时间变化且难以预测。希望在不影响可用性的前提下自动优化存储成本。
答案：S3 Intelligent-Tiering

分析：访问模式不确定且会变化，是 Intelligent-Tiering 的最佳适用场景。它自动监控访问并在层级间迁移对象，不需要手动配置生命周期规则，也不会因预测错误导致额外检索费用。如果访问模式是已知的固定规律（如超过 90 天后永远不访问），则用生命周期策略直接转换更经济。

关键词映射：访问模式不确定/变化 + 自动优化 + 不影响可用性 → Intelligent-Tiering
场景 3：账号 A 的应用需要从账号 B 的 S3 桶读取对象。安全团队要求遵循最小权限原则。需要在两端各做什么配置？
答案：账号 B Bucket Policy + 账号 A IAM Policy（双重授权）

分析：跨账号 S3 访问必须双向授权：
1. 账号 B（资源侧）：在 S3 桶的 Bucket Policy 中，添加 Principal 为账号 A 的 IAM 角色 ARN，Effect 为 Allow，Action 为 s3:GetObject，Resource 为桶中对应对象路径。
2. 账号 A（请求侧）：给发起请求的 IAM 角色附加 IAM Policy，允许对账号 B 的 S3 桶执行 s3:GetObject。

如果账号 A 不需要在自己侧有 IAM 限制（信任所有账号 A 的主体），可以只配置 Bucket Policy，但最小权限原则要求两边都配置。

关键词映射：跨账号 S3 访问 → Bucket Policy（资源侧）+ IAM Policy（身份侧）
场景 4：安全团队要求所有发送到 S3 桶的数据必须通过加密连接传输，HTTP 明文请求必须被拒绝。如何通过桶策略实现？
答案：Bucket Policy 使用 aws:SecureTransport 条件

分析：在 Bucket Policy 中添加 Deny 语句，条件为 "aws:SecureTransport": "false"，Effect 为 Deny，Principal 为 "*"，Action 为 "s3:*"，Resource 为桶和桶中所有对象。这样所有非 HTTPS 的请求都会被拒绝，无论请求方是谁。

{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": [
    "arn:aws:s3:::my-bucket",
    "arn:aws:s3:::my-bucket/*"
  ],
  "Condition": {
    "Bool": {"aws:SecureTransport": "false"}
  }
}
关键词映射：强制 HTTPS + 拒绝 HTTP → Bucket Policy + aws:SecureTransport: false + Deny
场景 5：公司刚刚为一个已有 100 万个对象的 S3 桶启用了跨区域复制（CRR）规则，但发现目标桶中没有任何对象。如何将现有对象同步到目标桶？
答案：S3 Batch Operations + CopyObject

分析：CRR 规则只对启用后新上传的对象生效，历史存量对象不会自动复制。要复制已有对象，需要使用 S3 Batch Operations，创建一个批处理任务，对所有现有对象执行 CopyObject 操作，将其复制到目标桶。Batch Operations 支持从 S3 Inventory 报告或 Manifest 文件指定要操作的对象列表，并提供任务完成报告。

关键词映射：CRR 启用前已有对象 / 存量数据同步 → S3 Batch Operations + CopyObject

十五、快速自测

先独立选择，再点击"查看解析"。这些是概念练习题，不代表真实考试题。

1. 公司需要将日志数据在 S3 中保存，访问频率极低（每年 1-2 次），但一旦需要访问，必须在 1 分钟内完成检索。应选择哪种存储类别？
正确答案：B。Glacier Instant Retrieval 提供毫秒级检索，适合极少访问但需要快速取回的数据，最短存储期 90 天。Glacier Flexible Retrieval 检索需要数分钟到数小时，不满足"1 分钟内"的要求。
2. 安全审计发现某 S3 桶中的对象可以被 HTTP 明文访问。以下哪个操作可以正确地强制所有访问使用 HTTPS？
正确答案：B。Bucket Policy 配合 aws:SecureTransport: false 条件可以拒绝所有非 HTTPS 请求。SSE-S3 是静态加密（at rest），不影响传输协议。Block Public Access 控制公共访问，不控制传输协议。IAM Policy 虽然也可以添加条件，但无法覆盖匿名请求或其他账号。
3. 公司在账号 A 和账号 B 之间配置了 S3 CRR，已成功启用规则。但运营团队反映，账号 A 桶中启用复制规则之前上传的 50 万个对象，在账号 B 的目标桶中不存在。应如何解决？
正确答案：C。CRR 规则仅对配置后新上传的对象生效，对历史存量对象不会自动复制，也不会"等待后自动同步"。必须使用 S3 Batch Operations 配合 CopyObject 操作来补全存量数据的复制。
4. 以下哪种 S3 加密方式可以通过 AWS CloudTrail 查看每次密钥使用记录，并且可以为特定 IAM 角色撤销解密权限？
正确答案：B。SSE-KMS 使用 KMS 托管的 CMK，每次加解密操作都记录在 CloudTrail 中，可以通过修改 KMS Key Policy 撤销特定主体的密钥使用权限。SSE-S3 的密钥由 S3 完全管理，无法控制密钥权限；SSE-C 密钥由客户管理但 AWS 不存储，没有审计。
5. 合规要求规定某类对象在 S3 中必须保留至少 3 年，且包括 AWS root 账号在内的任何人都不能在保留期内删除这些对象。以下哪个配置满足要求？
正确答案：B。Compliance Mode 保证保留期内任何人（包括 root 账户）都无法删除或修改对象，也不能缩短保留期，是唯一能满足"任何人都不能删除"强合规要求的选项。Governance Mode 允许有特殊权限的管理员绕过限制；MFA Delete 只增加额外验证步骤，并非完全阻止删除；生命周期策略不能防止主动删除。
