一、定位与核心能力

AWS Backup 是集中管理各种 AWS 资源备份和恢复的服务。它的优势不只是“可以备份”，而是能够按服务、账户、区域统一定义保留策略、恢复点、跨区域复制和合规锁定。

能力关键含义适用场景
统一备份计划按标签或资源类型批量绑定保留策略。多服务统一治理，减少漏备份。
跨区域复制备份副本可复制到其他区域，提升灾难恢复能力。RPO / RTO 需求高，灾备区域存在。
跨账号管理通过组织级策略或管理账户集中控制备份。多账号中台架构或企业审计场景。
Vault Lock受控地锁定保留期和删除动作。合规、审计、不可篡改需求。

二、备份计划

  • Backup plan：定义备份频率、保留期限和生命周期，例如每天备份、保留 30 天、按周/月归档。
  • 资源选择：可按资源类型、标签、账号或组织单元绑定，并持续覆盖新资源。
  • 资源标签：是最常见的批量管理入口；考试中经常考“添加标签后，备份计划生效”的题目。
  • 生命周期：可决定备份的分层保留，例如当前 30 天标准存储，之后转到低成本存储或更久保留。
  • 恢复点：恢复时基于备份点；实际恢复目标和窗口要和 RPO / RTO 要求匹配。
记忆重点：备份计划不是“单个实例点备份”，而是“企业级策略”，尤其在多资源、多账号、多区域中极其常见。

三、Vault、生命周期与 Vault Lock

能力作用答题提示
Backup Vault存放恢复点的容器，可绑定 KMS、日志和访问控制。Vault 本身就是备份的安全边界。
Lifecycle定义从当前备份到低成本存储的转换策略。总容量增长时，生命周期能显著降低成本。
Vault Lock锁定删除与保留窗口，适合不可篡改要求。题目一旦出现“合规/审计/不可删除”，第一时间想到 Vault Lock。
加密备份可使用 AWS 管理密钥或客户管理密钥（CMK）。密钥策略要和 KMS、账号权限一起看。
合规常考点：Vault Lock 可确保备份不被提前删除，适合金融、医疗、审计场景；但它也要求先规划清楚保留期和删除权限边界，否则后续难以调整。

四、跨区跨账号治理

  • 跨区域复制：用于灾难恢复和多区域一致性；常见需求是“备份在主区域以外的备用区域保留”。
  • 跨账号备份：管理账号可集中控制成员账号的恢复点、保留规则和审计权限。
  • 组织级策略：允许企业统一要求所有账户启用备份计划、KMS 密钥策略或 Vault 几个安全要求。
  • 审计与可见性：通过 AWS Backup 控制台、CloudTrail、Config 等辅助验证备份状态和合规策略是否真正生效。
  • 标签与策略：企业中最常见的做法是“按应用或环境标签统一应用备份规则”，避免手工逐资源配置。

五、恢复、演练与 RTO/RPO

要素设计重点注意事项
恢复点恢复点越近，RPO 越小，业务恢复风险越低。频率和保留策略不仅影响成本，也影响恢复粒度。
恢复目标要符合 RTO：从故障到恢复操作时间的业务要求。恢复演练必须有明确的切换步骤，不可只在意备份完成。
资源类型不同服务有不同的恢复方式：RDS、EBS、EFS、EC2、DynamoDB 等各有差异。不要想当然地把所有服务都按“整实例恢复”理解。
演练验证恢复过程、恢复点是否可信、KMS 配置与权限是否正常。数据恢复最容易出问题的是“权限 + 密钥 + 依赖网络”三类。
简短判断：业务要求“低 RPO/低 RTO”时，单纯保留备份不够，还要看复制、恢复窗口和演练过程是否存在缺口。

六、场景题解析

场景一：多账号环境如何统一管理备份

企业在多个账号中部署了 RDS、EFS 和 EC2，要求备份策略统一，并且审计部门要求查看备份状态。

正确方向：使用 AWS Backup 的跨账号管理/组织级治理，将备份计划统一应用到资源，并结合 Vault 和 KMS 策略提升审计能力。

分析思路：题目强调“多个账号 + 统一策略”，这正是 AWS Backup 管理中心的优势。

排除：单机配置备份计划无法覆盖批量多账号治理；手工逐资源设置明显不符合企业化要求。

场景二：要求“无法删除、不能提前失效”

监管要求备份保留时间不能被误删，恢复点需保留到合规窗口结束。

正确方向：启用 Vault Lock，并结合保留期限和删除限制。

分析思路：“不能删除、不能提前失效”是 Vault Lock 的最典型应用场景。

排除：普通备份计划的保留规则只能控制标准生命周期，不能像 Vault Lock 一样提供强约束。

场景三：公司要求 RPO 1 天、RTO 10 分钟

灾备环境需要做到在灾难发生后尽快恢复，并且副本保存在其他区域。

正确方向：定义恢复点 + 跨区域复制 + 演练切换流程。AWS Backup 可支持跨区域复制并保证恢复点可用。

分析思路：题目中最关键的非功能要求是“恢复点”和“跨区域副本”，而不是普通保留周期。

排除：只保留本地备份或没有演练流程，无法满足严格 RTO / RPO 要求。

七、关键词速查

  • Backup plan = 统一备份策略，控制频率和保留期限。
  • Vault = 备份容器，负责保留点与访问控制。
  • Vault Lock = 强制锁定保留期和删除动作，适合合规要求。
  • Cross-region copy = 复制到其他 AWS 区域，支持灾备。
  • Cross-account = 在多账号中统一治理备份。
  • Lifecycle = 会随着时间推移转换到更低成本存储层。

八、考前速记卡

  • 统一入口：AWS Backup 管理 EC2、EFS、RDS、DynamoDB 等备份
  • 标签驱动：按标签为资源分配备份计划，适合企业批量治理
  • 跨区域副本：提升灾难恢复能力，利于 RPO/RTO 目标
  • 跨账号管理：管理账号统一控制成员账号信息
  • Vault Lock：强制锁定保留期和删除动作，合规审计常见
  • 生命周期策略：从标准存储逐步转换到低成本长期保留
  • 恢复测试：备份不要只看创建是否成功，必须验证恢复有效
  • 成本与合规平衡：备份策略必须同时满足恢复要求与审计要求

九、快速自测

问题 1：如果要求“不能删除且保留期不能被提前修改”，最合适的能力是？

正确答案：A。Vault Lock 能对备份恢复点设置更强的保留和删除约束。

问题 2：以下哪项最符合企业统一备份治理？

正确答案：B。企业化备份治理的关键是“统一策略 + 批量标签 + 多账号管理”。
