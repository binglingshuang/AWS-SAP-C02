AWS Systems Manager
混合环境运维与参数管理

Systems Manager 将 AWS 与混合环境中的受管节点纳入统一运维。题目常把它拆成远程访问、批量命令、补丁编排、参数/密钥存储与自动化工作流；先确认节点是否受管、权限是否到位，再选择对应能力。

一、Systems Manager 能力地图

Systems Manager 是运维控制面，不是单一的远程登录工具。核心流程是让节点成为 managed node，再由 IAM 身份和文档（SSM Documents）限定可执行的操作。

需求能力常见考点
交互式运维访问Session Manager无需开放 SSH/RDP 入站端口；会话可记录到 S3 / CloudWatch Logs。
跨节点执行命令Run Command按标签/资源组选择节点，异步执行、查看状态与输出。
补丁合规Patch ManagerPatch baseline、patch group、扫描/安装与维护窗口。
集中配置值Parameter Store层级参数、版本、SecureString、IAM 与 KMS 权限。
自动化运维流程AutomationRunbook 将多步骤操作和 AWS API 串成可重复流程。
服务能否管理节点取决于 SSM Agent、节点身份凭证、网络连通性和目标操作权限；安装 Agent 本身不等于已具备访问权限。

二、受管节点、Agent 与权限边界

  • 节点：EC2 实例、混合云服务器和边缘节点可注册为 managed node。SSM Agent 负责与 Systems Manager 服务通信；受支持的多数 Amazon Linux / Windows AMI 已预装，但仍需确认版本和运行状态。
  • 身份：EC2 通常使用实例配置文件中的 SSM 权限；也可配置组织级默认主机管理。混合节点需按 Hybrid Activations 流程注册。人类操作者通过 IAM / Identity Center 获得 API 权限。
  • 网络：节点需能向 SSM 等服务端点发起出站 HTTPS 通信。私有子网可使用 NAT，或为所需服务配置 Interface VPC Endpoints；不需要为 Session Manager 开放公网 SSH 入站。
  • 分层授权：操作者权限控制谁能启动命令/会话；节点角色控制 Agent 能访问哪些服务；文档与资源策略进一步限制具体目标。记录会话还需对应的 S3、CloudWatch Logs 或 KMS 权限。
排障顺序：节点是否显示为 Online → Agent 状态/版本 → IAM 凭证和策略 → DNS、路由、端点安全组与出站网络 → 文档执行权限。

三、Session Manager：免入站端口的交互式会话

Session Manager 通过 SSM Agent 建立受控会话，避免维护堡垒机、SSH 私钥和开放管理端口。它支持 Linux shell、Windows PowerShell，以及对部分场景的端口转发；端口转发不是完整的 SSH 会话记录替代品。

  • 前置条件：目标为在线受管节点，Agent 能连接服务；调用者有启动会话权限，节点角色有必要的 Systems Manager 通信权限。
  • 审计：可将会话日志送到 CloudWatch Logs 或 S3，并可使用 KMS 加密。需事先配置目标日志组/存储桶、加密密钥权限和相应设置。
  • 安全边界：限制可连接的实例、文档、会话类型和端口；采用最小权限并审计启动者。不要把“无需入站端口”误解为“无需 IAM / 网络配置”。
题目说“私有子网 EC2 不可开放 22/3389，希望集中授权、留存会话审计”时，优先考虑 Session Manager，并补齐 Agent、IAM、端点/出站和日志配置。

四、Patch Manager：补丁基线与维护窗口

Patch Manager 可对受管节点进行补丁合规扫描和安装。补丁基线定义批准/拒绝规则及自动批准延迟；标签可将节点映射到 patch group（补丁组），维护窗口安排扫描或安装任务。补丁不会仅因启用服务就自动在任意时间安装。

组件作用易错点
Patch baseline定义操作系统补丁的批准规则、分类/严重性和延迟。默认基线不一定满足组织的审批与例外要求。
Patch group通过指定标签值，将节点关联到适用基线。标签键需按 Patch Manager 约定配置；确认节点实际命中预期组。
Maintenance Window在维护时段执行注册的任务，支持目标、任务和调度。检查窗口持续时间、截止行为、并发/错误阈值及权限。
Compliance查看扫描/安装后的补丁合规状态，并可配合报表治理。扫描、批准和安装是不同阶段；补丁基线不负责应用发布回滚。

生产环境通常先扫描并分组，再在维护窗口安装；用分批目标、维护时段、重启策略、应用健康检查和回滚方案控制变更风险。

五、Parameter Store：配置参数与 SecureString

  • 层级路径：使用如 /prod/payments/endpoint 组织环境/应用参数；支持版本、描述和按路径读取。不要将参数路径结构误当成 IAM 隔离的唯一手段。
  • 类型：String、StringList 保存一般配置；SecureString 使用 AWS KMS 加密，读取解密值需要相应的 Parameter Store 与 KMS 权限。
  • 标准/高级参数：高级参数支持更大的值容量、参数策略等增强功能，但有不同配额/计费；具体配额随服务文档更新。参数策略可用于到期、过期通知或变更通知等治理。
  • 选型边界：Parameter Store 适合配置和简单密文参数；Secrets Manager 针对机密生命周期、自动轮换、数据库凭据集成等能力更完整。SecureString 不会自动轮换凭据。
SecureString 加密不代表有权解密：调用者的 IAM 权限、KMS key policy/grant、密钥状态和跨账号授权必须共同允许。

六、Run Command、Automation 与其他运维能力

工具适合任务与其他能力的区别
Run Command对一个或多个节点远程执行脚本/命令。适合批量执行，不提供交互式 shell；可按标签选择目标。
Automation通过 Automation Runbook 执行多步骤、可追踪的 AWS 运维流程。可作用于 AWS 资源并编排 Systems Manager/其他服务动作；支持审批与执行控制。
State Manager按关联和计划保持节点达到声明状态，如安装代理或应用配置。持续维护期望配置；不同于一次性 Run Command。
Inventory收集节点软件、配置等清单信息。用于资产可见性，不等同补丁安装或漏洞扫描。

常见组合：Config 检出不合规 → EventBridge / Config remediation 调用 Automation Runbook → Run Command 或 Automation 修复 → 再由 Config 评估验证。

八、场景题解析（6 题）

1. 私有子网中的 Linux 实例不得开放 22 端口，管理员仍需交互式排障并留存会话记录。

采用 Session Manager。确保 Agent 在线、节点出站到 SSM（必要时用 VPC endpoints）、操作者/实例角色授权，并配置 CloudWatch Logs 或 S3 会话记录。

2. 数百台 EC2 需要每月在批准时段安装经过测试的安全补丁。

使用 Patch Manager 基线定义批准规则，按标签/patch group 分批目标，通过 Maintenance Window 安排扫描和安装，监控合规状态并验证应用。

3. 开发者需要读取应用配置，但不得解密生产数据库密码。

按路径和资源 ARN 授权只读非敏感参数；生产凭据采用独立权限边界。SecureString 还需 KMS 权限，不能只依赖路径命名来隔离。

4. 一组受管节点需要立即执行同一诊断脚本，并返回每台机器的执行结果。

选择 Run Command，按标签定位目标，限制并发与错误比例，设定超时并检查每个 invocation 的状态和输出。

5. Config 发现安全组违规后要自动执行多步修复，并保留可审计执行记录。

将 Config remediation 指向 Systems Manager Automation Runbook，设置执行角色与必要审批/参数，并验证幂等性、失败处置及修复后的 Config 评估。

6. 凭据需要定期自动轮换，并在轮换时更新数据库凭据。

优先 Secrets Manager 及其轮换集成；Parameter Store SecureString 提供加密存储，但本身不负责完整的秘密轮换生命周期。

十、快速自测

1. Session Manager 连接失败，实例显示 Offline，首先应核对什么？

Agent 是否运行、节点 IAM 凭证是否有效，以及实例到 SSM 服务端点的出站网络/DNS；操作者有权限也无法弥补节点不在线。

2. 需要周期性维持服务器具备指定软件和配置，而非只执行一次命令，应选什么？

State Manager Association；Run Command 更适合一次性命令执行。

3. Parameter Store SecureString 读取时报 KMS AccessDenied，应该检查什么？

调用者 IAM、KMS key policy/grant 以及跨账号授权和密钥状态，确保允许解密；不是重新创建普通 String。
