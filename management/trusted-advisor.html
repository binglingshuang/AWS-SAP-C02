AWS Trusted Advisor
最佳实践检查与建议

Trusted Advisor 将部分 AWS 最佳实践检查汇总为可执行建议，帮助识别成本、性能、安全、容错和服务配额/限制方面的机会。它给出检查结果和建议，不是资源配置审计数据库，也不会自动替你修复所有问题。

一、Trusted Advisor 能力地图

服务检查账号中的资源/配置并提供建议。适合快速发现与 AWS 最佳实践相关的问题；检查是否可见、能否刷新、是否支持 API/组织视图，取决于当前支持计划、功能版本、权限和区域。

组件/能力用途题目陷阱
Checks针对 AWS 资源和使用状态执行最佳实践检查。检查覆盖面与刷新方式并非所有计划都完全相同。
Recommendations呈现建议、风险/收益线索和资源列表。通常需客户评估和执行；不是自动修复引擎。
Organization view在符合条件的 Organizations 环境中集中查看多个账号结果。需满足支持计划、组织配置、权限及服务启用条件。
Trusted Advisor Priority对符合条件客户提供优先级建议管理体验。并非所有账号或支持计划默认具备。

二、五类 Trusted Advisor 检查

类别常见关注点架构师的下一步
成本优化 Cost Optimization闲置/低利用率资源、潜在节省机会。核实工作负载周期性、性能基线、承诺折扣和停机风险。
性能 Performance资源配置、吞吐/利用率和服务使用方式。以应用 SLO、压测和监控数据验证建议。
安全 Security可能增加暴露或安全风险的资源配置。结合 Security Hub、GuardDuty、Config 和安全基线治理。
容错 Fault Tolerance单点故障、弹性和恢复能力相关建议。对照 RTO/RPO、跨 AZ/区域架构与恢复演练判断。
服务配额/限制 Service Limits配额使用接近服务限制等风险。使用 Service Quotas 查看/申请配额，并在扩容前预留时间。

检查结果是优先级线索，不等于架构设计结论。建议在实施前确认资源实际用途、依赖关系、峰值/批处理周期和业务窗口。

三、支持计划与检查访问

Trusted Advisor 能力与 AWS Support 计划有关联，但不同计划下可见检查、检查刷新频率、通知/API、组织级访问和高级支持体验可能不同，且 AWS 会调整 Support 计划及其权益。

核对项实施前要确认
计划权益当前计划提供哪些检查、刷新/通知能力与技术支持；不要只沿用旧版“Basic vs Business”记忆。
账号资格组织管理账号/成员账号是否满足对应功能的计划和配置要求。
权限/APIIAM 是否允许读取检查结果、执行 refresh 或访问组织级视图；相关 API 权限/配额是否可用。
检查新鲜度各检查上次刷新时间、自动刷新规则和手动刷新限制；结果可能不是实时数据。
高级体验Trusted Advisor Priority 或组织视图等功能的计划资格和区域/服务配置。
考试若以旧版题干明确指定 Business/Enterprise Support，应按该题设的能力条件判断；现实部署需查最新 AWS Support plan comparison 和 Trusted Advisor 文档，勿把旧计划权益硬编码到新环境。

四、组织视图、刷新与运营闭环

  1. 启用组织访问：确认 Organizations 结构、管理账号/委派管理员和 Trusted Advisor 组织视图先决条件；按需授予成员账号权限。
  2. 收集检查：查看检查类别、受影响资源和结果更新时间；对支持的检查按计划刷新，注意刷新配额与延迟。
  3. 排定责任：将建议分配给成本、平台、安全或应用团队，并记录预期节省、风险、负责人和截止日期。
  4. 验证与处理：在变更管理流程中评估影响；执行配置变更后刷新或等待检查更新，再用监控/Config 等验证。
  5. 持续治理：结合 EventBridge/通知/工单（若当前集成支持）形成闭环；不要将检查结果直接变成未经审查的生产自动化动作。

五、Trusted Advisor 与邻近服务的边界

服务擅长解决与 Trusted Advisor 的区别
Trusted Advisor预建最佳实践检查与建议。检查覆盖范围由 AWS 定义，建议需评估；不是任意自定义规则引擎。
AWS Config资源配置历史、规则评估、合规时间线和聚合。可针对组织要求构建托管/自定义规则；强调资源状态记录与合规。
Service Quotas查看服务配额、利用率和申请增加配额。是配额管理工作流；Trusted Advisor 限制检查是风险提示。
Compute Optimizer基于利用率数据提供计算资源规格建议。针对特定资源优化，可作为深度评估补充而非替代整个 TA。
Security Hub汇总安全发现、标准控制及安全态势。专注安全发现/控制治理，不覆盖 TA 五大类建议。
如果问题要求“持续按自定义合规规则记录并评估资源配置”，优先 AWS Config；如果要求“查看 AWS 汇总的最佳实践建议”，优先 Trusted Advisor。

六、场景题解析（6 题）

1. CFO 想快速找出闲置资源和潜在节省机会。

从 Trusted Advisor 成本优化检查开始，结合 Cost Explorer/Compute Optimizer 验证用量与影响，再由负责人实施；不要未核对业务周期就自动删除资源。

2. 一个组织需要从管理账号查看多个成员账号的 Trusted Advisor 检查结果。

评估组织视图功能，先核对当前支持计划资格、组织/委派管理员配置、成员账号权限和检查数据刷新状态。

3. 架构团队要求自定义规则持续检测所有 S3 bucket 必须加密，并查看配置历史。

使用 AWS Config 托管/自定义规则和配置记录；Trusted Advisor 的预建检查不能替代企业特定的持续合规规则与历史。

4. Trusted Advisor 显示配额接近上限，项目将在两周后扩容。

查看 Service Quotas 的当前配额/使用量并尽早提交增加申请，同时设计扩容前监控和失败保护；不要仅等 Trusted Advisor 下次刷新。

5. 某一检查结果似乎与刚完成的资源变更不一致。

先检查该检查的最后刷新时间和刷新能力，必要时执行允许的 refresh；确认延迟/支持范围，再用 CloudWatch、Config 或资源控制面验证真实状态。

6. 旧题目说需要 Business/Enterprise Support 才能访问完整 Trusted Advisor checks，现行环境计划权益不同。

考试按题设版本的支持计划前提作答；现实部署按当前 AWS Support plan comparison 核验检查/API 权益，避免用过时计划名称做配置假设。

八、快速自测

1. Trusted Advisor 是否可替代 AWS Config 做企业自定义合规历史记录？

不能。Trusted Advisor 提供 AWS 预建检查；Config 记录资源配置并按自定义/托管规则评估。

2. 配额检查显示存在风险，申请提升配额应在哪里操作？

通过 Service Quotas 检查和申请对应服务配额；Trusted Advisor 主要提供检查提示。

3. 为何不能凭旧文档断言所有账号都能查看相同 Trusted Advisor 检查？

检查可见性、刷新、API、组织视图和高级体验会受当前支持计划、资格、权限及服务版本影响。
