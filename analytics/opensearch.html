Amazon OpenSearch Service
托管搜索与日志分析 — SAP-C02

OpenSearch 将索引、搜索和分析能力作为托管服务运行。架构题常考日志摄取路径、域的网络/身份/文档权限边界、分片容量，以及跨集群搜索的适用范围。

一、服务模型与场景

OpenSearch Service 托管 OpenSearch 集群（domain），支持全文检索、日志探索与分析；OpenSearch Serverless 是另一种容量/运维模型，需根据延迟、网络、索引和访问能力分别评估。

日志典型链路：CloudWatch Logs subscription / Kinesis / Data Firehose → OpenSearch domain → Dashboards。对长期低成本原始日志保留，可将 S3 作为归档和数据湖，再按需检索或回灌索引。

搜索索引是面向查询的派生数据。应规划保留期、重建流程和源数据备份，不能把 OpenSearch 集群当作唯一长期归档。

二、日志摄取、分片与容量

  • 选择 CloudWatch Logs subscription 进行日志实时路由，或用 Data Firehose 托管缓冲/投递；确认格式、重试、失败备份、IAM 和目标映射。
  • 索引由 shards 分布并可设 replicas；分片过少可能限制并行/容量，过多会增加协调和管理开销。按索引大小、查询模式和节点容量压测。
  • 使用索引模板、生命周期策略和合理时间分桶控制索引数量；热点写入、映射膨胀、字段过多会拖累集群。
  • 生产域评估多可用区部署、节点角色、容量告警和快照；写入/查询负载应分别监控，扩容不等于修复低效查询。
  • 数据摄取失败时检查 bulk 请求大小、字段映射冲突、目标域资源策略和服务端限流。

三、网络与访问控制

层检查重点
网络VPC domain 的子网、路由、安全组、DNS；公网 domain 则限制入口来源。
IAM / domain policy谁能调用 OpenSearch API；跨账号主体、SigV4 和资源策略是否匹配。
Fine-grained access control认证后对索引、文档或字段的细粒度权限及角色映射。
数据和快照日志服务/Firehose 写入角色、S3 快照桶策略、KMS 密钥权限。

授权常是多层交集：网络可达、域级策略允许、身份认证成功、FGAC 角色映射通过。不要用开放的匿名 domain policy 代替应用身份认证。

四、跨集群搜索、快照与可观测性

  • Cross-cluster search 在已配置的受信任远端连接上跨域查询；它不是自动复制，也不保证两个集群的索引或授权自动一致。
  • 跨区域/跨账号连接还需验证兼容性、网络连通、远端授权、DNS 和延迟；若要复制索引，应选择明确的跨集群复制/摄取方案。
  • 快照可用于备份与恢复；手动快照通常需要 S3 bucket、IAM 角色和相应权限，恢复演练要验证索引、模板、插件及版本兼容性。
  • 监控 CPU、JVM memory pressure、存储、节点/分片、拒绝请求、写入延迟和慢查询；CloudWatch 告警应关联容量与索引生命周期动作。

五、场景题解析

场景一：需要实时搜索应用和访问日志

日志目前在 CloudWatch Logs，团队要全文检索和仪表板。

方向：用 subscription 或 Firehose 将日志送入 OpenSearch，完善失败重试与 S3 备份。
日志路由服务负责摄取，OpenSearch 提供索引和搜索。
不要让应用同步逐条写入搜索域而无缓冲/退避设计。

场景二：VPC 内 domain 无法访问

客户端权限看似正确，但连接超时。

方向：先检查 VPC 子网、路由、安全组、DNS 和客户端网络，再检查 domain policy 与认证。
拒绝与超时可能分别来自授权层和网络层。
只修改 IAM policy 不会修复网络不可达。

场景三：用户只能查看本租户的日志索引

多个租户共享同一个 OpenSearch domain。

方向：启用 FGAC，配置身份到角色映射并按索引/文档权限隔离。
域级访问权不足以表达租户内细粒度边界。
不要依赖前端过滤来实现数据隔离。

场景四：分析人员想同时搜索两个 Region 的域

无需把所有数据集中复制。

方向：配置 Cross-cluster search 远端连接、网络和远端授权。
跨集群搜索允许查询联邦式检索，不是数据复制。
不能把只读搜索能力误当成跨区灾备。

场景五：集群因大量小时间索引而持续承压

日志保留年限长且索引/分片持续增加。

方向：调整索引时间粒度、分片规划与生命周期策略，将长期原始数据归档到 S3。
索引数和分片数都会带来集群管理开销。
简单增加节点不能替代索引治理。

场景六：误操作删除索引后需要恢复

团队已有周期备份但未验证还原。

方向：使用配置好的快照恢复，并定期演练及检查 S3/IAM/KMS 权限。
快照是恢复路径，须验证兼容性和实际 RPO/RTO。
高可用副本不能代替独立备份，误删可能同步影响副本。

七、考前速记卡

已掌握 0 / 18

  • Domain 是托管 OpenSearch 集群边界。
  • Serverless 是不同容量运维模型。
  • CloudWatch Logs 可经 subscription 摄取。
  • Firehose 可托管缓冲并投递日志。
  • 索引由 primary shards 和 replicas 组成。
  • 分片过多增加协调与管理负担。
  • 生命周期策略控制索引滚动/保留。
  • S3 适合长期原始日志归档。
  • VPC 路由/安全组/DNS 决定网络可达性。
  • Domain policy 控制域 API 请求边界。
  • FGAC 处理认证后的索引级权限。
  • 网络和身份授权必须都满足。
  • Cross-cluster search 用于远端查询。
  • 跨集群搜索不等同于索引复制。
  • 快照恢复需 S3/IAM/KMS 配置。
  • 副本提供可用性，不是独立备份。
  • 监控 JVM、存储、分片和拒绝请求。
  • 重建流程和保留期应与搜索域分开规划。

八、快速自测

1. Cross-cluster search 会自动复制远端数据吗？

不会；它提供跨集群查询能力。

2. VPC domain 请求超时，优先检查哪些配置？

网络连通、子网/路由、安全组和 DNS，再排查授权。

3. FGAC 主要解决什么问题？

对已认证主体实施索引/文档等细粒度访问控制。
