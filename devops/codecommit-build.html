一、服务分工与 CI/CD 链路

服务职责容易混淆的边界
CodeCommit托管私有 Git 仓库、分支与提交。源码版本管理，不执行构建或发布。
CodeBuild按 buildspec 在托管构建环境中编译、测试并生成制品。构建服务，不是完整的 stage 编排器。
CodeArtifact托管 Maven、npm、PyPI 等格式的软件包仓库及上游代理。依赖/软件包管理，不是应用部署制品流水线。

典型链路：源码仓库 → CodePipeline/触发器 → CodeBuild → S3/后续部署 action；构建时可从 CodeArtifact 拉取依赖并发布内部包。

二、CodeBuild：buildspec、环境与缓存

  • buildspec.yml 常定义 install、pre_build、build、post_build phases，以及 artifacts、cache、reports 等配置；可通过项目配置指定替代 buildspec 路径。
  • 构建环境以项目角色访问源码、日志、S3 制品、KMS 和 CodeArtifact；不要把凭证硬编码在仓库或 buildspec 中。
  • 缓存可选择 S3 缓存或环境本地缓存能力；缓存适合可重建依赖，需防止不可信构建共享敏感内容，并考虑缓存键失效。
  • 私有子网中的构建需通过 NAT 或 VPC endpoints 访问依赖、日志、制品等服务；检查 DNS、路由、安全组和端点策略。
  • 设置超时、并发配额、测试报告、CloudWatch Logs、失败通知和重试策略；缓存不是构建正确性的来源。
  • 敏感配置使用 Secrets Manager/Parameter Store 并通过环境引用注入，控制日志输出避免泄露。
构建边界：CodeBuild 的 service role 是构建容器代表项目访问 AWS 资源的主要身份；它不等于运行后应用的实例角色。

三、CodeArtifact：仓库、上游与令牌

  • Domain 是组织级边界，repository 存放特定包格式的软件包；通过仓库策略与 IAM 授权消费者和发布者。
  • 上游仓库支持代理/缓存公共源或内部仓库依赖；多个上游按仓库配置顺序解析，架构应明确来源与包投毒防护。
  • CI 客户端通常先取得 CodeArtifact authorization token，再配置 npm/Maven/PyPI 等客户端；令牌有时效，构建需处理刷新和最小权限。
  • 跨账号共享仓库时，检查 domain 与 repository resource policy、调用者 IAM 权限，以及 KMS 加密授权。
  • 依赖锁定版本、校验来源、限制发布权限并留存审计；代理上游不代表对公共包内容自动建立信任。

四、CodeCommit、访问与供应链安全

  • CodeCommit 是托管 Git 服务；通过 IAM 身份和仓库策略控制 clone、push、分支等操作，按团队需要配置事件触发流水线。
  • 代码提交触发 CodePipeline/CodeBuild 后，构建输出应注明 commit SHA、依赖版本和制品摘要，便于追溯。
  • 分支保护、代码审查、秘密扫描、依赖扫描和最小权限应作为供应链控制；不要将部署凭证写入源码。
  • 私有仓库/包仓库的网络可达性、加密密钥和跨账号授权需分别排查，不能用公共开放策略绕过连接问题。
  • 确认 AWS 区域、账户和组织对目标 CodeCommit 能力的当前可用性及配额；服务可用性和账户限制以 AWS 官方最新文档为准。

五、场景题解析

场景一：每次提交都要编译、测试并输出部署包

团队希望托管构建环境且不管理构建服务器。

方向：使用 CodeBuild 和 buildspec，必要时由 CodePipeline 触发并传递 artifacts。
CodeBuild 托管执行构建命令并生成输出制品。
CodeCommit 仓库本身不会编译或运行测试。

场景二：Maven 依赖下载慢且团队需共享私有包

希望缓存公共依赖并管理内部制品。

方向：建立 CodeArtifact domain/repository，配置适用的上游仓库和客户端认证。
仓库可承载私有包并按配置代理上游依赖。
不要把构建缓存误当作可治理的软件包仓库。

场景三：构建每次都重新下载大型依赖

依赖内容稳定，构建时间过长。

方向：为 CodeBuild 配置 S3/本地缓存并设置依赖锁文件对应的缓存键。
缓存可复用可重建依赖，降低重复下载时间。
缓存命中不能替代版本锁定和构建验证。

场景四：私有子网中的构建无法下载依赖

CodeBuild 能启动，但访问外部仓库超时。

方向：检查 NAT 或所需 VPC endpoints，以及路由、DNS、端点策略和安全组。
私有子网默认没有互联网出口。
单纯增加 IAM 权限无法修复网络不可达。

场景五：构建需要下载加密的 S3 输入并发布包

运行日志显示 AccessDenied。

方向：检查 CodeBuild 项目角色的 S3/KMS 权限以及 CodeArtifact 仓库授权。
构建身份必须能读取输入、解密并向目标仓库发布。
CodePipeline 服务角色权限不自动传递给 CodeBuild 项目角色。

场景六：担心构建凭证被提交到 Git

多个团队共用仓库和流水线。

方向：从源码移除密钥，轮换已暴露凭证，用 Secrets Manager/Parameter Store 按需注入并限制角色权限。
密钥轮换、秘密扫描与短期凭证能降低泄露影响。
删除 Git 当前版本中的密钥并不会从历史提交中自动清除。

六、关键词速查

需求匹配服务/能力
托管 Git 源码CodeCommit
构建、测试、生成制品CodeBuild + buildspec
依赖仓库与公共上游代理CodeArtifact
缩短重复构建时间CodeBuild cache + 正确缓存键
构建访问加密资源失败检查项目 role、资源策略、KMS key policy

七、考前速记卡

已掌握 0 / 18

  • CodeCommit 是托管 Git 源码仓库。
  • CodeBuild 托管执行编译和测试。
  • CodeArtifact 托管软件包依赖与制品。
  • CodePipeline 编排构建和部署 action。
  • buildspec 描述构建阶段与制品设置。
  • 构建项目角色控制构建容器的 AWS 访问。
  • 构建角色与流水线服务角色权限不同。
  • artifacts 用于输出可传递的构建结果。
  • S3 和本地缓存可减少重复依赖下载。
  • 缓存键应随依赖锁文件变化而失效。
  • 私有子网构建要准备 NAT 或 VPC endpoints。
  • Secrets Manager 可避免将凭证写入源码。
  • CodeArtifact domain 提供组织级仓库边界。
  • CodeArtifact 可配置上游仓库。
  • CodeArtifact 客户端认证令牌有有效期。
  • 跨账号访问需匹配 IAM 与资源策略。
  • KMS key policy 影响加密制品访问。
  • 锁定依赖并记录 commit 与制品摘要以便追溯。

八、快速自测

1. 运行 buildspec 并执行测试的服务是什么？

CodeBuild。

2. 需要缓存和共享 Maven/npm/PyPI 依赖应优先考虑什么？

CodeArtifact 仓库，可按需配置上游；CodeBuild 缓存则用于加速重复构建。

3. 私有子网中的 CodeBuild 无法联网时，应先检查什么？

NAT/VPC endpoints、路由、DNS、安全组和端点策略，而不只是 IAM。
