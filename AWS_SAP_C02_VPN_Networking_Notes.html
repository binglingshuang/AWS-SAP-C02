2. AWS VPN 服务考点

2.1 Client VPN

Client VPN 是一种托管式客户端 VPN 服务，允许用户通过 VPN 客户端安全地访问 AWS VPC 和其他授权网络。

使用场景

员工远程办公、开发人员访问私有资源。

连接对象

个人计算机、客户端设备。

认证方式

支持基于证书的认证、Active Directory 和 SAML 联合认证等。

网络控制

Routes、Authorization Rules、Security Groups。

2.2 Client VPN 重要配置

配置项目作用考试记忆
Client VPN Endpoint创建客户端 VPN 接入点集中管理客户端连接
Target Network将 Endpoint 关联到 VPC 子网决定客户端接入的 VPC 网络
Client CIDR分配客户端 IP 地址的地址池不能与相关网络地址范围冲突
Route决定访问目标网络的流量如何转发没有路由无法正确到达目标
Authorization Rule允许用户访问指定网络路由存在不等于有访问权限
Security Group控制目标资源的流量必须允许相应流量

2.3 Client VPN Split Tunnel

模式工作方式适用场景
Split Tunnel 只有匹配 VPN 路由的流量通过 VPN，其余流量走本地网络。 只需要访问公司内部资源，希望减少 VPN 流量。
Full Tunnel 客户端流量通过 VPN 连接。 需要统一控制客户端网络出口的场景。
易错点： Split Tunnel 不代表不需要配置路由。VPN 客户端仍然需要获得相应的目标网络路由。

2.4 Client VPN 成本考点

  • Client VPN Endpoint 通常涉及连接小时费用。
  • 还需要考虑客户端连接数量及数据传输成本。
  • 多个 Endpoint 可能带来额外费用和管理开销。
  • 如果一个 Endpoint 配合现有网络已经可以满足访问需求，通常不需要为每个账户单独创建 Endpoint。

2.5 Site-to-Site VPN

Site-to-Site VPN 用于连接企业本地网络与 AWS 网络。

组件作用
Customer Gateway代表客户侧 VPN 设备或网关的信息。

记忆：

3. VPC Peering 考点

3.1 VPC Peering 是什么？

VPC Peering 允许两个 VPC 之间建立私有网络连接，通过私有 IP 地址通信。

       VPC A
      10.0.0.0/16
           |
           |
      VPC Peering
           |
           |
       VPC B
      10.1.0.0/16

3.2 核心特点

特性说明
连接方式两个 VPC 之间直接建立连接。
跨账户支持不同 AWS 账户之间建立 Peering。
跨区域支持不同 AWS Region 之间的 VPC Peering。
IP 地址两个 VPC 的 CIDR 不能重叠。
传递路由不支持 Transitive Peering。
路由配置双方路由表都需要配置正确。
费用没有 Peering 连接小时费用，但存在数据传输费用。

3.3 最重要考点：不支持传递式路由

             VPC A
            /     \
       Peering   Peering
          /         \
       VPC B       VPC C

VPC B 不能通过 VPC A 自动访问 VPC C。
考试陷阱： VPC A 与 B 建立 Peering，A 与 C 建立 Peering，并不意味着 B 与 C 可以通过 A 通信。

3.4 Edge-to-Edge Routing 限制

VPC Peering 不支持将一个 VPC 的 VPN、Direct Connect 等边缘连接作为其他 Peered VPC 的中转连接。

例如： 
VPC A -------- VPC B
  |
  |
Site-to-Site VPN
  |
  |
On-Premises

不能让 VPC B 简单地通过 VPC A 的 Site-to-Site VPN 访问本地网络。

注意区分：Client VPN 访问 Peered VPC 是 AWS 支持的独立场景，不应与普通 VPC Peering 的 Edge-to-Edge 限制混淆。

3.5 Client VPN 如何访问 Peered VPC？

             Employee
                 |
             Client VPN
                 |
              VPC A
                 |
             Peering
                 |
              VPC B
                 |
            Internal App
需要关注：
  1. Client VPN Endpoint 关联的目标子网。
  2. Client VPN 路由表中存在目标 VPC 网段的路由。
  3. 配置相应的 Authorization Rules。
  4. VPC A 和 VPC B 的路由表正确配置。
  5. 安全组和网络 ACL 允许相应流量。
  6. 返回流量能够正确返回客户端网络。

4. AWS Transit Gateway 考点

4.1 Transit Gateway 是什么？

Transit Gateway 是 AWS 提供的中心化网络枢纽，用于连接多个 VPC、VPN 和 Direct Connect 等网络。

                VPC A
                  |
                  |
VPC B ------- Transit Gateway ------- VPC C
                  |
                  |
              Site-to-Site VPN
                  |
                  |
              On-Premises

4.2 Transit Gateway 的优势

  • 集中连接多个 VPC。
  • 支持 Hub-and-Spoke 网络架构。
  • 支持跨账户共享连接能力。
  • 可以连接 Site-to-Site VPN。
  • 支持 Transit Gateway Route Table 进行网络路由控制。
  • 避免大量 VPC 之间形成复杂的 Peering 网状连接。

4.3 VPC Peering 与 Transit Gateway 对比

比较项目VPC PeeringTransit Gateway
架构点对点中心化 Hub
传递路由不支持支持，取决于路由表和连接配置
多 VPC 扩展连接数量增长时管理复杂更适合大规模互联
跨账户支持支持，可配合 AWS RAM
跨区域支持支持通过 TGW Peering
连接费用无小时连接费用通常有小时费用
数据处理费用无 TGW 数据处理费通常有数据处理费用
适用规模少量 VPC大量 VPC、复杂网络

4.4 Transit Gateway 相关考点

AWS RAM（Resource Access Manager）

可以将 Transit Gateway 共享给其他 AWS 账户，使其他账户能够创建自己的 VPC Attachment。

Transit Gateway Route Table

用于控制不同 Attachment 之间的流量转发，可以通过路由表实现网络隔离。

Transit Gateway Peering

用于连接不同 Transit Gateway，支持跨区域网络互联。

考试技巧： 题目强调大量 VPC、多个账户、中心化网络管理、避免复杂 Peering，优先考虑 Transit Gateway。 如果现有 Peering 已经满足需求，且题目强调成本最低，不要无理由增加 TGW。

5. 路由、安全与网络访问控制

5.1 必须区分的三个概念

机制解决的问题记忆方式
Route Table流量应该发送到哪里？决定路径
Authorization RuleVPN 用户能否访问目标网络？决定 VPN 访问权限

5.2 Route Table 配置示例

假设网络如下：

Account B VPC10.1.0.0/16
Account C VPC10.2.0.0/16
Client VPN CIDR172.16.0.0/16

Client VPN 路由需要根据关联子网及目标网络正确配置，例如：

Destination       Target
--------------------------------
10.0.0.0/16       Main VPC
10.1.0.0/16       Peering Connection
10.2.0.0/16       Peering Connection

具体目标和配置位置需要遵循 Client VPN 对 Peered VPC 的路由配置要求；不能把上表理解为所有路由都添加在同一张路由表。

6. AWS 网络成本优化考点

6.1 网络服务成本比较

服务常见费用组成成本优化方向
Client VPNEndpoint 连接小时费、客户端连接费用及数据传输等减少不必要的 Endpoint 和连接资源
Site-to-Site VPN连接小时费、数据传输等根据业务需求选择合适连接架构
VPC Peering数据传输费用减少不必要的跨区域数据传输
Transit GatewayAttachment 小时费、数据处理费等合理规划 Attachment 和流量路径
Direct Connect端口小时费、数据传输费用等合理规划带宽和连接使用

6.2 成本题快速判断

原则一：复用现有资源。 如果现有 VPC Peering 已经满足需求，不要为了相同目的额外部署 Transit Gateway。
原则二：避免重复建设。 如果多个账户的应用可以通过一个 Client VPN Endpoint 访问，就不必为每个账户分别创建 Endpoint。
原则三：规模决定架构。 少量 VPC 优先考虑简单连接；大量 VPC、复杂路由和集中化管理则考虑 TGW。

6.3 不要混淆的成本概念

  • 没有连接小时费用，不等于没有数据传输费用。
  • 网络连接数量越多，管理成本和潜在费用通常越高。
  • TGW 的价值不仅是连接能力，还包括集中化管理和路由控制。
  • 最便宜的架构不一定满足可扩展性、安全性和高可用性要求。

8. SAP-C02 高频易错点

易错说法正确理解
VPC Peering 支持传递路由错误，不支持 Transitive Peering。
VPC A 分别连接 B 和 C，B 就能访问 C错误，必须建立合适的直接连接或使用 TGW 等架构。
Client VPN 只能访问关联的 VPC错误，正确配置后可以访问 Peered VPC。
有路由就一定可以访问错误，还需要授权、安全组等允许。
Security Group 是无状态的错误，Security Group 是有状态的。
NACL 是有状态的错误，NACL 是无状态的。
TGW 永远比 Peering 更好错误，必须结合规模、管理和成本判断。
Site-to-Site VPN 和 Client VPN 用途相同错误，一个主要连接网络，一个主要连接客户端。
Peering 没有小时费就没有任何费用错误，数据传输仍可能产生费用。

特别记忆：三个不要混淆

1. Client VPN ≠ Site-to-Site VPN
2. VPC Peering ≠ Transit Gateway
3. Route ≠ Authorization Rule
